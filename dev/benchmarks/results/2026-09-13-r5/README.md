## 最终行为与验证

交互 CLI 与 TUI 共用 Application 的插件命令选择、按需创建会话与输入消费；Host 保留各自的呈现和等待方式。
命令选择 Catalog 与执行使用同一次 Session/Harness 捕获，完整创建和读取离开事件循环。创建成功后，即使取消
或后续命令失败，Host 仍取得会话身份。结果逐个交付，CLI 保留最后一个结果，TUI 按原有呈现方式收集结果。
现行契约见[插件系统规格](../../../specs/OURO_插件系统规格_2026-09-02.md)。

最终实现的完整质量门槛：**2,835 passed / 4 skipped（1,676.05 s），覆盖率 84.58%**。

- `uv sync --frozen --all-groups`、Ruff 检查与格式检查、mypy、compileall、sdist/wheel 构建通过。
- 回归覆盖 files/SQLite 的会话创建、归因、FIFO、原子批次、回执重复消费、活动 Run 排队、取消和接受失败。
- 上下文计数与撤销竞争测试确认准备阶段只捕获一次；Catalog 获取期间的历史变化仍由既有提交冲突拒绝。
- 隔离进程禁止导入 CLI/TUI/Textual，应用用例仍可运行；真实 CLI 输入循环覆盖后台运行期间继续查询和 steer。
- 结果释放测试约束 CLI 多输入消费的引用寿命；TUI 覆盖异步创建、失败后的身份保留及会话跟随。

本次收尾只清理规划、未采用试验和临时文件，并更新文档，没有再改动生产代码或测试。
完整测试结果来自收尾前的同一实现；收尾后的静态检查与文档链接检查另行复核。

## 测量方法与原始数据

Windows 11、Python 3.14.6、锁定依赖。使用同一版[命令基准](../../plugin_commands.py)，四组对照依次为
before/after、after/before、before/after、after/before，不与 pytest 并发。
临时安装真实 SDK 插件，使用合成 Provider 流式输出和工具结果；覆盖 files/SQLite 的无会话查询、预建会话、
输出后创建会话和已有 120 条历史的会话。非查询输出一个两条输入的原子批次；安装、启动和初始历史准备不计时。

- [常规改前](commands-before.jsonl) / [常规改后](commands-after.jsonl)
- [注入 5 ms 慢存储的 TUI 改前](slow-tui-before.jsonl) / [改后](slow-tui-after.jsonl)

最终共 **192 个场景记录**，改前/改后各 96 个；对应场景的消息摘要、消息数量和 Run 终态完全一致。
常规场景中发生事件循环 Store 调用的记录从 **48/64 降为 0/64**，慢存储 TUI 从 **24/32 降为 0/32**。
计数包括嵌套 Store 方法，不等于物理磁盘 IO 次数。

## 时延结果与局限

以下为 CLI 四次运行的中位数，单位 ms。提交计至命令执行和目标会话准备完成；首段计至首个
`model_text_delta`，不代表终端实际绘制。`required` 为预建会话，`deferred` 为输出后创建，`existing` 为已有会话。

| 后端 | 场景 | 总耗时：改前 → 改后 | 提交：改前 → 改后 | 首段：改前 → 改后 |
|---|---|---:|---:|---:|
| files | required | 2934.43 → 2860.16 | 166.78 → 189.48 | 497.94 → 469.21 |
| files | deferred | 2780.50 → 2945.95 | 61.30 → 79.22 | 421.92 → 476.28 |
| files | existing | 2779.46 → 2767.39 | 100.01 → 110.62 | 398.46 → 428.36 |
| SQLite | required | 1966.23 → 1918.28 | 64.73 → 62.46 | 330.31 → 296.33 |
| SQLite | deferred | 1934.56 → 2040.74 | 32.51 → 34.93 | 315.57 → 348.94 |
| SQLite | existing | 2096.76 → 2176.59 | 35.92 → 38.20 | 310.90 → 399.81 |

确定的结构收益是消除 Host 重复协议分支与重复上下文读取，并将完整 Store 操作移出事件循环。
这些结果不证明所有时延均改善：files CLI 提交中位数增加约 **11–23 ms**；部分 TUI 场景的总耗时、首段和按键
时延也上升。原始记录保留 loop lag、按键与动画间隔的样本数、p50/p95/p99 和最大值；不能用其他场景的改善
抵消这些变化，或在缺乏证据时归因为系统噪声。

CLI 样本不包含终端输入线程和交互提示；headless TUI 不代表真实终端 paint，也不覆盖网络 Provider 性能。
帧预算、流式合并、背压、GC、刷新频率和持久化策略未改。本记录保留最终证据与验证局限，不再维护后续减负计划。
