# 未采用的 Run 资源聚合试点

这里的 `after` 是已撤回的私有 `_RunResources` 聚合对象试点，**不是最终交付实现**。
改前为 `5c2b4bb`。试点把七张表改为一个按 Run 持有全部字段的对象，并调整所有读取入口。
功能回归通过，但慢存储 TUI 动画 tick 尾延迟在交替样本中持续偏高，未按性能门槛接受该结构变化。

- 40 delta/轮、5 ms 存储注入、交替五次：SQLite tick gap p95 的中位数 129.060 → 176.703 ms。
- 400 delta/轮、同样注入、交替三次：SQLite 179.839 → 228.492 ms，files 147.088 → 152.158 ms。
- [GC 初态控制诊断](../gc_diagnostic.py)在测量前收集准备阶段垃圾，测量期间保持 GC 开启；三次长流结果为
  SQLite 175.102 → 185.694 ms、files 140.543 → 149.760 ms。差异缩小，但未消除，不能据此宣称完全等价。

这些数据不足以把差异归因于某个纳秒级读取操作，也不构成调整生产 GC 或 TUI 刷新策略的理由。
最终改为复用现有 Runtime 所有者和直接读取表，仅集中资源清理清单、修复失败收尾并消除重复解码。
最终方案重新测量，结果在[父目录验收记录](../README.md)；本目录只保留未采用试点的原始诊断证据。
