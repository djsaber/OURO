# Harness 状态与撤销：Windows 成本对照

日期：2026-09-11。基线为 M4 `7a241fa`，对照为随本报告提交的 M5 代码。
使用同一 Python 环境、同一 [脚本](../harness_lifecycle.py)，依次执行 M4、M5，期间不运行 pytest 或 TUI。
原始数据：[M4](harness-m4-windows-2026-09-11.jsonl)、[M5](harness-m5-windows-2026-09-11.jsonl)。

每个 revision 覆盖两个后端、100/10,000 条保留消息、固定两条撤回后缀和三种状态大小，各重复三次，共 36 次。
消息后另写入不同状态，撤销时断言准确恢复消息前值。夹具写入、首次索引建立、检查点计数在计时区间之外。
每阶段捕获一次完整状态，各 owner 并发执行 20 次只读或无变化回调。

## 读写、同步和版本

File 的 M4/M5 读写量相同。对应三种状态大小，撤销读取分别约 77 KB、346 KB、2.18 MB；
保留前缀从 100 增至 10,000 条时，每种只多读 10 字节。撤销写入从 9,469 增至 9,485 字节，
每次均执行 5 次 Python fsync。大状态增加读取成本，没有导致重新写入状态快照或复制保留消息正文。

SQLite 的 M5 撤销读取中位数为 168,036–1,781,860 字节，写入为 106,840 或 115,056 字节。
前缀变长时读取增量为 28,672–32,768 字节，符合索引定位和页访问的成本形状，没有随前缀正文成比例增长。
所有实例维持既有 WAL/FULL 配置。原生 VFS 同步在 C 层执行，Python 包装器无法测得，
原始数据中的 `native_sqlite_fsync_calls: null` 表示未测，不能用 Python 的 0 次推断数据库没有同步。

两个后端、两个 revision 的每次状态变更均新增一个版本；撤销、只读回调及无变化回调均新增零个版本。
状态捕获、只读和无变化回调均无写入或 Python fsync。M5 各配置中位数范围如下：

| 阶段 | File 耗时（ms） | SQLite 耗时（ms） |
|---|---:|---:|
| 首次状态提交 | 41.912–130.236 | 12.728–17.823 |
| 捕获一次状态 | 1.833–5.906 | 1.767–4.419 |
| 并发只读回调 | 1.047–8.889 | 0.913–6.560 |
| 并发无变化回调 | 0.914–10.085 | 0.883–6.693 |

状态变更写入随状态大小增加，File 每次 4 次 Python fsync。每条消息仍只持有常量大小版本引用。
本次数据支持热索引下的撤销和回调成本边界，不覆盖冷启动首屏、真实 Provider 或子树交付规模。
Windows GetProcessIoCounters 记录进程 I/O，不能等同于物理介质读写量；未降低持久化保证以获得这些结果。
POSIX 文件恢复和 SQLite 原生同步次数尚需相应环境与观测工具验证，因此不据此宣称 M5 全部验收完成。
