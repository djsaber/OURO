# OURO 轻量化重构优化计划

## 目标与约束

以当前功能契约为基础，审查核心框架、基础设施、CLI/TUI、测试和文档，减少重复计算、阻塞 I/O、无效刷新及不必要代码。保持插件、Provider、存储后端和未来 Host 的扩展边界。

每项改动须能回答：成本或缺陷在哪里、由谁负责、如何用更少的工作保持相同行为、如何验证。没有调用链或测量证据的猜测不直接进入实现。不按文件长度机械拆分，不引入通用缓存框架、第二套状态机或仅转发的抽象层。

现行设计文档独立描述当前职责、数据流、不变量和失败语义，不保留迭代日志、版本对比或改进叙述。本计划只跟踪工作范围与验收状态。

## 审查范围

| 层级 | 主要检查内容 | 必须保持的边界 |
|---|---|---|
| 目录与依赖 | 模块归属、公共接口、循环依赖、重复实现、无引用代码 | Host → Application → Core；基础设施实现端口 |
| Core | 模型轮次、上下文、压缩、流式事件、工具批次、取消与恢复 | 顺序、原子帧、确定性状态转换、动态扩展 |
| Application | 会话、Run、Agent、Harness、任务、事件观察与资源编排 | 状态单一来源、资源所有权、事务和取消收尾 |
| 基础设施 | 文件/SQLite、配置、资源、认证、Provider、插件、MCP、Skills | 持久化一致性、真实外部输入校验、资源释放 |
| TUI / CLI | 导入与启动、首屏、会话加载、输入、流式渲染、刷新与菜单 | 展示与业务分离、异步响应、过时结果隔离 |
| 文档与工程 | 规格一致性、历史残留、测试价值、测量可重复性 | 当前契约清晰、未来能力明确标注、链接有效 |

## 执行清单

- [x] 1. 建立基线：读取仓库规范和架构契约，统计模块规模与依赖，运行架构检查、关键测试及可重复性能采样。
- [x] 2. 审查 Core/Application 热路径：跟踪一次提交到结束、取消、恢复及工具交互，定位重复序列化、全量扫描、重复查询和同步阻塞。
- [x] 3. 审查基础设施：检查 I/O 放大、哈希与校验的实际用途、锁和任务生命周期、历史兼容及重复容错；只移除无有效契约支撑的机制。
- [x] 4. 审查 TUI：测量导入与首屏成本，检查事件投影、历史渲染、状态更新、输入与菜单调用链；实施有证据的轻量化优化。
- [x] 5. 实施与定向回归：按责任层完成独立改动，补充缺陷、取消、并发和性能工作量回归，保留所有当前功能和扩展接口。
- [x] 6. 整理文档：核对 README、架构、规格、规划及模块文档；统一为当前设计描述，清理已失效说明和引用。
- [x] 7. 整合验收：执行全量测试/覆盖率、Ruff、Mypy、编译、构建、差异与文档链接检查；复测性能并记录适用条件和未验证范围。

## 证据与取舍

性能数据区分导入、业务准备、存储与 headless TUI，不把局部或合成测量解释为真实终端时延保证。

优先处理高频路径中可直接消除的重复工作，再处理生命周期缺陷和边界泄漏。新增状态或缓存必须有明确所有者、失效条件和容量；能够靠减少调用或批处理解决的，不引入缓存。安全校验、哈希、重试和恢复分别核对消费者与失败场景，不能仅因名称看似复杂而删除。

## 验收

阶段执行受影响模块和架构回归；整合执行贡献指南中的完整门禁。外部服务与真实终端不能在本地可靠复现的部分明确列为未验证，不宣称通过。

```bash
uv run --frozen pytest --cov=ouro --cov-report=term-missing
uv run --frozen ruff check ouro tests
uv run --frozen ruff format --check ouro tests
uv run --frozen mypy ouro
uv run --frozen python -m compileall -q ouro
uv build
git diff --check
```
