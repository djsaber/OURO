# 模型订阅认证规格

> 文档类型：订阅接入规格；浏览器首期已实现，设备码及其他能力为未来增量
> 规划基线：2026-09-16
> 首期范围：多厂商认证边界与 OpenAI / ChatGPT 订阅组合。

设计理由见[目标设计](../../docs/OURO_模型订阅认证扩展设计_2026-09-16.md)，交付顺序见[实施计划](../plans/OURO_模型订阅认证实施计划_2026-09-16.md)。本文件定义通用认证契约与首期浏览器订阅接入，未验收的设备码及其他能力在对应章节明确标注。未修改的行为继续遵循[Provider 配置](OURO_Provider配置规格_2026-09-02.md)、[类型与协议](OURO_Provider类型与协议规格_2026-09-02.md)、[模板](OURO_Provider模板规格_2026-09-02.md)及[核心运行时](OURO_核心运行时规格_2026-09-02.md)规格。

## S1. 范围与不变量

- 认证驱动、产品档案和线协议分别选择；factory 仅按 protocol 分派。
- 模型路由保持 `provider_id/endpoint_id`。API Key 与订阅实例可同时存在，调用失败不隐式切换账户、模型或计费来源。
- Application 编排用例，auth 管理认证，providers 实现线协议，LocalApplication 统一组合和关闭。Core/Host 不含厂商分支。
- 本地秘密不进入配置、模板、普通 DTO、Session、日志或 Run 事件。登录 challenge 仅返回给发起登录的 Host。
- 状态查询不执行网络操作；显式连接检查和推理请求才验证实际模型可访问性。
- 除对外输入、持久化读取、供应商响应、最终请求及并发提交边界外，不重复验证内部类型化对象。

## S2. 配置与注册

配置、模板与 RuntimeOptions 的通用认证结构已实现，现行行为见上述 Provider 配置/类型/模板规格；通用运行时装配与首期浏览器订阅组合注册已实现，Windows/browser/gpt-5.5 真实持久凭据 Host 闭环已验收，见[使用指南](../../docs/OURO_订阅支持使用指南_ZH_2026-09-19.md#证据范围)。

Provider 新增 `auth_driver: str = "static"`；CredentialRef 新增 `managed` 分支，其 `name` 是由系统生成的 credential id，不是路径。现有 env/inline/none 语义保持。

已注册 `openai-codex` 产品、同名浏览器认证驱动及 `openai-responses` 协议；custom 类型可显式选择标准 Responses + static 组合，复用同一 adapter。以下是目标配置片段；Endpoint 能力和 model id 应由实施验证后的模板填入，不能直接复制占位符运行：

```json
{
  "display_name": "ChatGPT 订阅",
  "provider_type": "openai-codex",
  "protocol": "openai-responses",
  "auth_driver": "openai-codex",
  "credential_ref": {"type": "managed", "name": "cred_generated_id"},
  "base_url": "https://chatgpt.com/backend-api/codex",
  "api_path": "/responses",
  "default_endpoint": "endpoint_generated_id",
  "endpoints": {
    "endpoint_generated_id": {
      "display_name": "Codex",
      "model_id": "<verified-subscription-model>"
    }
  }
}
```

其中 Provider 映射键、`default_endpoint` 与 Endpoint 映射键均由框架生成和维护，不属于用户输入。

产品档案声明默认及允许的 `(protocol, auth_driver)` 组合，以及服务规则引用；不能将两组独立允许列表的任意组合视为可用。config 解析并传递引用和纯配置数据，由组合根解析实现；不另存用户可编辑的 service_profile。auth 方法类型及 browser/device 列表来自驱动描述，不持久化重复的 auth.method。

config 是结构与合法组合的唯一校验者：static 只接受既有静态引用；受管理驱动要求 managed ref；未知字段、不允许组合和冲突的 CLI API Key 覆盖在写盘或构造运行参数前失败。允许的最终目标由 S5 处理，不再在各层复制主机校验。

组合根构建时识别内建 static 策略，并校验产品声明所引用的 managed driver/service policy 均已注册。服务规则复用协议参数能力和少量明确策略；传给认证端口的允许目标是纯数据，不让 auth import providers。注册表仅在装配时建立；没有插件热加载或运行时 schema 注册。config 不导入具体 driver；Application 不自行加载 driver 实现。

未登录可以持久化完整 Provider 与 managed ref，此时 credential 记录可以不存在。未登录的默认 Provider 不能导致 Host 无法启动、进入设置或注销；秘密解析延迟到需要网络认证时。

模板 API Key 分支可声明 credential_env，OAuth 分支无需该字段；模板只提供 auth_driver 默认值，不保存 credential id 或账户。实例 managed ref 由创建用例生成。普通模板更新保留实例认证选择和引用，变更认证方式必须显式执行。模板绑定、指纹、严格 codec 与公开 DTO 同步更新。

新增可选字段使用确定默认值，不引入历史转换分支。必要的模板/凭据存储版本升级遵循项目严格版本策略：不兼容时明确失败，不自动清理或迁移数据。

## S3. 认证端口与 Application 用例

`AuthDriver`、方法/challenge、`AuthorizationAttempt` 及单次授权资源生命周期由[认证驱动与授权现行规格](OURO_认证驱动与授权规格_2026-09-16.md)定义。

通用 ProviderAuthService、操作/状态 DTO、credentials/forget、条件提交和取消收尾已实现，权威契约及实际配置锁竞争证据见[Provider 认证用例现行规格](OURO_Provider认证用例规格_2026-09-16.md)。两种测试驱动复用同一用例和 store；static 返回空方法集合，不伪造登录驱动。

轻量本地组合与 CLI 已实现，见[CLI 与 Host 规格](OURO_CLI与Host规格_2026-09-02.md#provider-认证命令)；通用 Runtime 装配见请求认证规格，通用 TUI 管理见[TUI 规格](OURO_TUI规格_2026-09-02.md#provider-认证管理)；OpenAI 浏览器 driver 已由本地组合注册，设备方法仍待真实验证。Host 只展示方法/challenge 并打开外部浏览器，不能读取秘密文件或依据授权完成自行宣布成功；必须使用 Application 返回的终态。operation/status 不复制交互 URL/code，诊断不包含 Token、verifier 或供应商原始响应。Host 验收必须覆盖等待取消与显式取消的区别、重复操作、关闭收尾及保存失败。

## S4. 凭据存储、并发与恢复

记录格式、受限文件存储、单 revision、跨进程互斥、条件提交、刷新/注销及取消收尾已由[受管理凭据核心规格](OURO_凭据核心规格_2026-09-16.md)定义。订阅接入复用该核心，不新增 epoch、凭据 WAL 或远端事务协议；现有协议的请求认证及 Runtime 共享服务已接线；通用 TUI 管理已接线，OpenAI 浏览器驱动已由本地组合注册，设备方法仍待真实验证。

接入层根据 active 记录的有效期和驱动 refresh 能力派生 ready/refresh_needed，不持久化这些镜像状态。secret payload 由所属 driver 在材料使用边界解码，不能将外部 JSON 直接当作可信内部对象。driver 返回完整刷新结果，新 refresh token 替换旧值，缺失时按供应商契约保留；已发送但结果未知的交换不能无限重试。

登录通过 CredentialService 的同步 binding_guard 接入 S3 配置绑定检查；OAuth 网络等待不占配置锁。请求认证复用锁内重读和 revision，不以进程内缓存替代跨进程协调。LocalApplication 的装配与关闭遵循 S9；本地已开始的原子写入遵循凭据核心的不可强行中断语义。

同一 OURO_HOME 内不增加 Provider owner ACL；显式引用同一 credential 时共享注销效果，DTO 应展示该事实。不同 OURO_HOME 不隐式共享或搜索凭据，不自动导入 Codex/OpenCode 缓存。

Provider remove/replace 只原子修改配置，不隐式修改秘密仓库。正在登录的提交因绑定变化而失败；已有未绑定凭据可通过 credentials/forget 清理。forget 正在使用的引用会使其后续认证失败，调用结果列出受影响实例，不增加额外确认流程。

认证状态是本地材料状态，账户显示名也不构成权益证明。首期 OpenAI driver 可从可信 Token 端点响应提取所需账户路由元数据，但不根据未验证 JWT 声明授权、额度或订阅等级。某驱动若将 ID Token 作为身份断言，必须在该驱动实现相应验证，不能把这一要求泛化为所有 Token 的公共检查。

## S5. 请求认证与重试

Chat Completions/Messages/Responses 的通用认证端口、最终目标检查、共用重试及错误码传播已实现，现行契约见[请求认证规格](OURO_请求认证规格_2026-09-17.md)。生产产品服务注册与真实闭环仍为未来增量；通用 Runtime 装配和缓存重绑定已验收。

三种真实模型协议统一依赖 `RequestAuthenticator`。静态实现使用现有解析结果；managed 实现仅持 credential ref/driver 及目标规则，每次网络尝试前通过 CredentialService 取得有效材料。一次 acquire 返回内部认证快照，认证头、凭据 revision 和续接 scope 属于同一份材料；codec 用该 scope 校验重放并标记本次返回的 continuation，不另行读取凭据。快照不进入公开 DTO/日志，adapter 不跨请求尝试缓存 access token。

Provider、Endpoint 和命令参数合并得到最终 URL 后，RequestAuthenticator 在注入 managed 秘密前执行一次目标检查。目标规则来自已装配的服务档案：匹配 HTTPS origin 及适用路径范围，不使用宽泛后缀匹配。static 自定义兼容端点保留原有语义。带认证的模型请求及 Token 请求不自动跟随 HTTP 重定向；HTTPS 使用正常证书校验。

外部请求的认证头由认证实现拥有，不能通过 request_options 或普通 header override 覆盖。业务请求字段继续由 codec 与 Endpoint 能力规则拥有。

发送授权以取得认证材料为边界：logout 成功后新的 acquire 必须失败；已经取得材料并发出的/正在发送的请求可能完成。立即终止已有流使用现有 Run abort，不增加远端取消承诺。

认证恢复和 transport transient 重试使用现有 `stream_with_retries` 的同一模型请求尝试预算；最多一次认证恢复，且只允许在模型事件尚未输出时执行。认证恢复只返回是否可以重试，不在认证端口内重发模型请求。刷新请求自己的超时/可重试性由 driver 定义，不因普通模型 HTTP retry 循环被无界重复。

| 失败 | 处理 |
|---|---|
| 即将过期 | 请求前按驱动策略刷新 |
| 401，未输出 | 以失败尝试的 revision 重读凭据；已更新则复用新材料，否则必要时一次刷新，在剩余尝试预算内重发 |
| 再次 401 / 失效 refresh | authentication_required |
| 403 | access_denied；不统一解释为欠费或刷新问题 |
| 429 | 按服务错误事实区分速率/额度；尊重 Retry-After；额度耗尽不短间隔循环重试 |
| 网络/5xx，未输出 | 复用现有有界退避 |
| 输出后断流 | 报错，不重放文本、工具或完整模型请求 |
| 目标不允许 / 配置冲突 | HTTP 前失败 |

transport 保留内部 HTTP status、Retry-After 和所需错误 code；providers 的服务规则分类模型服务错误，AuthDriver 只分类授权/Token 端点错误。迟到的 401 不得把已更新的 credential 标记为失效。不得将原始 Token 响应、Authorization 或完整 callback URL 拼入错误文本。

现有 stream 只有字符串错误，新增供应商无关的可选 `error_code` 并沿 Application 事件/CLI JSON 传递，保留安全 message。已识别的 authentication_required、access_denied、rate_limited 等错误必须携带对应 code；未分类错误可为空。code 不包含 OpenAI、HTTP 或 OAuth 对象，不得让 Host 解析字符串猜登录动作。

## S6. OpenAI 驱动

浏览器驱动、严格材料格式、Token 错误分类及文件 store/请求认证集成的现行行为见[认证驱动与授权规格](OURO_认证驱动与授权规格_2026-09-16.md#openai-浏览器驱动)。浏览器产品已内建注册；本节设备码发布仍为待完成要求。

浏览器流程使用外部浏览器、随机 state、S256 PKCE 和短期 loopback listener。只接收预期回调路径/方法；成功和 error callback 均先验证 state，无关回调不终止合法 operation。成功、取消、拒绝、超时和关闭均释放 listener/任务。

客户端 id、redirect URI、scopes 与 Token 端点由经过验证的 driver 配置提供，不开放在普通 request_options 中。使用该客户端允许的回调端口；端口占用时返回诊断并可选择 device 方法，不干预其他客户端。

设备码流程按服务协议申请 code、轮询、交换 Token，遵守 interval、总时限与取消。供应商 pending 状态只在其驱动内解释，不假定所有厂商采用同一 device grant 报文。

不按 Token 的 JWT 形状推断认证方式；refresh 能力、expires_at 与 account/workspace 路由由 driver 提供。需要特定工作区/区域但无法忠实处理时返回不支持诊断，不随意选第一个组织或静默更改服务区域。

本地 logout 不等于远端撤销。首期只承诺清除本地秘密；远端 revoke 可在供应商明确提供契约后加入驱动能力，不作为通用注销的前置网络调用。

## S7. Responses 与 continuation

请求内容、流投影、严格 envelope/scope、adapter/协议注册及通用认证重试见[Responses 编解码现行规格](OURO_Responses编解码规格_2026-09-19.md)。通用 Runtime 的工具、恢复、分支和压缩续接已通过合成服务集成验收；真实刷新/工具续接与真实持久凭据 Host 闭环已分别验收；以下未声明的模型参数及能力仍须独立证据。

新增通用 Responses codec：system prompt → instructions，消息 → input，tool call/result → function_call/function_call_output，保持 call_id 与 item id 的区别；reasoning intent 通过已校验 profile 映射。不得用 Codex 的 Agent 提示词或内置工具替换 OURO 的提示词与工具契约。

Codex 服务规则首期采用 SSE、store=false、完整本地上下文，不依赖 previous_response_id。温度、结构化输出等服务能力以实际核验结果为准。保持单一正整数 max_output_tokens 用于本地上下文预算；实测 Codex 订阅后端拒绝该字段，此集成接受没有请求级输出硬上限，由受信服务策略声明 supports_output_limit=false，adapter 不发送输出上限，实际输出可能超过本地预算。默认服务策略仍发送上限；不按厂商或 OAuth 分支，不新增独立预留参数，不在 HTTP 失败后自动调整。当前探针通过启动提示及 output_limit_enforced=false 明确披露限制；正式 Provider/Template DTO 携带只读服务 notice，CLI/TUI 创建、查看和管理入口展示该限制。省略参数后的正式 adapter 已在 Windows/browser/gpt-5.5 真实实验中通过文本、刷新、两轮工具及加密 reasoning 重放，scope 保持稳定；证据见[探针验收](../probes/README.md#正式-adapter-验证)，生产 CLI 与持久凭据闭环已通过，见[使用指南](../../docs/OURO_订阅支持使用指南_ZH_2026-09-19.md#证据范围)。图像未验收时 capability 为不支持。

| Responses 输入/事件 | canonical 行为 |
|---|---|
| output_text delta | text_delta |
| reasoning summary delta | 可展示 reasoning_delta |
| tool item / arguments 事件 | 按 item identity/output index 组装 tool_call_delta |
| replay 所需完整 items | continuation |
| completed | 一次 done，附 usage/completion |
| incomplete | 明确不完整终态；残缺工具参数不进入执行 |
| failed/error/缺少终态的 EOF | 失败，不伪造成功 |

最终快照可以补齐尚未输出的内容，不能重复输出已收到的 delta。usage 仅按现有 done 契约提交一次。首期至少覆盖交错工具、仅 reasoning、拒绝、空输出、取消与提前 EOF。

复用现有 `ProviderContinuationArtifact` 外层 provider/protocol/model 身份。在 Responses 的 opaque blocks 中保存一个带格式版本的 envelope，包含 `scope` 与按原始顺序保存的 replay items；codec 读取/校验 envelope，发送前解包，OURO envelope 不发送给供应商。重放完整 assistant items 时，不再从同一消息的 canonical 文本/tool_calls 重建一份重复输入；tool result 仍由现有 canonical 消息编码。Core 不新增 OAuth、账户、scope_id 或驱动字段，也不解释 blocks。

scope 由稳定的服务身份及必要账户/工作区标识组成，不含 Token、有效期、每次刷新 revision 或无关模板版本。缺少可证明稳定身份的驱动应提供保守的本地授权绑定标识，不能假装跨重登兼容。只有重放 opaque items 时比较作用域，不对普通文本消息增加逐条认证检查。

切换到不同账户/服务或无法解码该 envelope 时，不重放不兼容 opaque 状态、不静默丢弃仍被工具帧依赖的内容；给出恢复原路由/账户或新建会话的明确错误。分支和恢复保持完整帧，压缩遵循现有帧/lineage 规则。普通刷新保持同一 scope。

## S8. 用量、Host 与配置生效

usage 仅使用实际供应商返回值。cached input 是 input 子集，reasoning token 不重复加入 output；无单次金额时 estimated_cost=None。计费模式按请求归属写入账本 metadata 的类型化字段，不由事后 Provider 当前配置反推，不由 OAuth 类型推断为订阅。

请求归属、账本 metadata、来源分组及 CLI/TUI 呈现已实现，见[用量与计费规格](OURO_用量与计费规格_2026-09-17.md)。汇总复用 `UsageTotals.estimated_cost`、`priced_request_count` 和 `unpriced_request_count`，以去重的 billing_modes 表达涉及的计费模式，不另建持久化计数或汇总状态。未知金额与已知零金额有明确区别；token/轮次预算继续有效，未知金额不能承诺严格美元预算。无需额度查询后台任务或订阅费用分摊系统。

主模型、压缩模型、子智能体、连接检查与缓存/default adapter 都从同一 home 范围的认证服务取得材料。普通 Token 刷新不改变配置指纹；auth_driver、credential_ref 或服务连接参数变化时，沿现有请求边界重新绑定 adapter，默认路由也不能绕过配置指纹而永久使用旧绑定。无需引入全局缓存广播或重启 Runtime。

查询目录不刷新，不动态修改模型模板。登录成功不自动执行连接检查；显式 check 才发送可能消耗额度的最小请求。

CLI/TUI 使用 Application 方法描述展示登录，不按厂商写分支。非交互 run、定时任务遇到失效认证返回结构化错误，不打开浏览器或等待无限交互。恢复使用现有 Run 恢复入口。

建议入口为 `provider auth login/status/logout <provider_id>`，以及 `provider auth list/forget <credential_id>`；login 可指定稳定 method id。命令参数和退出码沿用 CLI 现行约定，新增认证错误需在 CLI 规格更新时明确映射。

## S9. 生命周期与架构验收

本地组合根为每个 Runtime 创建共享认证服务，Runtime 拥有最终收尾职责，以同时覆盖独立 run/check 和完整 Host。LocalApplication 先停止新登录、取消 pending 操作，再关闭 Runtime 消费者；Runtime 在模型资源关闭后有界收尾凭据刷新与写入。错误和调用者取消不跳过其他资源，重复关闭复用同一任务。轻量 auth CLI 独立拥有认证资源，不为登录启动无关运行时。

架构测试保护 Core 无外层依赖、Application 无具体 providers/driver/store import、config 无 auth 实现依赖。所有 adapter 只借用 RequestAuthenticator，不能 import driver 或直接读取凭据文件。

新增第二个测试 driver 使用不同认证头和方法描述，复用同一个 ProviderAuthService/Store；三种协议 adapter 的认证契约测试不依赖 OpenAI driver。新增真实厂商只变更注册、驱动、产品/服务数据及确有差异的协议，不修改通用用例或 Host 品牌分支。
