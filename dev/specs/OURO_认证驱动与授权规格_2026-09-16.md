# 认证驱动与单次授权规格

> 文档类型：现行规格
> 代码基线：2026-09-16
> 范围：受管理认证的纯契约与单次授权资源生命周期；已被通用登录用例与轻量 CLI 使用，尚无生产 OAuth driver 或 TUI 接线。

凭据的持久化、刷新协调和条件提交以[凭据核心规格](OURO_凭据核心规格_2026-09-16.md)为准。Application 操作状态见[Provider 认证用例规格](OURO_Provider认证用例规格_2026-09-16.md)，产品接入目标见[订阅接入目标规格](OURO_模型订阅认证规格_2026-09-16.md)，剩余工作见[实施计划](../plans/OURO_模型订阅认证实施计划_2026-09-16.md)。

## 驱动契约与边界

`auth/driver_contracts.py` 定义 `AuthDriver`、`AuthorizationAttempt`、方法描述、challenge 和内部请求材料，不导入存储、授权任务或生产驱动实现。`auth/contracts.py` 继续拥有凭据及通用错误事实。

`AuthDriver` 暴露：

| 端口 | 责任 |
|---|---|
| descriptor | 稳定 driver id、显示名、非空方法集合及 refresh_leeway_seconds（非负有限秒数，默认 60）；方法 id 在驱动内唯一，不使用菜单序号 |
| begin_authorization(method_id) | 创建一次授权，拒绝未知方法；方法返回前失败或被取消时，由 driver 释放已申请资源 |
| refresh | 可注入 CredentialService 的完整材料刷新函数；不支持刷新时为 None |
| encode(record) | 解码本驱动材料，生成认证头和稳定账户/工作区作用域，不读配置或修改 store |

static 保持既有静态凭据解析路径，不注册为受管理 driver；descriptor 拒绝保留 id `static`。驱动的 HTTP、PKCE、回调校验、轮询和 Token 响应解码由生产实现负责，通用层不猜供应商报文或 Token 形状。当前尚无生产注册表，不提前开放未验证的产品组合。

## 方法与 challenge

方法类型为封闭的 `browser_callback | device_code`，并携带稳定 method id、显示名和可选说明。challenge 使用相同 kind 判别的封闭联合：

- BrowserAuthorizationChallenge：authorization_url、expires_at、可选说明。
- DeviceAuthorizationChallenge：verification_uri、user_code、可选 verification_uri_complete、expires_at 和说明。

对外授权/验证 URL 必须为带主机的 HTTPS URL；它们不代表本地 callback listener 地址。expires_at 必须带时区。未知字段或交互类型明确拒绝，不通过任意 JSON 扩展为通用表单系统。

challenge 是只交付发起登录 Host 的交互材料，允许该 Host 显示 URL/code；它不是普通状态、诊断或 Session 数据。URL 与 user code 不参与对象 repr，不包含 callback code、PKCE verifier 或 Token。驱动描述为静态显示数据，不夹带账户秘密。

## 单次授权生命周期

`TaskAuthorizationAttempt` 是可复用的 AuthorizationAttempt 实现。driver 传入 challenge、异步授权函数和资源清理函数；实例拥有这两项工作，既不写凭据，也不宣布登录成功。Application 仍需在授权完成后核对操作/配置绑定并条件提交。

授权函数在实例建立后执行一次。challenge 的绝对截止时间通过注入时钟换算为事件循环的单调截止时间，无需等待第一个调用者才启动或过期。已过期 challenge 不执行授权 I/O。

`wait` 可重复或并发调用，结果只在授权完成且清理成功后返回。取消一个 waiter 只停止该次等待，不取消实例拥有的工作。没有 waiter 时，授权仍在自身截止时间结束并清理；拥有者必须在退出生命周期前调用 cancel/close。

`cancel` 与 `close` 停止尚未完成的授权，并等待同一清理工作；重复或并发调用不会重复清理或再次中断 driver 的 finally。close 的调用者被取消时仍等待清理收尾。即使在授权函数第一次执行前取消，也会释放 begin 阶段已交接的资源。

授权和清理分别拥有任务：取消交换不会取消清理。清理有独立的正数时限，不复用已经到期的 challenge 时限。驱动必须使用可取消的异步 I/O；这些时限不能强制中断阻塞事件循环或无限压制取消的驱动代码。

已收到的材料在 close 后仍可被 wait 读取；它不等于已经保存的登录结果。Application 的取消/提交竞争仍遵循凭据核心的条件提交及不可中断写入语义，不能仅根据 attempt 已关闭来决定操作终态。取消或过期已作用于仍在运行的授权时，驱动压制取消后迟到返回的材料不会被接受。

## 失败与内部请求材料

错误使用固定安全消息：authorization_unsupported、authorization_denied、authorization_expired、authorization_cancelled、authorization_failed、authorization_cleanup_failed。普通网络超时归为授权失败，与 challenge 截止时间到期区分。未知异常不传播 Token 响应或 callback URL。清理失败或超时优先返回 cleanup_failed，即使已收到材料也不能报告成功；后续 wait/close 仍可查询该失败。

`RequestAuthMaterial` 是内部值：认证头复制为不可变映射且不参与 repr；account_scope 是驱动导出的非空稳定账户/工作区标识元组，不含 Token、有效期或每次刷新 revision，也不代表订阅权益。缺少稳定身份时，生产驱动必须按目标规格给出保守的授权绑定标识。

该值本身不构成发送许可。RequestAuthenticator 先核对最终目标，再将服务身份、凭据 revision 与同次材料组合交给协议 adapter，现行行为见[请求认证规格](OURO_请求认证规格_2026-09-17.md)。

## 验收证据

`tests/auth/test_authorization.py` 覆盖封闭类型、脱敏 repr、重复等待、即时/并发取消、截止时间、迟到结果、清理失败和安全错误；成功、拒绝、过期、取消均通过真实本地 TCP listener 验证端口释放。

`tests/auth/test_driver_contracts.py` 提供两种仅供测试的 AuthDriver：浏览器/Bearer 与设备码/独立 Session header，使用不同材料形状和方法 id。两者通过相同 CredentialService/Store 完成授权、条件保存、编码与注销，刷新驱动保留稳定 account_scope；接口符合性另经类型检查验证。相同驱动的 Application 集成证据见 Provider 认证用例规格；现有两种协议的请求认证验收见请求认证规格；真实 OAuth 与 Responses 验收仍保留在实施计划中。
