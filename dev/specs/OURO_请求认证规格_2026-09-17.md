# 模型请求认证规格

> 文档类型：现行规格
> 范围：通用请求认证、三种模型协议 adapter、HTTP 边界、共享重试、Runtime 认证生命周期、配置重绑定及 CLI/TUI 管理。

凭据生命周期以[凭据核心规格](OURO_凭据核心规格_2026-09-16.md)为准；驱动材料见[认证驱动规格](OURO_认证驱动与授权规格_2026-09-16.md)，完整产品目标及剩余工作见[订阅目标规格](OURO_模型订阅认证规格_2026-09-16.md)和[实施计划](../plans/OURO_模型订阅认证实施计划_2026-09-16.md)。

## 认证端口与材料

`auth/request_auth.py` 定义 `RequestAuthenticator.acquire(url)`、`recover(snapshot)`、内部 `RequestAuthSnapshot` 与静态实现。providers 只依赖该端口，不导入 driver、CredentialService 或文件 store。adapter 借用认证对象，不负责关闭共享认证服务。

一次 acquire 返回同一份材料的认证头、revision 与 scope。headers 复制为不可变映射，headers/scope 不进入 repr；快照不得序列化到公开 DTO、日志或事件。static 快照没有 revision，保留已有 CredentialResolver 的 env/inline/none 和自定义 HTTP 端点语义，不伪造登录驱动。

static scope 使用认证实例范围的随机本地绑定，不由秘密派生。它允许同实例的 opaque 续接，但不证明跨实例或进程重启的账户相同；重建后旧 scope 必须明确拒绝。managed 的稳定账户 scope 则可跨普通刷新与 adapter 重建使用。

`ManagedRequestAuthenticator` 持有 credential id、driver、共享 CredentialService、服务身份和允许目标。构造不读取秘密；每次请求尝试才读取当前 active 记录，核对 driver 并调用 encode。adapter 不缓存 managed Token，普通刷新无需重建 adapter。

驱动 descriptor 的 `refresh_leeway_seconds` 是非负有限秒数，默认 60；有 refresh 能力的记录进入该窗口时先通过 CredentialService 刷新。没有刷新能力时，尚未到期的材料仍可使用，到期后返回 authentication_required。刷新返回过期材料时不进入无限刷新循环，也不发送请求。驱动解码异常只返回安全认证错误。

managed scope 由服务身份和 driver 的非空 account_scope 组成，不包含 Token 或 revision。driver 必须提供稳定账户/工作区标识，或在缺少稳定身份时提供保守的本地授权绑定标识；不能用空 scope 假定不同登录可以续接。三种协议均取得此快照；Responses codec 从该快照接收 scope 并校验/封装 envelope，不二次读取凭据。

logout/forget 完成后新的 acquire 失败。已经取得材料的请求允许完成；立即终止流仍使用现有 Run abort。请求取消只取消该次刷新等待，刷新交换和原子保存仍由 CredentialService 按既有生命周期负责。

## 最终目标与头字段

`RequestTarget` 是组合根提供的纯数据：精确 HTTPS origin 和路径子树。managed acquire 在读取任何凭据前检查合并后的最终 URL：

- 主机和有效端口必须与 origin 一致，默认 HTTPS 端口按 443 比较，不使用域名后缀匹配。
- 路径须等于前缀或处于该前缀的 `/` 子树内，`/api-other` 不属于 `/api`。
- 拒绝 userinfo、fragment、控制字符、反斜线、点路径段和含百分号编码的路径，避免客户端/代理二次归一化改变允许范围。查询参数不参与路径范围匹配。
- static 不使用 managed 允许目标规则。

认证头由 RequestAuthenticator 提供。普通 default_headers 与认证头按大小写不敏感规则冲突时，在 HTTP 前明确失败；managed 还拒绝 Host、Authorization、Proxy-Authorization、X-API-Key、Cookie 普通覆盖。业务 request_options 仍由 codec 处理，不是 HTTP header 配置入口。

Provider 请求头由通用解析器在每次模型调用开始时生成独立快照，JSON 与 SSE、三种协议、普通推理与
显式连接检查使用同一规则。默认 User-Agent 为 `ouro/<version>`；普通默认头可被显式配置覆盖。
请求上下文通过 RuntimeAdapter 与 Provider 调用参数传递，不绑定到缓存的 adapter 实例。
会话生命周期由上下文提供方管理，解析器不判断供应商、URL 或特定业务头名。

配置不能覆盖 Host、Content-Length、Transfer-Encoding、Connection、TE、Trailer、Upgrade、Keep-Alive、
Proxy-Connection、Content-Type、Accept、Accept-Encoding、Content-Encoding 与协议版本头。
普通配置与 RequestAuthenticator 实际产出的认证头冲突时明确失败；managed 的额外限制仍生效。
解析结果只在当前调用中使用，重试共享业务头快照但重新获取认证材料。配置、校验和缺失值错误不回显
原始值；配置了自定义头的请求错误使用安全诊断，避免服务端回显头值进入公开异常或事件。

共享 HTTP transport 在每次 POST/SSE 调用显式关闭自动重定向，即使注入的 client 默认开启也不跟随。SSE 3xx 同样明确失败；正常 TLS 证书校验和现有代理路由保留。

## 重试与错误

三种 adapter 的推理和显式连接检查使用同一 `stream_with_retries`。Chat Completions/Messages 检查发送非流式、输出预算为 1 的请求；Responses 检查保留端点流模式与输出预算，避免误判需思考预算的模型。是否发送输出上限由同一服务策略决定；它们使用相同认证和尝试预算。

重试执行器在结束、取消及显式关闭时关闭当前尝试。Responses 外层逐层传递关闭，等待流事件受单次尝试总时限约束；隐藏思考的展示过滤放在重试边界之后，不能因隐藏输出而重新发送已经开始的响应。

| 场景 | 行为 |
|---|---|
| 首次 401，尚无模型事件且剩余预算 | 以失败快照的 revision 重读；更新后的材料可复用，否则有 refresh 能力时通过核心执行一次刷新 |
| 再次 401、无恢复能力、预算耗尽 | authentication_required，不继续刷新或重放 |
| 403 | access_denied，不刷新、不推断欠费 |
| 429 | 按注入的 ProviderRequestPolicy.quota_error_codes 区分 quota_exhausted 与 rate_limited；额度耗尽不短重试 |
| Retry-After | 数值秒数或 HTTP 日期；在最大退避范围内等待至少该时长，超过范围时直接返回失败，不提前重试或无限等待 |
| 网络/可重试 HTTP 失败 | 在同一模型尝试预算内退避；每次重发重新 acquire |
| 已输出任何模型事件后失败 | 返回错误，不恢复认证或重放内容/工具请求 |

认证恢复最多一次且不自行重发模型请求。并发失败复用 CredentialService 的锁内 revision 检查；迟到 401 不标记或覆盖新材料。模型错误分类属于 providers 服务策略，Token 错误分类属于 driver，不混入 codec 品牌分支。

transport 保留内部 HTTP status、Retry-After 和用于服务规则比较的供应商 error code。供应商 code 只参与内部精确比较，不直接复制到公开 code。managed HTTP 错误、异常和报文内错误不回显原始响应、请求 URL 或秘密。

`ProviderStreamEvent.error_code` 是仅允许在 error 事件出现的可选字符串；`ProviderCheckResult` 同样可返回 code。已识别认证、权限、限速、额度错误携带供应商无关 code；static 未分类错误可为空；managed 未分类传输/响应错误分别使用 provider_request_failed/provider_response_failed，使上层能够停止跨模型回退而无需解释认证实现。Core 将 code 传给 Application，持久化到 `run_failed.payload.error_code`，CLI `run --json` 的 events 原样携带；不在 RunRecord 增加重复认证状态。

## 装配范围与验收

factory 仍只按 protocol 分派，可接收已装配的 authenticator/service policy；managed 缺少 authenticator 时明确失败，不能误用静态 resolver。注入认证端口时，未登录也能构造 adapter，直到 check/推理才返回 authentication_required。

`LocalApplication.build` / `build_local_runtime` 显式接收 driver 与 ProviderServicePolicy 注册；策略包含稳定 policy id、纯目标规则和 ProviderRequestPolicy 服务事实。组合时校验产品声明引用及 id 唯一性，按已校验引用注入 factory；没有插件热加载或用户自定义注册表。static 仍由原 resolver 解析，同样应用产品声明的服务策略。

ProviderRequestPolicy 包含额度错误码、计费方式和 supports_output_limit（默认 true）。输出上限能力与认证和计费方式独立，由受信服务装配注入，不成为用户配置开关。false 表示单一 max_output_tokens 只保留本地预算语义，Responses/Chat adapter 省略相应输出上限字段，使用入口明确披露实际输出可能超过预算。Messages 协议要求输出上限，装配 false 时明确拒绝。Core 预算、压缩和用量记账不依赖此服务标记，也不通过本地截流伪造硬上限。

每个本地 Runtime 创建一个 home 范围的 CredentialService 和 ProviderAuthService，主模型、专用压缩、子会话路由和连接检查借用同一凭据核心。`LocalApplication.provider_auth` 暴露该 Application 用例；注入测试 Runtime 时该 facet 可为空。不同 home 不共享材料或关闭行为；构造和目录查询不读取 managed 秘密，未登录默认模型可以启动、进入管理及执行注销。

认证生命周期跟随 Runtime 的显式资源所有权，以覆盖独立 run/check 入口：LocalApplication 在停止消费者前关闭登录用例，Runtime.close 也负责这一前置步骤，随后关闭模型 catalog/辅助 adapter，最后关闭凭据核心。重复关闭复用同一任务；调用者取消不跳过收尾，某项失败不阻止关闭后续资源。启动失败复用相同清理路径，保留原启动错误。轻量 auth CLI 继续使用独立组合，不启动模型 Runtime。

ConfiguredModelCatalog 在所有已配置路由（含初始默认路由）上比较完整运行参数的规范化摘要，覆盖 driver、credential ref、服务引用、连接参数和 inline Key；不使用隐藏秘密字段的 repr，也不读取 managed 记录生成指纹。启动缓存以构造 adapter 时的实际参数为基准，配置在构造间隙变化仍会被发现。显式进程参数只保留到原始默认路由；已配置路由删除/禁用后不退回旧 adapter。纯临时、未配置的路由仍由注入 adapter 负责。

并发 Session 请求在同一临界区内解析、构建和发布缓存，避免重复构造导致 HTTP client 失去关闭归属。替换后的 adapter 保留到 Runtime 关闭，已开始的请求不被中断；普通 Token 更新不改变配置指纹。专用压缩请求通过同一 catalog 在边界重新选择 adapter，绑定变化会生效；受管理请求失败、结构化认证/访问/额度错误以及已绑定压缩路由配置失效是终止错误，不触发其他模型或策略回退。未分类摘要质量等失败保留既有压缩回退契约。

LocalApplication 与轻量认证组合均内建 openai-codex 浏览器驱动；额外注入的驱动/策略作为补充，重复 id 明确拒绝。服务策略只允许 https://chatgpt.com/backend-api/codex/responses 路径子树，billing_mode=subscription、supports_output_limit=false；标准协议 adapter 不判断产品。驱动按请求创建并关闭 HTTP client，纯构造不读秘密或发网络请求。公开客户端兼容接入与能力范围见[使用指南](../../docs/OURO_订阅支持使用指南_ZH_2026-09-19.md)。真实 adapter 探针已通过，持久凭据的真实 CLI 登录、check/run、跨进程续接及注销已通过；证据范围见上述使用指南。
