# 供应商模板本地化规格

> 文档类型：现行规格
> 代码基线：2026-09-02

## 目标与范围

定义供应商模板目录的本地文件契约：内联目录与本地文件的关系、版本模型、修改感知、自动升级、
结构迁移与失败处理。模板是配置域蓝图数据，不是新的 adapter 类型；模板与实际 Provider 配置的
实例化关系、类型与协议拆分由 [Provider 与配置](OURO_Provider配置规格_2026-09-02.md)和
[Provider 类型与协议](OURO_Provider类型与协议规格_2026-09-02.md)定义。内联模板目录继续由
`ouro/config/provider_templates.py` 维护。

## 总体模型

内联供应商模板配置是唯一数据真源；本地模板文件是内联配置的物化副本，叠加用户覆盖层。文件层面
与模板层面的全部边界行为由该模型推导，不出现双真源歧义。

本地模板文件为独立 JSON 文件，位于 `OURO_HOME` 目录下 `config` 子目录的
`provider-templates.json`，不并入 `config/config.json`，使模板升级逻辑与用户其他设置互不影响。
文件读写复用既有的原子写与跨进程互斥锁机制。

## 本地文件布局

`templates` 以 `template_id` 为 key；模板业务字段集合与既有内联 `ProviderTemplate` 模型一致
（含端点嵌套结构），本规格不重复定义。示例中端点为节略：

```json
{
  "schema_version": 1,
  "templates": {
    "openai": {
      "template_id": "openai",
      "display_name": "OpenAI",
      "provider_type": "openai",
      "protocol": "openai-chat-completions",
      "credential_env": "OPENAI_API_KEY",
      "base_url": "https://api.openai.com/v1",
      "default_endpoint": "gpt-5.6",
      "endpoints": {
        "gpt-5.6": {"model_id": "gpt-5.6"}
      },
      "meta": {
        "origin": "inline",
        "baseline_revision": 1,
        "baseline_fingerprint": "sha256:…",
        "deprecated": false,
        "enabled": true
      }
    }
  }
}
```

模板级元数据固定存于 `meta` 对象，字段与归属如下：

| 字段 | 归属 | 语义 |
|---|---|---|
| `meta.origin` | 系统 | `inline` 或 `custom`；按 `template_id` 是否存在于内联目录判定 |
| `meta.baseline_revision` | 系统 | 该副本最后对齐的内联修订号；`custom` 模板为 `null` |
| `meta.baseline_fingerprint` | 系统 | 物化时内联业务字段的规范化指纹；`custom` 模板为 `null` |
| `meta.deprecated` | 系统 | 内联目录已废弃该模板；仅对 `inline` 来源有意义 |
| `meta.enabled` | 用户 | 启用状态；`false` 即禁用，不进入可选模板列表 |

`meta.enabled` 只约束模板目录呈现，与 Provider 实例的 `enabled` 无关。系统管理字段由系统写入，
用户手改 `baseline_fingerprint` 的最坏后果是模板被判未修改而被后续升级覆盖。

## 版本模型

版本为两个独立维度，不可混用：

- 结构版本（`schema_version`）为文件级，标记模板字段布局本身的变化，决定是否需要迁移；
- 内容更新为模板级，内联目录每个模板携带单调递增修订号（`revision`），本地以
  `meta.baseline_revision` 记录，逐模板比较即可判定落后或降级。不设文件级内容版本，也不维护
  全局内容计数器。

比较双向定义：

- 本地结构版本低于内联时进入迁移流程；高于内联（用户回退旧版 OURO）时不做任何重置或改写，
  按当前版本可理解的范围加载；
- 本地基线修订号低于内联进入升级；高于内联视为降级，不予改动。

加载器对文件中的未知字段采取容忍策略：加载时忽略而非拒绝，读改写与迁移的往返中原样透传保留，
防止降级场景被误判为损坏、也防止旧版写回时丢失新版字段。该容忍策略仅适用于本地模板文件；
`config/config.json` 的权威结构仍按 [Provider 与配置](OURO_Provider配置规格_2026-09-02.md)严格拒绝未知字段。

内联维护纪律：同一 `template_id` 的修订号单调不回落；模板废弃后重新加回时，修订号须延续更高
值，否则存量用户会误判为降级而永久不更新，废弃标记清除也随之卡死。

## 校验与错误反馈

系统只负责 schema 层面检测判断配置合法性，不分析、推测实际配置有效性（路由、端点、凭据）。

校验采取模板级容错：单个模板校验失败仅跳过该模板并单独报告，不影响文件内其余模板的加载。
校验结果通过明确渠道反馈（CLI 输出、TUI 提示、日志），指明具体 `template_id` 与字段，保证用户
可自助定位与修复。

本地模板文件的任何加载失败都不阻止 OURO 启动，运行时回退内联目录。

## 修改感知

用户是否修改过模板由系统判定，不依赖用户手动声明。

指纹只对模板业务字段计算，基面为业务字段原始映射的规范化序列化（键排序、紧凑分隔、UTF-8
文本），排除全部模板级元数据。原始映射是唯一可跨结构版本比较的指纹基面，迁移前的修改判定依赖
这一性质。系统写入的条目始终全量物化字段，用户重排键序或空白不影响指纹；删除显式写入的默认值
或新增未知键视为修改，保守方向为保留用户版本。指纹算法与规范化规则跨版本稳定，任何变更按结构
版本变更处理。

升级时对比当前内容指纹与 `meta.baseline_fingerprint`：一致判定为未修改，允许被升级覆盖；
不一致判定为用户修改，保留用户版本。这是唯一的保留判定规则，不存在用户手动声明的接管或
锁定标记。系统对被保留且上游存在新修订的模板给出提示，并提供放弃本地修改、恢复内联版本的
途径（`provider restore-template <id>`）。

用户新增的自定义模板与未来内联新增模板发生 `template_id` 冲突时，用户配置优先并给出告警。

## 初始化与失败处理

本地模板文件不存在时，自动从内联目录物化写入，每个模板携带默认元数据：`origin` 为 `inline`、
基线修订号与基线指纹为内联当前值、`deprecated` 为 `false`、`enabled` 为 `true`。

加载失败按原因区分：

- 语法错误（整文件不可解析）：原地保留文件，不重命名、不重建、不重置主文件；运行时回退内联
  目录并明确提示用户在原文件上修复。运行时始终可无损回退内联，不制造备份或重建窗口；
- 校验错误：按模板级容错处理，不触发整文件回退；
- IO 类失败（权限不足、文件被占用等）：不执行任何写入，仅运行时回退内联目录。

所有写入采用临时文件加原子替换；读改写事务以跨进程锁包裹，防止并发竞态与半写文件。

## 升级

升级在启动时触发，逐模板按基线修订号与内联修订号比较，对每个 `template_id` 独立决策：

- 基线修订号等于内联修订号：无动作；
- 基线修订号低于内联，且未修改：覆盖该模板，仅替换业务字段；`baseline_revision` 与
  `baseline_fingerprint` 按升级结果更新；用户字段（`enabled`）原样保留；
- 基线修订号低于内联，且已修改：保留用户版本，同时推进 `baseline_revision` 至内联
  当前值、保持 `baseline_fingerprint` 不变（语义为该修订已知悉、内容有意保留），使上游更新
  提示仅在真正出现新修订时触发一次，而非每次启动重复提示；
- 基线修订号高于内联：降级，不予改动；
- 内联目录存在而本地缺失：物化新增，含被用户删除的内联模板的补回；
- 本地存在而内联缺失：不静默删除，标记 `deprecated` 并提示用户；废弃模板是否仍进入可选列表
  由呈现层决定；内联后续重新加回同名模板时，随升级动作清除废弃标记；
- `origin` 为 `custom` 的 `template_id` 出现于内联目录：用户配置优先，告警提示。

升级不做字段级合并：判定保留用户版本的模板整体保留，其后新增字段不自动合入，仅通过上游更新
提示交由用户处理。写入成功后方更新对应模板的基线字段，失败保持原状待下次重试；升级完成后向
用户提示变更摘要。

## 结构迁移

内联结构版本高于本地结构版本时，先执行结构迁移再执行内容升级。完整时序：

1. 在旧结构上完成全部模板的修改判定（对比当前指纹与基线指纹）；判定必须先于迁移，否则迁移
   引起的字段变化会使未修改模板指纹漂移而被误判为用户修改；
2. 对原文件做完整备份，备份名带时间戳，避免多次迁移互相覆盖；
3. 按字段级迁移规则将所有模板（含用户修改的模板）转换到新结构，而非整体覆盖，以免
   用户模板因结构过期被校验跳过而静默丢失；迁移过程中未知字段同样原样透传；
4. 对判定为未修改的模板以迁移后内容重算 `baseline_fingerprint`；重算属系统行为，不改变
   未修改这一事实。用户修改过的模板不重算，保留其版本；
5. 进入内容升级。

无法自动迁移的模板保留原样：若仍通过新 schema 校验则照常加载，否则按校验一节跳过；两种情况
均单独报告，交由用户手动处理，不丢弃，不强制打不可加载标记。

迁移走原子写，写入失败时主文件未变、无需回滚；时间戳备份用于迁移结果逻辑出错时的人工回滚
依据。迁移后向用户提示。

## 删除与禁用

删除语义按模板来源区分：

- 内联来源模板不可删除：删除后升级仍会从内联目录补回；
- 自定义模板可以删除：删除即真正移除，不补回。

禁用通过 `meta.enabled` 表达：被禁用模板不进入可选模板列表；升级覆盖仅替换业务字段、原样
保留用户字段，因此不会重新启用。

## 边界与约束

- 模板与实例为复制关系而非引用关系：模板升级不自动改动任何已配置的实际供应商，用户需要同步
  时须显式执行基于模板的更新操作；实例侧以紧凑旧基线做三方合并，完整规则见
  [Provider 配置](OURO_Provider配置规格_2026-09-02.md#模板来源与显式更新)；
- 模板文件不承载明文凭据：模板仅包含凭据环境变量名等引用信息，schema 校验对疑似明文密钥内容
  给出告警；
- 内联目录在代码中继续维护，作为首次初始化、运行时回退与升级比对的唯一依据；
- 本地文件与内联定义之间保持序列化往返一致性（含端点嵌套结构），并以此为基线建立回归校验；
  指纹规范化与序列化往返为两件独立事项：前者保证语义相等的不同写法指纹一致，后者保证读写
  不失真，二者均需单独覆盖测试；
- 结构演进以增量变更为原则（新增字段、新增可选分支），破坏性变更（字段改名、删除、类型变更）
  须通过新旧字段并存逐步过渡，使回退旧版 OURO 的用户仍可被旧代码读取；迁移规则同受此约束；
- 模板级元数据的字段归属：`origin`、`baseline_revision`、`baseline_fingerprint`、
  `deprecated` 为系统管理字段，`enabled` 为用户字段；全部模板级元数据均
  排除在指纹计算之外。

## 非目标

- 不分析、推测实际配置有效性（路由、端点连通性、凭据可用性）；
- 不做字段级或语义级合并；
- 不设文件级内容版本或全局内容计数器；
- 不在模板目录升级时自动同步已实例化的 Provider 配置；显式 Provider 更新属于 Provider 配置域；
- 不涉及模板分发、导入或分享机制。
