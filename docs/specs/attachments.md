# 附件输入与 TUI 交互规格

> 文档类型：现行规格
> 范围：会话副本与原路径引用、提交与排队、模型内容投影、历史请求和 TUI 交互
> 真实终端、视觉端点与跨平台验证范围见[附件输入验收](../plans/attachment-validation.md)。

## 1. 目标和所有权

本规格定义文本、图片、音频、视频和不透明文件作为任务材料进入 OURO 的行为。设计依据及社区源码证据见
[文件输入架构](../architecture/file-input.md)。提交与撤销遵循[运行时](runtime.md)和
[会话撤销](session-undo.md)，资源身份遵循[资源规格](resources-and-supervision.md)，视觉遵循[TUI 规格](tui.md)。

- 文件项按来源区分上传副本与原路径引用，统一保存原名称和它在用户文字中的位置。
- 上传副本归当前 Session 所有；原路径引用只绑定源路径及选择时的工作区，不导入附件库。
- Application 校验、导入、接受输入、排队和取消；Host 不写 Session 存储，不展开模型附件。
- TUI 编辑器拥有文字与附件元素组成的草稿；文件名不是身份，不从普通用户文字猜出已上传附件。
- 模型正文与附件骨架分别保存，表示选择不覆盖原件和用户文字。

上传副本保存在 `OURO_HOME/sessions/<session_id>/resources/files/<filename>`，保留可读文件名；
同名冲突分配 `名称 (2).后缀`，相同内容不合并不同名称或来源。导入绝不自动写入工作目录。
`@file` 保存原文件的绝对路径，工作区内引用另绑定选择时的工作区；切换工作区后提交绑定不一致的引用会明确拒绝，
不会重新解释为另一个项目中的同名文件。存储归属见[资源规格](resources-and-supervision.md)。

## 2. 附件草稿

### AT-01：输入内容

草稿由用户文字和有序附件项组成。上传项携带会话资源身份，引用项携带原路径和可选工作区绑定；公共部分包括原文件名、文字偏移及同位置元素的顺序；偏移以 Unicode 码点计数，
不包含附件显示字符。多个附件可以处于相同文字位置，保持加入顺序。同名不同内容以不同资源身份处理。
同一资源重复选择不必重复传输，不能把相同文件名的其他资源错误合并。

上传元素显示文件名及扩展名（如 `测试图片.jpg`），原路径引用显示 `@文件名及扩展名`（如 `@测试图片.jpg`），完整路径保留在引用数据中，使用主题 accent 色。它是不可拆开的编辑单位，
不是写入用户正文的文件名文字。长名称遵循编辑器现有换行和视口规则，不能撑宽终端布局。

### AT-02：编辑和恢复

- 光标可移到元素前后；Backspace 或 Delete 命中元素时一次删除整个元素。
- 范围删除、剪切或替换只要覆盖元素的一部分，便作用于整个元素，不留下半个文件名。
- 元素内部的插入落到元素边界；编辑器撤销/重做同时恢复文字和附件身份。
- 普通复制/粘贴文字不自动获得附件身份；成功导入或显式恢复的结构化草稿才能创建元素。
- 会话切换、发送失败和排队撤回恢复完整草稿，附件不串到其他会话。
- 删除元素只改变草稿，资源移除由所属会话的消息和队列引用约束。

草稿记忆启用时文字和附件一同保存，禁用时遵循现有设置，不另设附件开关。
空文字但有附件的草稿有效。导入未完成时不能发送半份输入。
单次提交最多 16 个文件元素；合并恢复可以暂时超过此数，编辑器保留全部内容，提交前需缩减到限制内。
输入历史按 Session 隔离。草稿 schema 4 保存来源、原文件名、路径绑定与结构化位置，欢迎草稿也可保存引用。
不支持的格式明确报错并保留原文件；本次进程内的新草稿不覆盖该文件，完成显式数据维护并重启后恢复持久化。

## 3. 导入入口

### AT-03：批量拖入终端

终端通常把拖入文件表示为粘贴的路径文字，TUI 以有界解析支持带引号、空格、中文、换行、Windows 绝对路径、
POSIX 绝对路径及本地 `file:` URI 的批量输入。不执行 shell，不做变量、通配符或命令替换展开。
只有整个粘贴内容能解释为存在的普通文件集合时才触发导入；混有说明文字或无法确认时保持原始文字。
目录不作为文件上传，不递归展开；符号链接、设备等按资源校验拒绝。

欢迎页和会话页在终端事件入口识别文件路径，不依赖输入框焦点或鼠标落点。终端因拖动失焦、
尚未恢复控件焦点时，首次收到路径粘贴即可导入；成功后附件填入当前草稿并聚焦输入框，无需再次拖动。
普通文字继续交给原焦点控件处理；设置等独立界面、只读会话和等待交互时遵循各自输入规则。
文件识别期间切换会话或进入其他交互会中止本次接收并提示，不把附件插入另一个输入目标。

成功项按原顺序在原输入位置插入元素。部分失败明确显示失败项，不显示虚假成功，不丢失已有草稿。
不同终端的真实拖入编码分别验证，不将 headless 粘贴测试描述为所有终端验证通过。

外部文件拖入后的接收以路径粘贴事件为边界。当前终端输入链路不提供松手前的拖入、移出或悬停通知，
因此拖拽悬停提示由终端宿主负责，TUI 不通过鼠标移动或焦点变化推测文件拖拽状态。

### AT-04：@file 文件选择

仅在输入框首位键入 `@` 显示 `@file` 与 `@skill` 引用类型，选择 `@file` 或输入 `@file ` 打开目录菜单。
两级菜单复用 `/` 的 CommandPopup；不切换到行动菜单或 modal Screen。焦点留在输入框，继续键入名称过滤当前目录；正文中、空白后或已有元素后的 `@` 以及粘贴正文不自动触发。
起点是当前会话工作目录，未创建会话时使用草稿工作目录。

- 菜单顶部常驻低亮度当前目录路径，右侧固定显示已选数量 `[x]`；路径过长时省略，计数保持右对齐。列表滚动或过滤无匹配不隐藏顶部行。目录优先并稳定排序，按需进入，不递归扫描工作区。
- 父级、目录和文件名称使用相同左端起点。父级和目录不使用 `/` 后缀，不显示文件多选标记；文件在名称左侧显示主题定义的选中与未选中标记，焦点箭头与多选状态各自独立，不堆叠树枝和装饰。
- `↑/↓` 移动，Enter 进入目录，`..` 条目返回父目录且不显示附加提示，根目录不提供无效父级。
- Enter 在文件上直接添加原路径引用；Space 切换文件选中，主题化标记显示选择，支持跨目录保留选择。
- Space 在目录或导航条目上不产生选择；匹配期间过滤词只属于当前菜单，不写入用户消息或持久草稿。
- 非空过滤词没有匹配项时显示空结果提示并保留顶部行；无已选项时 Space 输入普通空格，回车将完整 `@file` 输入插回草稿首位并按普通文本发送，保留已有附件与提交模式。
- 有多选时 Enter 在文件上或无匹配项时引用全部选中文件；目录上的 Enter 仍用于导航。选中数量仅在顶部显示，不占用可选列表条目。
- Esc 或删除 `@` 关闭并恢复原草稿和光标位置，不增加第二次确认。
- 进入目录或返回父目录时，异步读取期间保留上一份完整列表、路径和菜单高度；成功后一次更新目录视图，不经过空列表或收缩的加载占位。首次打开没有列表时才显示加载提示。
- 导航成功清空原目录过滤词；读取期间新输入的过滤词保留并应用到目标目录。取消或切换会话后，迟到结果不再更新菜单。
- 文件消失或目录不可读时给出错误；目录读取失败保留原列表、过滤词和已有选择，不关闭整个 TUI。

复用 CommandPopup 的边框、宽高约束、滚动、主题和键盘导航；会话页与欢迎页都紧贴输入框，窄终端不横向溢出。

## 4. 提交、排队与撤回

### AT-05：提交边界

导入成功表示进入草稿，不等于 LLM 已读取。欢迎页选择或拖入附件后保留欢迎页和输入框，发送消息时才进入会话页。
上传为资源归属准备空闲 Session，不改变这一页面边界；单纯选择原路径不创建 Session。发送时将文字和附件作为同一接受单位校验。
Enter 沿用 follow-up，Ctrl+Enter 沿用 steer；附件不绕过现有输入策略、权限或安全 turn 边界。
同次引用多个文件时，汇总文件说明与可用内容到一条完整附件骨架，不逐文件创建消息。混合选择的全部 Skill 激活保存在同一条用户正文消息中，不逐 Skill 创建骨架或拆分提交。
一次提交保存附件骨架（`role=user, scaffold=true, semantic_tag=attachments`）及存在时的独立用户正文
（`role=user, scaffold=false`）。回执保留 Host 来源和触发提交关系，不能虚构工具调用。
空正文附件不虚构分析指令；选择和导入草稿不单独调用模型。

队列消费与消息写入遵循同一持久化提交边界；不能形成半份输入。骨架与正文属于同一上下文输入单元，
压缩不能错误拆分。用户撤销以正文或仅含文件的骨架定位，恢复整个输入；配对正文的 Host 骨架不能独立作为用户撤销目标。
底层任意消息节点撤销仍遵循[会话撤销规格](session-undo.md)。

### AT-06：排队展示

队列以一次提交为一个可编辑项，不分别列骨架和正文。查询 DTO 提供完整附件项。
排队列表及 `/unqueue` 菜单在行右侧分别展示非零的附件和引用数量，例如 `2 attachments · 1 reference`。
数量按附件元素数计，标签使用主题色，不拼入 prompt，不参与身份匹配。

### AT-07：撤回排队项

按 queue ID 原子取消未消费的整个输入，成功后恢复原文字、文件名、顺序和位置。
若已消费，明确提示已不在队列，不伪造成功或重发。若已有新草稿，合并保留并提示，附件偏移同步调整，不能静默覆盖。
取消前捕获目标 Session，异步结果不能写入后来切换到的会话。发送失败只恢复未被接受的输入，
已进入 durable 队列或 canonical 历史的输入不能因模型失败再次插回待发送草稿。

## 5. 模型投影与资源输出

### AT-08：表示和预算

每项以自然语言展示原文件名、来源、真实读取路径、已知类型与大小和表示状态。
上传项的 `Session file` 为会话内不冲突的存储名称；请求中的读取路径表用该名称关联绝对地址，明确区分同名原文件。
模型无需使用内部资源 ID 或 OURO URI；提供路径不代表提供了文本、像素、音频或视频内容。类型依据受限内容检查与确定性解码，不完全依赖后缀。
文件及文件名不因处于 scaffold 就获得 system 或 Skill 权限。

- 文本在单项及全局预算内提供全文，否则提供首尾预览、可验证范围、省略标志与引用。
- 图片、音频、视频在端点输入能力、codec、格式和预算均满足时提供对应原生块，否则引用降级并明确未提供媒体内容的原因。
- 不透明文件提供元信息和引用，不默认解析、执行或解压。
- 读取失败与能力不足分开表达；不能声称看过仅提供引用的内容。

能力不足的请求说明直接告知模型无法查看图片、听取音频或查看视频，重复尝试或改变大小无效；大小或总量超限则建议减少文件或
提供更小的版本，不使用端点、消息角色或内部预算术语。持久化的输入说明使用过去时描述附件加入时的情况，
后续模型不会被旧说明误标为不支持该模态。

同次输入的全部文件共享准备预算，预览不称为语义摘要。准备完成的文本与媒体直接持久化在骨架 `content` 中，
后续对话复用消息内容，工具读取结果保存于各自的 tool_result。历史总量由既有上下文预算和压缩机制管理。

当前默认限额：原件导入 100 MiB；单项文本最多 8 KiB，单次文件输入共用 8192 的保守准备配额，
文本按 UTF-8 字节数计、每个原生媒体块按 2048 的本地规划配额计；媒体单项原始字节最多 20 MiB，Base64 合计最多 20 Mi 字符。
每次请求的附件、内联媒体与工具资源共用 20 Mi 编码字符限额。无法发送的模态或格式不占用限额；其余已有媒体和各资源预览依次扣减。
资源媒体在签名识别后、完整内容载入内存与编码前检查剩余额度；上传资源的窗口读取仍需流式校验整个文件的摘要与大小。
ContextBuilder 对全部消息、元信息和工具定义做完整预算检查。
媒体配额不是实际 token 上界；音视频时长、帧采样和供应商编码决定实际消耗，账单与 usage 只采用供应商报告值。Host/tool 输出资源的即时投影另受 `min(8192, 模型输入预算 / 4)` 限制。

文本检查支持 UTF-8 与 BOM 标记的 UTF-16；无后缀文本可进入预览，其他格式保持不透明。
首尾预览标注实际字节范围，包括边界不完整的行；解码后 UTF-8 开销超限时缩小首尾窗口，省略不是按语义选取。媒体识别只检查容器签名，
不引入缩放、转码或完整解码器。受支持的原生格式为 PNG/JPEG/GIF/WebP、WAV/MP3、MP4。
识别检查图片签名、RIFF/WAVE、ID3/MPEG Layer III 与 MP4 ftyp 容器品牌；音频专用 M4A/M4B 品牌不作为视频发送，
未知格式或仅有匹配后缀的内容保留为引用。容器识别不保证内部流可解码，服务端解码失败按普通请求错误报告。
识别得到的类型用于媒体块及文件说明，不由文件名覆盖。图片、音频、视频分别用标准 `ImageContent`、
`AudioContent`、`VideoContent` 保存 URI 与媒体类型；Provider adapter 负责原生协议编码，具体协议范围见
[输入模态契约](provider-configuration.md#输入模态契约)。

图片骨架的相关字段如下；省略其他消息字段，`<图片字节的 Base64>` 是示意占位值：

```json
{
  "role": "user",
  "scaffold": true,
  "semantic_tag": "attachments",
  "content": [
    {
      "type": "text",
      "text": "File: \"页面截图.png\"\nSource: Session attachment\nSession file: \"页面截图.png\"\nMedia type: image/png; size: 1024 bytes\n"
    },
    {
      "type": "image",
      "uri": "data:image/png;base64,<图片字节的 Base64>",
      "media_type": "image/png"
    }
  ]
}
```

文字块保存说明；媒体块保存当时实际输入的字节。音频块的 `type` 为 `audio`，视频块为 `video`，
`uri` 分别采用 `data:audio/wav;base64,...`、`data:audio/mpeg;base64,...` 或 `data:video/mp4;base64,...`。
不自动生成 OCR、转写或音视频摘要。Base64 是持久化与传输表示，不作为普通文本交给模型阅读。
原路径媒体按同样方式保存已经输入的内容，源文件后来删除也不会改变这条历史消息。
未提供原生媒体时没有媒体块，只保存元信息、路径及原因；上传原件仍由会话附件目录持有。

### AT-09：读取和输出

Agent 自主使用现有 Read、Glob、Grep 或其他工具操作所提供的真实路径；输入准备不伪造工具调用，
工具目录与文件输入解耦。Read 按 UTF-8 文本与行分页契约执行；非文本的处理取决于实际可用工具。
通用路径策略包含当前会话附件目录的只读范围，不开放其他会话或整个 OURO_HOME，也不扩展写入权限。
`@file` 不授予父目录访问权限，受 workspace_only 限制的原路径明确报告受限。
工具输出保留真实 tool_result 身份，产物可使用现有资源服务；模型编造的路径或 ID 不自动成为产物。

### AT-10：历史与请求快照

切模型与压缩模型只对保存的内容作请求适配，例如省略目标不支持的原生媒体，原件与旧快照不变。快照还原当时实际范围、媒体和降级原因，
不能按查询时的新能力解释旧请求。分支与回收维持引用完整；迟到导入结果受 history_epoch 与 Host 导航归属约束。

原路径在输入消费时做一次有界观察，使用同一文件句柄读取所需范围，比较前后文件身份、大小和修改时间。
变化时仅重试一次，持续变化或不可读则保留路径并注明未提供内容；排队期间不预先复制工作区。
已观察的文本和媒体直接存入文件骨架的 TextContent/ImageContent/AudioContent/VideoContent，后续请求不重新读取原文件，也不自动扫描依赖。
上传项的实际读取路径按当前会话清单附加到请求；副本内容已在骨架中，不因分支或导入重新生成预览。
目标端点不支持对应模态或预算不足时仍可降级为引用；切换模型不补读历史引用从未观察过的内容。

ContextSnapshot schema 4 原样保存实际发送的文本、原生媒体字节、当时端点的三种输入能力和降级说明，查询不读取原文件，
不反推上传 ID，不按当前模型能力重建历史。分支选择文件骨架会扩展到同一输入的正文；
分支和子会话得到独立上传副本，删除源会话不影响目标。会话迁移携带上传副本与实际请求快照，
原路径仅保留为外部依赖；新请求重算上传副本的目标地址，历史快照保留当时地址。

## 6. 验收

| 场景 | 证据 |
|---|---|
| 批量路径、中文空格、引号和 URI | 元素顺序与位置正确，不执行路径文字 |
| 普通粘贴、邮箱和混合文字 | 不误上传 |
| @file 导航、过滤、多选、取消 | 复用菜单，跨目录选择保持，Enter 无多余确认 |
| 原子删除、替换、剪切、撤销/重做 | 文字与资源身份一致 |
| 同名文件、混合文字、空正文 | 独立消息及来源正确 |
| 活跃 Run 的 follow-up/steer | 可排队，数量标签正确，不拆工具交换 |
| 撤回竞争、已有新草稿、会话切换 | 不丢内容、不跨会话污染、不重复接受 |
| 长文本、图片、音频、视频、二进制、预算不足 | 降级明确，原件可继续读取 |
| 压缩、撤销、快照与重启 | 不丢引用，不伪还原请求 |

算法、应用集成、Textual headless 和真实终端分别记录；未执行的平台验证保留明确状态。
