# 数据升级

> 文档类型：现行契约

## 目标与边界

`ouro-upgrade` 将已停写 home 内受支持的历史核心数据转换为 OURO 的当前格式。
后端选择和数据位置保持不变。工具随 `ouro-agent` 安装，也可用 `python -m ouro_upgrade` 调用。
操作方法见[数据升级指南](../guides/data-upgrade.md)。

历史转换集中于 `ouro_upgrade`，不启动 Runtime、插件、模型、认证刷新或任务调度。
升级根据已保存内容补齐缺失的结构信息，执行结果未知的调用保留为可恢复状态。当前格式检查不是全库健康审计。
转换保留未选后端、附件本体、任务防重标记、回收站、既有备份、凭据、其他配置、插件安装包、审计及插件私有数据，
在报告的 `preserved_outside_scope` 中声明；旧回收站不能直接恢复为当前在线数据。

## 支持格式

转换依据实际记录与容器版本，不依据应用版本推测格式。未登记的中间版本明确拒绝。
历史 writer 来源和合成场景见 [tests/upgrade/fixtures](../../tests/upgrade/fixtures/README.md)。

| 数据 | 源格式 | 当前处理 |

| providers.json | 历史能力、reasoning 字段或当前字段 | 当前 codec 校验并维护模板绑定基线 |

## 精简模型的持久化边界

| 持久化内容 | 转换与校验 | 失败删除边界 |
|---|---|---|
| 智能体配置、Run 目录、委派冻结定义 | 核验源哈希，移除能力字段，重算定义及目录哈希 | 配置文件或所属会话存储单元 |
| 委派身份、投递策略与层级副本 | 确认与定义、调用来源及执行模式一致后移除 | 所属会话存储单元 |
| Session、Harness、续接与工具提案中的控制激活 | 移除激活阶段、修订、更新时间与错误占位；保留控制集合修订及业务 data | 所属会话存储单元 |
| 工具调用等待状态 | 校验 resolution 与等待对象一致，移除可推导状态和重复身份 | 所属会话存储单元 |
| Session 与目录标题 | 移除 title_locked，保留 title_source | 所属会话存储单元 |
| plugins/state.json | 核验安装身份、版本、来源摘要及活动配置副本，再移除冗余字段 | 仅状态文件，原文件进入备份 |

插件代次记录、命令原始结果与绑定结果是进程内对象，无独立持久化转换。消息正文、工具结果、审计和
插件私有数据中的历史业务 JSON 保持原样，不按同名键递归修改。Files 的失败单元是所属会话目录，
原生 SQLite 的失败单元是会话数据库；删除范围沿用对应存储的恢复边界。

## 转换与处理成本

当前文件容器枚举会话目录，并在原生数据库中检查 Session、Run、工具调用状态的版本及相关结构；委派与 Harness 按其独立记录检查。
Run 与委派中的冻结智能体定义和目录先核验源哈希，再转换并重算哈希；容器版本已是当前值也执行结构检查。
转换保留原定义内容、工具授权、身份和时间，不读取当前消息和请求正文。
layout 41 与 schema 26 的消息、调用事实、Run、请求头和草稿已采用原生存储。升级只在私有数据库副本中
添加事实修订列及索引、移除会话事件表；Files 输入状态按文件预取后直接写入数据库，原始 Input 正文保持原位。
Session、Run 与委派按独立版本转换调用授权字段，保留 workspace、已授予的工具集合和审批下限；目录摘要先校验再重算。
消息与请求正文不解析、不重建，工具执行事实、输入状态原文、顺序和身份保持不变。
SQLite 的整体副本与一致性检查仍随库大小增长，释放页交给数据库复用，不额外执行全库重排。
无 WAL 或恢复日志的 SQLite 库通过 immutable 只读连接检查版本和相关记录结构；当前数据不计算整库摘要、
不复制数据库或创建协调文件。
存在辅助状态时，在私有副本上检查，确保包含已提交 WAL。

历史会话以单个会话为内存边界，主体源记录读取一次，直接生成当前编码和索引，不逐代写回业务文件。
执行调用按 `ToolInvocation` 的已知字段投影后校验，保留参数、授权和执行身份，不将额外生产者注解作为转换前提。
参数与业务 JSON 保持原值；已知字段的类型和调用归属仍须满足各自契约。
SQLite 按 Session 归属索引读取，缺少归属索引的摘要表只在私有副本中建立索引。
目标数据库直接移交发布工作区，不再复制回源副本。附件不读入暂存区。

消息保留身份、顺序、自有正文和开放 metadata，序号与会话计数按实际记录重建。
缺失时间优先采用会话或 Run 中已有时间，无可用时间时使用 Unix 起点；缺失 Harness 使用默认状态。
Call 优先使用原批次身份；没有保存批次的历史消息使用消息身份作为稳定批次键，没有 turn 时使用消息身份作为结构分组键。
已发布结果关联同 Run 中此前保存的 Call；找不到请求时，保留结果身份并用空参数建立结构记录。
只有已发布文本时保存为字面反馈，不推测执行结果。

已保存批次结果拆分为 Call、Start、Outcome 与状态，保留参数、结构化结果和时间；未提交生效的工具变更提案直接丢弃。
绑定使用所属 Call 的身份；缺失绑定从 Call 构建，缺失开始与结束时间使用请求和批次时间。
运行中但没有结果的调用保存为 unknown_outcome，所属 Run 和批次标记为 recoverable。
历史消息已承载消费后的输入正文和附件，queued_input_id 标记直接丢弃，不重建已消费队列及其来源记录。

委派优先使用保存的父批次，按父 Session、Run 和 Call 查询；多条匹配使用最近保存的记录。
缺少父 Call 时保留父子会话关系，清除失效调用关联，结果仅作通知。
文件转换按被引用的父会话分组，只读取所需 Run；仍缺关联时流式扫描该父会话消息一次，不加载其他会话正文。
当前父会话通过原生数据库索引查询。

请求保存为固定 Manifest，不重新运行上下文投影、估算 token 或重算摘要。
completed_at 对应 provider_done_at，缺少完成事实时保持未结算。
旧请求摘要、摘要散列、Run 用量缓存及操作回执不属于当前在线契约，其原文件或数据库保存在维护备份中。
文件后端的旧 Session/Run JSON、完整 context、资源索引、事件与摘要日志、操作回执、事件偏移索引
随目标产物发布移入备份。Harness 与委派保持各自存储责任。

预算转换保留估算值与 estimator，将窗口和输出上限归入 budget；当前 budget 优先，缺失窗口时使用无预算默认值。
旧剩余量、利用率等派生计数直接丢弃，读取时由当前模型计算。
历史会话事件不进入当前格式；保留在原始备份中。工具参数、提供方原生片段及开放字典不递归转换。

## 用量、任务与配置

有效账单和完整审计分别转换，不重放 reset 或 replace 来重算账单。
原始请求引用指向审计中的 record 事件，Run 原始小计只累计首次报告；修订值继续保留在有效账单中。
重复原始请求身份不能静默覆盖。金额、token、时间、顺序和审计身份保持不变。

任务 description 成为 agent target 的 prompt，workspace、model、reasoning、approval_mode、session_mode
移入 target；执行归属同步迁入 agent target。无插件所有者时 owner_id 为 null，result 为 null，
cancel_requested 为 false。任务、执行、revision、日程、历史链与防重标记保持不变。

提供方配置通过有序结构规则转换 supports_vision、reasoning.default_effort、profile.variants 和 profile.text_field。
旧 default_effort 合入 default.effort，明确选择 effort 的 default 模式转为 enabled。
reasoning.profile.text_field 移至端点的 reasoning_text_field；仅声明文本字段的空生成预设置为 null，
非空 effort、summary 映射与默认值保持原样。显式 null 的文本字段按未配置处理。
两个旧默认 effort 不一致、混用新旧字段或未知原生字段均拒绝。原生映射和开放内容原样保留，
不推断摘要能力、不刷新认证。与源结构保存基线一致的端点更新绑定指纹，已修改实例保留旧基线。
模板文件由模板加载流程管理，不参与离线事务。

## 失败与恢复

严格模式在任一转换失败时停止发布。隔离模式保留失败数据，其他独立单元可以发布。
文件会话按 Session 隔离，文件任务按任务隔离；提供方配置、用量、SQLite 会话和 SQLite 任务分别按整个文件或数据库隔离。
原生文件会话全部转换完成后才推进 home 布局与目录索引；部分失败时保留原布局，重试通过数据库结构跳过已完成单元。
文件记录转换后的失败会话保留在目录索引中，缺少会话头的目录也继续列为失败，不因 home 布局已更新而被跳过。

失败单元只有在用户明确确认且重新检查仍失败时才移入维护备份。缺少记录、未知版本、内容损坏和未完成的
单元内事务均可以放弃；已修复的数据正常保留或升级，新失败仍需确认。共享布局无法识别时，删除边界是对应的
文件容器：会话的 `sessions/` 与 `layout.json`，或任务的 `tasks/`。选择删除整个文件会话容器包含其中全部会话及附件。
SQLite 删除只处理所选数据库及其 WAL、SHM、journal 文件，外部资源文件保留。可单独定位的会话失败不扩大为容器删除。
锁、权限、磁盘 I/O 和源文件并发变化属于维护条件，不作为删除依据。删除与转换使用同一备份、发布和恢复管线。

1. home 必须是已有普通目录，用户负责停止所有写入者。标准 CLI/TUI 使用 `.upgrade/lock` 共享锁，
   维护使用独占锁；旧程序、直接 Store 调用和外部脚本仍受停写前提约束。
2. 未完成的会话提交或任务事务可以由原版本恢复，也可以明确放弃所属失败单元；导入、回收及 home 级发布中间态须先恢复。
3. 产物在受限 `.upgrade/<id>/scratch` 生成。只有修改集合进入 `new/`；关闭后的暂存文件直接移交工作区，
   摘要和同步共用一次打开。`--check` 不同步暂存产物、不准备发布、不再次读取源文件。
4. 清单记录相对路径、前后 SHA-256、存在性及文件模式。只复核修改集合；源变化立即停止。
   完整目录删除时摘要覆盖结构和文件内容，只有确认删除才读取其中附件。
5. 清单、产物、原文件和目录同步后写入 `.upgrade/in-progress.json`，此后才修改业务路径。
   每个原文件移到 `before/<序号>`，产物重命名到原位置；删除只保留备份。发布不再次复制产物。
6. 保存 `.upgrade/receipts/<id>.json` 后解除标记。备份和清单保留，工作区必须与业务文件处于同一文件系统。

多文件发布不是 home 级原子事务。标记前失败不改变业务数据；标记后失败保留恢复材料并阻止 Runtime 使用 home。
`--restore` 在写入前核对整个修改集合的原始摘要，备份损坏时停止，不能用业务路径掩盖损坏。
尚未移走的原文件可以留在原位；已移走的原文件从备份复制恢复，重复恢复不消耗备份。
写入清单格式 3，恢复接受格式 1、2、3。恢复只处理未完成的本次发布，不自动降级已经成功升级并继续使用的数据。

## 接口与验证

命令行与 Python 接口默认严格模式，TUI 使用隔离模式。结果状态为 current、upgrade_required、upgraded 或 partial；
failures 和 discarded 分别列出失败、实际删除单元，已发布报告另含备份与清单位置。
进度回调报告当前阶段及已完成单元数，不表示整体百分比。

针对性回归覆盖当前 reader、默认值补全、已消费队列清理、跨会话委派、可恢复工具状态、配置、历史事实转换、
原始与有效用量、当前容器跳过、未知输入拒绝、WAL、失败隔离、确认重查、发布中断、恢复、备份损坏、权限和维护锁。支持范围以这些契约和夹具为准。
