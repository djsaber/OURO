# 数据升级

> 文档类型：现行契约

## 目标与边界

`ouro-upgrade` 将已停写 home 内受支持的历史核心数据转换为 OURO 0.4.0 的当前格式。
后端选择和数据位置保持不变。工具随 `ouro-agent` 安装，也可用 `python -m ouro_upgrade` 调用。
操作方法见[数据升级指南](../guides/data-upgrade.md)。

历史转换集中于 `ouro_upgrade`，不启动 Runtime、插件、模型、认证刷新或任务调度。
升级不修复损坏、不推测执行结果，也不保证历史执行可以续跑。当前格式检查不是全库健康审计。
未选后端、附件本体、任务防重标记、回收站、既有备份、凭据、其他配置及插件私有数据保留原样，
在报告的 `preserved_outside_scope` 中声明；旧回收站不能直接恢复为当前在线数据。

## 支持格式

转换依据实际记录与容器版本，不依据应用版本推测格式。未登记的中间版本明确拒绝。
历史 writer 来源和合成场景见 [tests/upgrade/fixtures](../../tests/upgrade/fixtures/README.md)。

| 数据 | 源格式 | 当前处理 |
|---|---|---|
| 文件 Session | layout 9、41 | 41；每会话原生数据库、消息正文和请求 Manifest |
| SQLite Session | schema 7、26 | 26；按会话读取历史行，直接生成当前表及查询索引 |
| Session | 2 | 5；摘要指针转入 context_selection，controls 来自 Harness，计数来自实际成员 |
| Run | 2、5 | 10；源 2 绑定默认 Driver，工具批次拆分为小头和独立事实、状态 |
| Message | 3、4 | 8；保留原文，工具参数归入 Call，已发布结果引用 Call |
| ContextSnapshot | 3、4、5 | 请求头 11、Manifest 10；保存固定模型可见内容与预算事实 |
| Compaction | 1、2 | 3；保存覆盖数量、终点及展示锚点 |
| Resource | 2、3 | 3；旧资源标为非内部资源，附件本体保持原位 |
| Harness / Event | 1 / 2 | 当前记录；已知事件预算字段按结构转换 |
| Delegation | 1、2 | 2；从唯一父 Call 确定批次，建立父 Run 查询索引 |
| 文件任务 / SQLite 任务 | 1、3 | 3；转换 target、owner、result 与 cancel 字段 |
| 用量 SQLite | 1、2、5 | 5；保留有效账单及审计，建立原始请求引用和 Run 原始用量小计 |
| 用量记录 / 审计记录 | 1、2 | 2；补独立 plugin 归属字段 |
| providers.json | 历史能力、reasoning 字段或当前字段 | 当前 codec 校验并维护模板绑定基线 |

## 转换与处理成本

当前文件容器只枚举会话目录，识别尚待转换的旧 Session 头，不读取当前消息和请求正文。
无 WAL 或恢复日志的当前 SQLite 库通过 immutable 只读连接检查版本，不计算整库摘要、复制数据库或创建协调文件。
存在辅助状态时，在私有副本上检查，确保包含已提交 WAL。

历史会话以单个会话为内存边界，源记录读取一次，直接生成当前编码和索引，不逐代写回业务文件。
SQLite 按 Session 归属索引读取，缺少归属索引的摘要表只在私有副本中建立索引。
目标数据库直接移交发布工作区，不再复制回源副本。附件不读入暂存区。

消息保留身份、顺序、时间、自有正文和开放 metadata。Call 优先使用原批次身份；没有保存批次的历史消息
使用消息身份作为稳定批次键，没有 turn 时使用消息身份作为结构分组键。这些键不声明一次新的执行。
结果必须关联同 Run 中此前保存的 Call。只有已发布文本时保存为字面反馈，不补造执行开始或 Outcome。
保存完整绑定和确定结果的批次拆分为 Call、Start、Outcome 与状态，保留参数、结构化结果、时间及待提交提案。
身份冲突、缺少绑定、未结束结果和正在执行的调用明确拒绝，要求原版本先完成恢复。
委派的父 Call 必须能在所属原生库中唯一定位；文件会话中的跨会话父 Call、歧义关联及缺少独立接受事实的
历史 queued_input_id 不补造关联，保留原数据并报告转换失败。

请求保存为固定 Manifest，不重新运行上下文投影、估算 token 或重算摘要。
completed_at 对应 provider_done_at，缺少完成事实时保持未结算。
旧请求摘要、摘要散列、Run 用量缓存及操作回执不属于当前在线契约，其原文件或数据库保存在维护备份中。
文件后端的旧 Session/Run JSON、完整 context、资源索引、事件与摘要日志、操作回执、事件偏移索引
随目标产物发布移入备份。Harness 与委派保持各自存储责任。

预算转换保留估算值与 estimator，将窗口和输出上限归入 budget，并核对旧派生指标的一致性。
只转换框架拥有的 model_request_started.context_metrics 与 compaction_completed.context_metrics_after；
其他事件载荷、工具参数、提供方原生片段及开放字典不递归转换。

## 用量、任务与配置

有效账单和完整审计分别转换，不重放 reset 或 replace 来重算账单。
原始请求引用指向审计中的 record 事件，Run 原始小计只累计首次报告；修订值继续保留在有效账单中。
重复原始请求身份不能静默覆盖。金额、token、时间、顺序和审计身份保持不变。

任务 description 成为 agent target 的 prompt，workspace、model、reasoning、approval_mode、session_mode
移入 target；执行归属同步迁入 agent target。无插件所有者时 owner_id 为 null，result 为 null，
cancel_requested 为 false。任务、执行、revision、日程、历史链与防重标记保持不变。

提供方配置通过有序结构规则转换 supports_vision、reasoning.default_effort 和 profile.variants。
旧 default_effort 合入 default.effort，明确选择 effort 的 default 模式转为 enabled。
两个旧默认 effort 不一致、混用新旧字段或未知原生字段均拒绝。原生映射和开放内容原样保留，
不推断摘要能力、不刷新认证。与 v0.3.0 保存基线一致的端点更新绑定指纹，已修改实例保留旧基线。
模板文件由模板加载流程管理，不参与离线事务。

## 失败与恢复

严格模式在任一转换失败时停止发布。隔离模式保留失败数据，其他独立单元可以发布。
文件会话按 Session 隔离；成功会话保存为当前原生数据，失败会话保留旧头，catalog 标为不可读。
重试只转换剩余旧会话。文件任务按任务隔离，提供方配置、用量和 SQLite 任务分别按整个文件或数据库隔离。
SQLite Session 的结构整体转换，失败时保留整个源库，不发布混合表结构，也不提供扩大删除范围的操作。

文件会话、文件任务和可删除独立域只有在用户明确确认且重新检查仍失败时才移入备份。
已经修复的数据正常保留或升级，新失败仍需确认。缺少归属头、共享结构错误、未完成事务、锁、权限、
I/O 与源变化不能作为删除依据。删除使用同一恢复清单，不删除其他会话、任务或共享附件。

1. home 必须是已有普通目录，用户负责停止所有写入者。标准 CLI/TUI 使用 `.upgrade/lock` 共享锁，
   维护使用独占锁；旧程序、直接 Store 调用和外部脚本仍受停写前提约束。
2. 未完成的会话提交、任务事务、导入及回收发布要求先由原版本恢复；home 级发布中间态阻止维护。
3. 产物在受限 `.upgrade/<id>/scratch` 生成。只有修改集合进入 `new/`；关闭后的暂存文件直接移交工作区，
   摘要和同步共用一次打开。`--check` 不同步暂存产物、不准备发布、不再次读取源文件。
4. 清单记录相对路径、前后 SHA-256、存在性及文件模式。只复核修改集合；源变化立即停止。
   完整目录删除时摘要覆盖结构和文件内容，只有确认删除才读取其中附件。
5. 清单、产物、原文件和目录同步后写入 `.upgrade/in-progress.json`，此后才修改业务路径。
   每个原文件移到 `before/<序号>`，产物重命名到原位置；删除只保留备份。发布不再次复制产物。
6. 保存 `.upgrade/receipts/<id>.json` 后解除标记。备份和清单保留，工作区必须与业务文件处于同一文件系统。

多文件发布不是 home 级原子事务。标记前失败不改变业务数据；标记后失败保留恢复材料并阻止 Runtime 使用 home。
`--restore` 在写入前核对整个修改集合的原始摘要，备份损坏时停止，不能用业务路径掩盖损坏。
尚未移走的原文件可以留在原位；已移走的原文件从备份复制恢复，重复恢复不消耗备份。
写入清单格式 3，恢复接受格式 1、2、3。恢复只处理未完成的本次发布，不自动降级已经成功升级并继续使用的数据。

## 接口与验证

命令行与 Python 接口默认严格模式，TUI 使用隔离模式。结果状态为 current、upgrade_required、upgraded 或 partial；
failures 和 discarded 分别列出失败、实际删除单元，已发布报告另含备份与清单位置。
进度回调报告当前阶段及已完成单元数，不表示整体百分比。

针对性回归覆盖当前 reader、配置、历史事实转换、原始与有效用量、当前容器跳过、未知输入拒绝、WAL、
失败隔离、确认重查、发布中断、恢复、备份损坏、权限和维护锁。支持范围以这些契约和夹具为准。
