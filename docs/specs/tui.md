# OURO TUI 规格

> 文档类型：现行规格
> 主要实现：`ouro/tui/`、`ouro/local_application.py`、`ouro/application/`

## 目标与边界

OURO 默认以 Textual 全屏 TUI 启动。TUI 是 Application 的本地 Host adapter，负责页面状态、输入映射、
渲染、导航和本地偏好；Session、Run、工具审批、AskUser、子智能体、插件、Provider、MCP、Skills 与恢复规则
仍由 Application/Core 及其端口拥有。

TUI 不得：

- 读取或改写 Session 文件、SQLite 表、插件状态文件或全局配置 JSON；
- 从原始事件 payload 推断 Application 已提供的业务状态；
- 自建 Agent loop、工具执行器、审批状态机、子智能体调度器或 MCP 生命周期；
- 因切换视图、刷新页面或关闭弹层而改变后台 Run 生命周期；
- 将 Textual widget、Message、Screen 或 driver 类型暴露给 Application。

## 组合与生命周期

`ouro` 无子命令时，CLI 解析 `--home`、`--session-backend`、`--system-prompt`、`--session`、
`--approval-mode` 与 `--afk`，再由本地 composition root 创建 `LocalApplication`、`TuiController` 和
`OuroTuiApp`。TUI 只使用 controller 暴露的 DTO、命令与借用的 Application 用例服务。

启动流程必须满足：

1. 解析 OURO home、Session 后端和初始策略；
2. 启动 `LocalApplication`，完成 Provider、插件、MCP、Skills 与 Agent catalog 装配；
3. 读取 TUI 偏好和最近工作区；
4. 加载指定 Session，或显示新 Session 欢迎页；
5. 建立可见 Session 的正文观察与所属主会话的 Agent 状态观察；
6. 退出时依次停止观察、保存允许持久化的 UI 状态并关闭 Application 资源。

启动诊断属于系统状态，不得用假 Session 消息写入对话。单个 optional MCP 或插件贡献失败可以显示 degraded
状态；无法建立权威 Application 边界的错误必须阻止对应操作。

## 页面与状态所有权

主页面由以下稳定区域组成：

- 会话标题与工作区头部：按扣除内边距后的内容区宽度排成一行，工作区右对齐；空间不足时优先省略标题，再截断工作区；
- 欢迎页或会话时间线；
- 运行活动、上下文和子智能体导航投影；
- composer、排队输入提示和交互面板；
- command popup、选择器、配置页和帮助页等临时 surface。

会话页按命令候选及交互面板、输入框、排队输入提示、底部状态栏排列；排队输入提示位于输入框下方。
底部会话状态的 `brand_mark` 在就绪时使用主题 `accent`，失败时使用 `failure`，其他静态状态使用 `text_primary`；
运行中的 spinner 保持主题色。状态文字统一使用 `text_primary` 和常规字重。
提交准备不禁用或移走输入焦点，用户可继续编辑下一条草稿；首次提交尚未绑定 Session 时只暂停再次发送，
会话绑定后恢复发送能力。只读会话与审批、问答等明确的交互约束单独决定输入是否可用。

TUI 状态分为三类：

| 状态 | 所有者 | 示例 |
|---|---|---|
| 业务事实 | Application/SessionStore | Session、Run、消息、工具批次、审批、交互、Delegation |
| Host 控制状态 | TUI controller | controlled Session、当前模型选择、待提交输入 |
| 纯呈现状态 | Widget/App | visible Session、滚动锚点、选中项、弹层、展开状态、输入光标 |

`controlled Session` 是允许提交输入和控制 Run 的主会话；`visible Session` 是时间线当前展示的会话。
查看 child Session 时两者可以不同。只切换 visible Session 不得重启、暂停、接管或取消任何 Run。

## 欢迎页样式

欢迎页样式与界面配色为并行配置，保存于 `<OURO_HOME>/config/tui.json`：

| 字段 | 默认值 | 约束 |
|---|---|---|
| `welcome_style` | `basic` | 小写字母、数字及连字符组成的样式包身份；允许包或依赖暂不可用 |

`Ctrl+P → Theme` 使用标准筛选菜单，依次展示 `Welcome style` 与 `Theme color` 两个分组。
欢迎页样式直接以单行名称展示，不显示描述，菜单只列出当前环境可用的主题。
TUI 只负责主题选择和应用，不提供主题内部设置入口或设置传递管线；动画逻辑由主题实现。
主题色保留色阶预览，`←/→` 仅在主题色行调整饱和度，`Enter` 应用当前选项。
默认 Original 使用中性灰文字与结构色。其他内置配色仅为文字的不可用、辅助、常规、
强调和高亮五个语义层级加入克制的主题色倾向，保持亮度梯度；背景、边框、轨道、状态色和语法色不随主题色染色。
各主题独立声明文字色值，构造与注册时直接使用声明值。

选择必须先成功持久化再应用。存储失败时保持当前组件与偏好并显示错误。连续选择和关闭菜单不取消
App 持有的写入/挂载事务；事务与其他 TUI 偏好更新共用锁。切换包不重建 composer 或清除草稿。

基础安装包含完整 TUI 和静态 OURO 字标 `basic`，不包含可选主题及点阵引擎源码。
`ouro-agent[themes]` 整体安装兼容版本的 `ouro-tui-themes` 扩展发行包，其中包含 `event-horizon`、
`electron-bloom`、`interference`、`clifford-torus`、`quasicrystal` 风格及它们共用的点阵引擎，
依赖 `numpy>=2.3.3,<3`。引擎和风格在模块职责上分离，在安装和发布上属于同一个扩展。
主题身份、名称和说明不依赖渲染实现的导入。框架只内置 basic，由 App 组装已安装的官方包和注入包。

每个 App 启动时检查官方扩展满足核心声明的最低主题版本后加载注册信息，再执行主题的依赖检查；同一检查函数
只执行一次。可用性取决于扩展和兼容依赖能否成功加载，不依赖安装时是否使用 extra。
安装或移除扩展及依赖后通过重启重新检测。
已保存主题未注册、扩展未安装或依赖不可用时，显示 `basic` 并提示原因，持久化的 `welcome_style`
保持原值；修改配色等其他偏好不得覆盖该选择。恢复扩展后按保存的选择显示主题。
新安装及无偏好配置时均默认使用 `basic`，安装扩展不会自动切换主题。格式非法的 ID 为配置错误；
格式合法但未找到的已保存 ID 进入回退，新提交的未知或不可用 ID 被拒绝。

依赖未安装属于正常可选状态，不阻止启动；依赖版本不兼容或二进制加载失败提供具体诊断。
可选主题的渲染实现只在选用时导入；主题实现的编程错误不得伪装为依赖缺失。

`WelcomeStyle` 以身份、名称、说明和工厂组成通用包契约；工厂提供新的 `WelcomePage` 全屏根组件。
可选 `check_requirements` 回调返回不可用原因或 `None`，未设置时视为无可选依赖要求。
`run_tui(welcome_styles=...)` 与 `OuroTuiApp(welcome_styles=...)` 支持显式注入自定义包，目录按 App 隔离，
重复 ID 被拒绝。框架只管理注册、选择、应用和组件生命周期，支持任意 Textual 渲染或组件组合，
不规定图形原语或动画算法。

样式包控制整个欢迎页的背景、装饰、组件组合、信息布局与响应式规则。包通过 `place_input(viewport, measure)`
返回公共输入层的位置与尺寸；Host 在其上层呈现持久输入组件。命令弹窗紧贴输入区上方并按上方空间限制高度，
仅上方不足最小菜单高度且下方空间更大时向下展开。菜单覆盖页面，不移动输入区。
System、Usage、Tips、Version 是可选的复用组件，包通过 `set_system_status` 接收 Host 的不可变信息快照。
Tips 标题使用主题 `accent`，前缀使用主题 `selected_choice_marker`（默认 `●`），切换主题时同步更新。
通用 Host 不限定居中布局、最大页宽、艺术区域或点阵形式。局部输入样式由当前包的 Host 类限定，离开欢迎页即撤销。

页面通过只读 `tui_theme` 获取当前不可变 `TuiTheme`，颜色已包含用户选择的饱和度。
`refresh_theme()` 在初次挂载、替换页面后以及配色变化时调用，包括隐藏的已挂载页面；TCSS 的 `$ouro-*`
变量自动更新。包自行决定是否联动配色，刷新不重建页面或改变激活状态、输入与焦点。
Host 通过 `set_active(bool)` 通知前台可见性，页面自行管理动画与其他资源，并在卸载时释放。

内置点阵页在组件存续期间共用一个帧 worker，数值引擎按采样尺寸持有。同尺寸的在途帧因主题刷新或暂停失效时，
保留数值引擎，只使终端行比较基线失效，下一次有效帧完整重绘；重复尺寸通知不重建引擎。
后台帧计算在实际尺寸变化时重建匹配引擎，过期尺寸或已卸载组件的计算结果不得发布到终端。

扩展代码及生命周期说明见
[欢迎页样式包开发](../development/welcome-styles.md)。

## 语义色

语义色独立于主题 accent 与文字亮度层级，各类只定义一个固定色值，不设置高亮、低亮变体。
内置主题共用以下语义色，主题切换和饱和度调整均保持这些值；Host 可显式覆盖各字段。

| Token | 默认值 | 语义职责 |
|---|---|---|
| `running` | `#6fa8a0` | 正在进行中的状态，如运行中的会话节点 |
| `success` | `#86ad7a` | 正向结果、允许与接受，以及差异中的新增内容 |
| `warning` | `#b8a06a` | 需要关注但尚未失败，如待审批、容量预警和插件待处理项 |
| `danger` | `#c18d6c` | 将要执行的风险或否定操作，如删除、拒绝与自动审批 |
| `failure` | `#c17b7b` | 已发生的错误或失败结果，以及差异中的删除内容 |

错误通知、错误消息和失败状态使用 `failure`，警告通知使用 `warning`。工具行悬停只改变普通文本，
保留语义色的固定前景。就绪标记、spinner、选择焦点仍按交互职责使用主题 accent。

## 会话与工作区

新会话通常在第一条普通输入提交时创建；附件导入准备草稿资源空间，页面仍停留在欢迎页，
发送后才展示会话时间线。欢迎页可通过 `/workspace [path]` 选择工作区；Session 创建后工作区固定，
变更工作区必须先进入新会话。`/workspace clear` 只清理最近工作区记录。

页面状态与正文是否已生成分离。提交后进入会话页，同一会话的空快照、排版等待和状态刷新保持该页面；
已受理但尚未产生正式消息的输入也属于会话页。显式打开会话时，根据正文、待处理输入和活动 Run 选择初始布局；
没有这些内容的空闲会话可显示欢迎布局。新建会话返回主页；提交未获受理时仅恢复原页面及草稿，不覆盖后续导航。

会话入口支持：

- `/new` 或 `Ctrl+N`：回到新会话欢迎页；
- `/sessions`、`/resume` 或 `Ctrl+O`：浏览并打开 durable Session；
- `/fork [full|#N]` 或 `/branch`：在合法消息边界创建独立分支；
- `/clear`：只清空当前可见时间线，不删除 canonical 数据；
- `/navigate [target]`：在顶部、底部和用户消息之间导航。

打开、重命名和归档会话菜单通过 `Tab` 循环切换 `USER`、`TASK`、`SUBAGENT`、`ARCHIVED` 会话域，允许域为空。
前三个域分别展示未归档的用户主会话、任务主会话和所有子智能体会话；子智能体按 `session_kind` 汇总，
不受主会话、命名空间或派遣层级限制。`ARCHIVED` 汇总所有已归档会话，列表内部不按归档状态分组。
归档菜单在前三个域执行归档，在 `ARCHIVED` 域执行取消归档；重命名适用于所有域。
删除菜单固定展示 `ARCHIVED` 域，沿用多选与永久删除确认，并在确认时重新检查归档状态。
未归档的会话即使存在目录或内容错误，也不进入删除列表。

Actions 的 Settings 分组提供 `Session grouping`，可选择 `By date`（默认）或 `By workspace`，持久化到
TUI 偏好 `session_grouping`。所有会话列表共用同一分组投影：日期按本地最近活动时间分组，工作空间按完整路径
分组，未指定工作空间使用 `No workspace`。分组按目录中首次出现的顺序排列，组内保留目录顺序。
各页复用筛选、左右键分组导航、当前会话标记及健康状态样式，不扫描 canonical Session。
页标题显示当前会话域，Tab 提示统一为 `Tab switch sessions`；行内重命名期间保留编辑上下文，不切换域。
打开子智能体会话复用现有只读视图及主会话控制边界。

会话运行或等待审批、输入时仍可返回欢迎页、浏览和切换会话，包括从只读 child 视图离开。
导航只切换页面及其订阅，不取消后台 Run。后台事件、完成结果和排队输入不得覆盖当前页面、草稿或交互面板；
重新打开会话时复用标准 snapshot/live 衔接，恢复流式内容及待处理交互。

新会话、重新进入、root/child 和外部进程会话统一调用 `RuntimeSupervisor.observe_session`。
Application 拥有一致快照、消息点查、history_epoch、分页追赶与已应用游标；TUI 在内容批次应用成功后确认，
读取或排版排队不推进游标。历史代次变化交付新快照，当前代次中缺失消息报告读取错误。
正文不通过本地 event sink 或 RunResult 回填，执行结果只用于命令反馈和非正文状态。

会话选择先准备 Application 观察与正文投影，再检查目标版本并提交到共享视图。失效准备结果不能改变
controlled Session、草稿或可见内容，未接管的订阅必须关闭。快速 child 导航合并待切换目标。
视图提交与内容应用共享顺序边界。快照中的稳定正文和流式尾部先准备后安装，初始历史排版独立推进；
运行中已可见的内容转入历史时，呈现 worker 异步等待替代内容就绪，再释放活动表面。

Session 历史读取与模型执行配置解耦。模型路由失效、Provider 不可用或 reasoning 无法解析，不得阻止打开和
观察有效会话。上下文用量优先保留持久化事实，当前模型可解析时投影其额度，否则保留记录中的额度；无法解析
的 reasoning 不展示状态指示。加载不自动替换持久化模型，用户可重新选择有效路由；模型切换只验证目标路由，
实际请求仍执行模型、认证与能力校验。会话数据缺失、损坏或版本不受支持仍按持久化契约报错。

## 输入与运行控制

计划确认使用公开的 `ouro.sdk.plugins.interactions` DTO。TUI 为有效的 `plan_confirmation` 请求提供计划预览、
方案选择及接受／修改／拒绝动作，适用于 builtin 和 user 插件；未知或无效结构使用通用输入。界面只提交用户
选择，计划校验、恢复、权限和 Session 控制仍由 Application 与请求所属插件处理。

会话正文、思考正文、流式文本与多行输入按终端 cell 宽度软换行。可用宽度由组件扣除边框、内边距、
滚动条及光标预留后提供。中文等非空白分词文本使用 Unicode 断行边界，英文单词优先保持完整，
超长单位按完整字形折行。纯文本中的显式换行保留；软换行不向输入或 canonical 消息插入字符。
Markdown 遵循自身的段落与硬换行语义，保留列表缩进、行内样式及链接，代码块沿用 Rich Syntax 的代码折行策略。

编辑器的显示行、光标、选区和鼠标定位共用文档断行偏移。窗口尺寸变化重建显示几何；文本编辑只重排
受影响的源行并更新后续行的位置索引。附件身份、撤销重做及提交文本继续由原有文档和编辑流程拥有。

composer 支持多行编辑、历史、命令补全和运行中排队：

- `Enter` 提交通常输入；
- `Ctrl+Enter` 插入换行；
- `Ctrl+G` 将运行中输入作为 steer 提交；
- 普通运行中提交按配置形成 follow-up；
- `/unqueue` 将选中的未消费输入取回 composer；
- `/undo` 撤销最近直接用户输入，优先选择待消费输入，并恢复完整编辑草稿；
- `/continue` 继续合法检查点，撤销后从当前历史创建新 Run；
- `Ctrl+C` 优先复制选区，无选区时请求中止 active Run；`/abort` 始终请求中止；
- `Ctrl+Q` 或 `/quit` 关闭 TUI。

直接用户输入必须保持 `role=user`、`scaffold=false` 和用户 provenance。命令只负责选择 Application 动作；
有效命令不得作为普通用户消息误提交；无法匹配的命令或固定参数作为原始正文发送。
排队输入使用 Application 的 durable queue、消费模式和去重语义。
Application 提供待处理输入及其正在等待的活动 Run，TUI 据此区分发送准备和运行中追加。
空闲会话提交期间保持输入焦点，以状态栏表达等待调度；消息在 canonical 消费提交后进入正文。
只有等待活动 Run 消费的后续输入或 steer 才展开输入框下方的队列提示。全部未消费输入仍可通过 `/unqueue` 取回。
这些呈现规则统一用于主页提交、空会话和已有历史的会话；Application 不持有页面、焦点或组件布局状态。

队列提示和 `/unqueue` 候选共用同一投影。TUI 将实时事件、提交结果和撤回操作触发的队列读取与发布串行化，
不以请求发起顺序推断后台线程实际取得快照的顺序；读取仍离开事件循环，消息泵保持可交互。
刷新绑定可见视图及其投影实例，切换会话或安装替换快照使在途结果和等待中的旧刷新失效。
读取失败保留已显示的队列并向调用方传播错误；失败或取消均释放后续刷新。

## Slash 命令

参数菜单区分固定选项和自由输入的建议项。输入非空且匹配结果包含建议项时，不自动选中候选；
`Enter` 提交输入原文，`↑/↓` 显式选择后可提交候选，`→` 接受行内补全。继续编辑会清除建议项的选择。
空输入和仅含固定选项的菜单沿用默认选择行为。工作区历史路径属于建议项，`clear` 属于固定选项。

菜单保留完整候选集，按可见行绘制。上下导航复用当前候选及输入提示，不重新构造命令目录、排序模型或投影历史消息；
补全仅在命令名称及过滤文本与菜单快照一致时复用，输入修改仍立即更新提示。

命令前缀或非空参数没有候选时隐藏菜单，不显示无匹配占位。回车仅在输入匹配命令及其参数契约时执行命令；
否则保留完整输入、已有附件及提交模式，按普通消息发送。固定选项不接受未声明的后续文字；
工作区路径与插件声明的自由参数不要求存在菜单候选，仍由对应命令校验和执行。

内置命令目录由 `ouro/tui/commands.py` 定义。当前命令为：

| 命令 | 行为 |
|---|---|
| `/new` | 新会话 |
| `/workspace [clear\|path]` | 新会话工作区与最近记录 |
| `/sessions`、`/resume` | 会话选择 |
| `/actions`、`/menu` | Action 菜单 |
| `/fork [full\|#N]`、`/branch` | 会话分支 |
| `/model <provider/endpoint>` | 会话模型路由 |
| `/approval [inherit\|auto\|approval\|deny\|afk]` | 会话审批/无人值守预设 |
| `/thinking [...]`、`/reasoning` | 会话思考意图 |
| `/thoughts [expand\|collapse]` | reasoning 显示偏好 |
| `/compact` | 手动上下文压缩 |
| `/summary` | 显示当前可见会话最新一次压缩摘要 |
| `@skill` | 内联多选技能引用，作为独立元素加入草稿 |
| `@file` | 内联多选原路径文件引用 |
| `/unqueue` | 取回排队输入 |
| `/undo` | 撤销并恢复最近用户输入 |
| `/continue` | 继续当前会话 |
| `/clear` | 清空可见时间线 |
| `/navigate` | 对话导航 |
| `/abort` | 中止 active Run |
| `/help` | 快捷键与命令帮助 |
| `/quit`、`/exit` | 退出 |

`/summary` 通过 Application 查询持久化摘要，仅显示持久化顺序中的最后一条，保留完整正文；最新结果与当前生效状态独立。
结果沿用命令输出的低亮消息容器，空结果沿用单行 notice。
命令不接受参数，输出标题和提示不展示会话 ID；未打开会话时提示先打开会话。显示生成时间、触发方式和生效标记，
不重新生成摘要、不切换受控或可见会话、不写入模型对话历史。查询期间若切换了可见会话，结果不追加到新会话视图。

插件 command 与内置目录合并时使用稳定 canonical identity。内置命令优先；插件 local name 只有在当前目录唯一
时才可作为短别名。插件返回的 Session input、control transition 和输出继续通过 Plugin/Application 契约执行。
多行命令结果（含结构化数据的 JSON 展示）与脚手架共用消息容器、低亮正文和低亮左边栏，支持悬停及右键复制原文；
保留换行、缩进和字面 Markdown 标记，不额外添加时间戳。命令结果保持独立类型，不受脚手架显示开关影响，
不参与用户消息导航和分叉编号；单行提示标记保持现有样式。
命令提交成功后，TUI 立即调度会话控制状态刷新，与后续输入消费及模型执行独立进行。模式标签读取 Application
提供的已提交状态，不解析命令参数或插件私有状态，也不等待工具调用或 Run 结束。

## 快捷键

快捷键按输入编辑、会话操作和导航分工。所有多行输入使用 `Ctrl+Enter` 换行；
composer 使用 `Enter` 发送或排队，菜单使用 `Enter` 确认，内联字段使用 `Enter` 保存。
单行字段不接受换行组合，也不将其作为确认。

| 快捷键 | 行为 |
|---|---|
| `Enter` | 发送、排队或确认当前操作 |
| `Ctrl+Enter` | 多行输入换行，包括 composer、任务 Instruction 和提示词 |
| `Ctrl+G` | 提交输入以引导当前运行 |
| `Ctrl+N` | 新会话 |
| `Ctrl+O` | 会话选择 |
| `Ctrl+P` | Actions |
| `Ctrl+S` | 技能管理 |
| `Ctrl+T` | 任务管理 |
| `Alt+P` | 插件管理 |
| `Alt+T` | 循环思考设置 |
| `Alt+A` | 循环审批设置 |
| `Alt+Home / Alt+End` | 对话顶部 / 底部 |
| `Alt+PageUp / Alt+PageDown` | 上一 / 下一条用户消息；最后一条之后跳转底部 |
| `Alt+← / Alt+→` | 按主会话、首个子智能体到最后子智能体的显示顺序切换 |
| `Alt+↑ / Alt+↓` | 主会话 / 最后子智能体 |
| `Ctrl+C` | 有选区时复制；无选区时中止 active Run |
| `F1` | 帮助 |
| `Ctrl+Q` | 退出 |

智能体导航不循环：主会话向左、最后子智能体向右均保持原位；没有子智能体时保持主会话。
最后子智能体按导航栏的分组显示顺序确定。消息导航在对话顶部向前、底部向后均保持原位。
行动、会话、任务、技能、插件和帮助使用同一菜单导航机制。快捷键在当前菜单窗口内直接切换页面，
不叠加弹窗；重复当前菜单的快捷键保持页面及筛选状态，`Esc` 返回保留的父页或关闭菜单。
帮助条目用于说明操作，选中条目不执行命令；切换菜单后，选择操作由当前页面的回调处理。
瞬时确认框和编辑子屏保留自己的交互边界，不被全局菜单快捷键替换。

弹出菜单居中显示，遮罩与菜单面板统一使用活动主题的 `background` 不透明背景，与终端主页面同色。
菜单面板、标题、说明、筛选框、选项列表和提示栏均无边框；标题以主题 accent 和粗体表达层级，
当前选项通过前景色与高亮背景表达焦点。主题色预览作用于标题和选项高亮前景。
子屏打开期间，父菜单面板隐藏、父屏背景透明；返回时恢复父菜单及其筛选、焦点和滚动位置。

composer 与菜单筛选框使用常规文本编辑组合：`Ctrl+A` 全选，`Ctrl+←/→` 按词移动，
`Home/End` 行首行尾，`Ctrl+Home/End` 文首文尾，`Shift` 配合方向键或 `Home/End` 扩展选区，
`Ctrl+Shift+←/→` 按词扩展选区，`Ctrl+X/C/V` 剪切、复制、粘贴。
`Backspace/Delete` 删除字符，`Ctrl+Backspace` 或 `Ctrl+W` 删除前一个词，`Ctrl+U/K` 删除至行首或行尾。
composer 支持 `Ctrl+Z/Y` 撤销和重做。空 composer 的 `↑/↓` 浏览输入历史；正在编辑的文本优先移动光标，
未改动的单行历史项可继续浏览。命令候选可见时，`↑/↓` 选择候选。

菜单使用 `↑/↓` 选择、`←/→` 切换分组，内联编辑时方向键移动光标；`Space` 切换多选项，
`Tab` 向前循环切换当前菜单域或焦点，`Esc` 取消编辑或返回。问答选择保留数字 `1–5`，
滚动预览保留 `PageUp/PageDown`。

终端负责将按键编码为输入事件，OURO 负责将可辨识事件映射为一致的动作。
`Ctrl+Enter` 同时接受增强键盘协议事件和传统终端的 LF 编码；Textual 将 LF 命名为 `ctrl+j`，
该事件只执行换行。终端拦截的组合键或与普通键编码相同的修饰键无法由应用可靠还原。
Windows driver 只保留 Alt 修饰信息的现有适配，不猜测 Enter 或 Backspace 的修饰键状态。

Windows 输出适配器在 Textual 的 flush 边界合并画面片段，复用框架的输出线程。
控制台输出通过一次 `WriteConsoleW` 提交完整 UTF-16 帧及末尾的输入光标恢复指令，
避免分段写入之间暴露绘图光标；重定向输出沿用原始文本流。独立控制指令在下一事件循环轮次排出，关闭驱动时排空待写数据。
驱动启动时查询终端的同步输出能力（DEC 2026），由 Textual 处理响应并在支持时封装完整画面更新。
同步输出控制终端画面的呈现时机，与原生写入边界是独立的约束；不支持该能力时仍保持完整帧写入。
输入法预编辑和候选窗由终端管理，TUI 不模拟输入法组合状态，也不按语言改变动画行为。

## 模型、上下文与设置

`/model` 与模型选择器使用完整 `provider/endpoint` 路由。已有 Session 的切换只影响下一次模型请求；已发出的
请求继续使用原路由。`/thinking` 写入供应商中立意图，Endpoint 能力不支持时在网络调用前失败。

`/compact` 调用现有 compaction 用例；TUI 不自行选取消息或生成摘要。上下文详情读取最近一次真实 Provider
请求快照，不重新运行 Context Provider，也不从消息历史猜测请求内容。

Actions/设置界面当前覆盖主题、reasoning 展开、输入草稿、排队输入、压缩、工具执行、Agent definition 与派遣
策略、Provider/Endpoint、MCP、插件、Skills 及来源。编辑使用 Configuration/Application 命令的 revision 与
校验规则；UI 不直接合并共享配置。

插件 **Edit settings** 从 Application 取得完整 Schema、凭据槽和固定编辑基线。字符串与数值使用行内输入，
布尔、枚举与常量复用选择菜单，复杂结构使用带 Schema 示例占位符的 JSON 输入；整份 JSON 编辑保留原生
表单未呈现的字段。凭据单独编辑引用。校验失败或冲突保留草稿，刷新须确认丢弃；只有显式 Apply 才提交。
控件能力不限制配置表达能力，完整约束和生效语义见[插件配置规格](plugin-configuration.md)。

端点列表在当前 Session 或待建会话选中的完整 `provider/endpoint` 路由左侧显示主题选定标记，与菜单焦点独立。
全局默认端点通过右侧 `default` 标签展示，两者可以同时出现；修改默认配置不覆盖已有会话选择。
列表刷新时同步更新标记与标签；当前选择无法解析时不显示选定标记，仍允许浏览端点菜单。
添加自定义供应商时，协议由上级自定义连接类型确定，表单不提供协议配置项；已有供应商及预设的协议信息只读。
新增 Endpoint 表单的 context window 默认为 `1000000`。端点与摘要设置中的 `Max output tokens` 为可选项，默认值为空，列表标为 `Optional`，输入框不显示占位提示；清空有限值表示不配置输出上限。编辑已有 Endpoint 时
显示并保留其已配置额度。

欢迎页 USAGE 区显示最近日期的用量图、请求数、输入/输出 token 和缓存命中率；日期悬停展示对应日数据。
进入欢迎页时先显示最近一次有效数据，首帧绘制后在后台读取最新系统状态与用量，不阻塞页面显示和输入。
运行完成只在欢迎页可见时刷新全局用量；完整状态与用量刷新共用串行读取，并发通知合并，完整状态读取优先，
读取期间的新通知触发后续读取。未变化的数据不更新控件，成功刷新不显示提示；读取失败保留有效数据并显示警告。
离开页面前发起的读取不得覆盖新页面状态；完整状态读取期间若工作区、模型或服务状态发生变化，重新读取后再更新。
主页不展示费用、计费模式或 priced/unpriced 信息，账本查询契约见[用量与计费规格](usage-and-billing.md)。

## Provider 认证管理

Provider 子菜单的 `Authentication` 入口通过 `TuiController.provider_auth()` 借用当前 LocalApplication 的同一 ProviderAuthService；TUI 不创建认证服务、不读取凭据文件，也不导入 auth 的驱动或存储实现。

- 状态和共享引用直接来自 Application DTO，手动刷新及返回子页面时重新查询。缺失或损坏凭据不阻止完整 TUI 启动；损坏状态显示安全错误码。static 不显示登录方法，注销项禁用。
- 登录列表使用稳定 method id、label 和 description；浏览器回调和设备码页面由 challenge.kind 决定，不按厂商分支。URL、设备码、有效期和说明仅在当前登录页展示，不写入会话、通知或本地偏好。
- 只有用户选择 `Open browser` 才打开浏览器；复制 URL 同样是显式动作。浏览器启动失败仍保留手动打开和取消入口。成功后不自动发送模型请求。
- 登录页只拥有一个等待任务；Application 拥有授权、条件提交与终态。Esc 或取消动作取消当前操作并等待清理，随后显示实际终态；若保存已先行，显示成功。页面卸载或 Host 退出同样收尾，不能留下迟到保存。临时筛选条件不会隐藏终态。
- 注销先展示当前共享 Provider 引用并使用现有确认页。`Manage local credentials` 展示安全摘要，允许清理 Provider 删除后留下的凭据；取消确认没有副作用。清理保留 Application 定义的 logged_out 记录。
- 受管理 Provider 的配置页显示认证驱动并隐藏 API Key/env 输入；创建时传递模板认证默认值，普通编辑保留现有认证绑定，不隐式切换账户或认证方式。
- Provider 配置页的 Request headers 接受 literal/env/context 请求头声明 JSON；空白保留已有配置，`{}` 清空，完整对象整组替换。页面显示当前条目数，编辑框不预填脱敏值；保存通过 ConfigurationFacade 原子校验并持久化，格式及字段错误阻止保存。

## 工具审批与 AskUser

审批、AskUser 和 resumable plugin tool 使用 composer 上方的专用交互 surface。面板必须显示明确的调用身份、
问题/选项或批准范围，并把结果路由到精确 Session/Run/ToolCall/request identity。

- approval 与 user input 是不同状态，不得共用含糊布尔值；
- AskUser 支持稳定问题 id、选项说明、多选和 Host 提供的自由输入；
- `/abort` 与退出在交互面板打开时仍必须可达；
- AFK resolution 使用 host-policy provenance，不渲染为用户回答；
- 交互完成前不得提前显示成功 ToolResult。

审批预检可能先发布请求、再保存可恢复批次。面板已经允许用户决定时，Controller 必须保留该决定，
通过 Supervisor 的持久化 Run 状态订阅等待 `waiting_approval` 检查点，再向捕获的目标 Session
提交一次；终态与取消必须结束等待，不使用固定延迟、轮询或重复提交来跨越此边界。

Plan 的退出确认可使用专用计划正文视图，但提交仍走通用 resumable tool/Session control 契约。

## 子智能体视图

SpawnAgent 工具记录携带类型化导航 identity。用户可从历史或 live 工具行打开 child Session，并通过键盘或
Agent tree 在主会话和多个 child 之间切换。

child surface 为只读：禁止普通输入、steer、follow-up、abort、fork、模型修改、审批策略修改和 destructive
Session 操作。root interaction inbox 中的 child 审批与 AskUser 仍由 controlled root 的交互面板处理；只读限制
不等于丢弃 HITL。不可见 child 继续运行，重新打开时使用 snapshot/high-water/cursor 衔接全部缺失事件。

## 渲染与性能

时间线分别呈现用户文本、assistant Markdown、reasoning、工具活动、压缩和 Run 状态。Provider delta 是输入事实，
不是 UI 重绘单位：TUI 按帧合并连续增量，保持到达顺序，并在完成边界冻结稳定块。

稳定内容集中在单个历史行缓冲组件中，其后仅保留当前模型轮次与工具批次的活动组件。会话容器使用标准纵向布局，
根据各组件当前内容高度确定位置，保证工具活动期间前序稳定内容持续可见。布局遍历规模由存活组件数量决定，
不随历史消息条数增长；历史正文复用已渲染的 Strip。

历史区和 assistant 活动区由 ConversationView 持续持有。模型轮次结束或切换会话时，活动区清空内容、身份及计时状态，
收到新内容后显示；工具活动行按批次创建，位于历史区与 assistant 活动区之间。组件生命周期和页面布局均由 TUI 管理。
正文、思考及工具批次转入历史时，原表面保持可见，直到历史完成对应排版；排版失败保留原内容并报告错误。
该交接只约束当前呈现 worker 的顺序，不阻塞 App 消息泵、执行者或其他观察者。

首次进入通过 Application 读取近期 200 条消息的完整帧窗口，首个正文画面直接定位到该窗口末尾。
向上滚动到已加载历史的顶部时自动补入一页；
滚轮、翻页和相邻用户消息导航共用同一分页请求，在途请求合并，打开会话或恢复滚动位置不自动补齐全部历史。
会话区的 `PgUp` / `PgDn` 按可见区域高度直接翻页，不播放滚动动画。
前缀共用历史渲染 worker，只排版新条目和接缝处的首个旧条目，保留已有内容、点击目标和滚动锚点。
`/navigate` 的编号、顶部跳转及 `/fork` 候选需要完整用户消息序列时，按需补齐历史后解析；加载期间不显示窗口内
临时编号。切换会话或历史代次改变后，迟到页不得写入当前视图。Run 终态摘要只出现于该 Run 的最后一条消息后。
补页保持原有可见内容的位置；跳到底部会取消待执行的顶部或编号定位，并停止继续补页。
快照重置使旧补页请求失效，即使仍在同一会话，旧请求也不能继续加载或执行跳转。
补页失败保留当前内容并显示诊断，继续向上滚动可重试，不自动循环重试。

历史组件先接管不可变条目；需要后台排版的批次分块准备临时结果，整批就绪后一次提交内容与高度。
历史加载不按排版进度向用户回放旧消息。冷加载、增量、宽度与主题变化共用一个渲染 worker；
迟到结果必须匹配内容版本、条目、宽度和主题，不能写入已切换的视图。
取消或切换不补做旧目标剩余排版。缓存保留已发布的兼容内容，重进后只准备缺失部分，再一次并入显示。
进入执行中的 Session 时，即使任务输入因 scaffold 规则隐藏，也必须呈现工具前已产生的 assistant 内容。
切换 Session 时，缓存历史与其保存的滚动位置共同恢复；首次可见帧不得混用上一 Session 的滚动位置。
最多保留三个非当前会话的历史缓存，窗口起点随缓存保留；同代次新消息不改变已有起点，代次变化使缓存失效。
重进读取近期窗口并按 canonical 消息坐标复用稳定前缀；离开期间超过窗口的新增内容通过现有分页接口补齐。
缓存起点、手动展开选择及滚动位置保持不变。主页隐藏造成的临时零宽度不丢弃缓存，实际宽度确定后才判断布局兼容。

思考、工具调用（含子智能体）、压缩和 Run 的耗时统一通过 TUI 的 `format_duration` 呈现，实时与历史复用同一规则。
不足一秒显示整数毫秒；其余按天、时、分、秒进位，使用 `d/h/m/s`，秒保留一位小数。
省略前导零单位，从最高有效单位连续显示至秒，例如 `1h 0m 00.0s`、`1d 2h 3m 04.5s`；
包含分钟时秒补齐两位整数。按显示精度舍入后再进位，负耗时按零呈现，工具行继续隐藏舍入后为零的耗时。

运行中的执行轨迹始终可见。运行结束后，以末尾实际文本输出判定是否存在最终回复，不判断语义完整性，
也不要求 Run 成功；以工具或仅思考结束的运行不能折叠。可折叠范围为最终回复之前的工具交互及中间输出，
最终回复的全部 Markdown 块和同轮思考保留，思考正文继续遵循独立的展开设置。没有前序轨迹时不提供折叠入口。
鼠标悬停运行下方的模型摘要时，条目高亮，品牌标记替换为当前状态对应的 `+` / `-`，
末尾以主题 section 连接符附加 `show trace` / `hide trace`；点击切换该运行的轨迹。悬停说明不增加条目高度。
首次加载不排版折叠轨迹。首次展开在后台准备缺少的内容，准备期间保留原画面，输入和滚动继续响应；
后续切换复用已渲染内容。每次原子提交可见行与高度，在用户未主动滚动时保持点击条目的视口位置。
思考正文使用同样的准备／发布边界，流式输出转历史、再次展开及标签悬停复用兼容的正文布局；只在内容、宽度或主题改变时重排。
正文行几何与终端对象分离：仅视口内的纯文本行创建 Strip，选择复制读取全部已展开文本，首次展开使用完整内容和准确高度。
Actions → Settings → `Collapse traces` 提供 `On`（默认）和 `Off`，持久化为 `config/tui.json` 中的
`collapse_traces`。设置应用于尚未手动选择的已结束运行和后续运行；手动选择随会话历史缓存保存，
不写入 canonical 会话。实时、重载、分页及缓存恢复共用同一规则，覆盖主会话、子会话与任务会话。

强制约束：

- 事件 mailbox 有界；落后时回读持久化事实，不无限扩张内存队列；
- 文本分片以线性累积结构归约，避免每个 delta 复制完整前缀；
- 相同状态不重复构造 Rich 内容或触发 Textual layout；
- 用户离开底部后，流式事件不得抢回滚动位置；返回底部后恢复跟随；
- 历史只读 Markdown 不创建无期限存活的流任务；
- 文件 I/O、SQLite 查询、长历史投影和重 CPU 渲染准备不得长期占用 UI loop；
- 最近会话缓存、活动尾部、工具摘要和可见控件数量保持显式上界。

更细的流式、工具边界和响应性约束见[性能热路径规格](performance.md)。

### 事件与呈现边界

Host event sink 先注册完整 mailbox 再创建消费任务，任务直接持有所属 mailbox；该顺序兼容 Textual 的 eager
task factory。超时、失败和有界队列溢出按 sink 独立隔离，不能反向阻塞 durable event 或其他 Session。
Host 可用无 I/O 的同步 filter 在入队前选择事件，拒绝投递不影响持久化或其他消费者；filter 失败隔离到所属 sink。
TUI sink 只接收子会话控制候选事件；子会话归属在线程中确认，消费时重新校验页面选择。
子会话控制事件包括 `run_status_changed`。工具预检可能先发布审批/输入请求，再保存批次检查点；根界面必须在
后续状态事件到达时重新查询权威交互，避免首次查询为空后永久漏显审批。此处不转发子会话高频正文流，也不增加轮询。
无关后台文本、reasoning 和工具流不占用 TUI sink mailbox；欢迎页没有控制会话时不接收会话事件。
ready message 只启动一个呈现 worker，不在 App 消息泵中等待解析、排版或查询，以保持按键分发可用。
正文观察一次只交付一个待确认批次，帧 worker 从中取走有界前缀，按 sequence 更新投影并合并连续文本增量；
工具与交互面板按规范快照刷新。批次全部应用后才能确认并读取下一批，慢消费者在 Application 中分页追赶。
帧消费共享顺序锁，后续内容不能越过仍在应用或交接显示所有权的前缀；冷加载快照的确认不等待历史排版。
工具 delta 与后续生命周期事件位于同一前缀时，在相位边界分开呈现，下一原生刷新帧再处理后缀。

会话控制状态在命令提交、控制变更的 `applied` 事件、工具完成、压缩完成及运行收束边界刷新。事件仅对当前会话、
当前历史且尚未呈现的序列生效；控制变更的开始、失败通知和文本增量不触发额外控制状态读取。
刷新复用单个后台任务，合并并发通知，不阻塞模型执行或正文呈现，不增加定时轮询。
切换页面后返回的旧查询不得覆盖当前状态，包括离开后重新打开同一会话；只读子会话保持其独立标识。
标签未变化时不更新控件。

工具名称形成即可显示活动行，参数片段只更新有界尾部。Assistant 的 reasoning 使用纯文本缓冲，answer 使用
独立源流；完整顶层 Markdown 块冻结，未闭合长尾部保持有界解析工作，完成后再收束。较大解析和语法高亮在线程
中处理不可变快照，UI loop 只提交捕获宽度对应的 strips，后台线程不得修改 Widget。

实时和重载使用 canonical MessageRecord 的 `role/scaffold` 决定可见性；事件类型表达来源，不能替代这些字段。
默认隐藏内部 `scaffold=true` 消息，保留附件输入和当前子会话自身的委派输入。Actions → Settings →
`Scaffold messages` 提供 `Off`（默认）和 `On`，持久化为 `config/tui.json` 中的
`show_scaffold_messages`。开启后，脚手架正文复用用户消息的布局、时间戳、悬停与复制交互，正文和左边栏均使用
主题 `text_lowlight`，悬停时正文仍保持低亮；真实用户消息使用 `text_emphasis` 正文和 `accent` 左边栏。
composer 编辑文字和排队输入预览正文同样使用 `text_emphasis`，保持常规字重；时间戳、占位提示和分隔符使用低亮色。
模型回复正文在流式显示、完成块、历史消息和 Markdown 失败的纯文本降级中统一使用 `text_emphasis`，
与工具消息、思考和脚手架的低亮层级区分；Markdown 内的链接、引用和代码仍使用各自语义色。
内部消息的显示不改变 `/fork`、`/navigate`
的用户消息编号。该偏好统一应用于主会话、子会话和任务会话的快照、实时事件、分页及缓存恢复；切换立即刷新当前
视图并保留已加载的历史范围，不改变后台 Run。只读子会话可打开 Actions 中的 Theme、Thinking display、
Collapse traces 和 Scaffold messages，其他会话与运行配置操作仍不可用。semantic tag 只影响模型包络。
流式回归须在 Provider 仍被阻塞时验证可见源流，
不能仅检查最终 RunResult。

Catalog 错误条目单独标记，但不能据此推断 canonical Session 不可读取。有稳定 Session identity 时仍由
Application 尝试 observation；只有该读取失败才显示加载错误。删除使用 Application 的 Catalog-scope trash，
Host 不重复解释归档、health 或持久化目录。

## 本地偏好与草稿

TUI preference 与 canonical Session 数据分离。主题、reasoning 展开方式、草稿记忆等纯呈现偏好可由
`TuiPreferencesStore` 保存；保存失败可诊断但不得损坏 Session。关闭草稿记忆时必须清理已保存草稿。

偏好只接受当前主题标识和配置结构；未知主题明确报错，不自动映射为其他主题。主题选择通过单一
Textual worker 合并为最新请求，revision 保护异步保存与渲染结果，避免过时结果覆盖当前选择。

输入草稿按稳定 Host/Session 语义保存，采用尾沿防抖并离开 UI loop 执行持久化。切换 Session、提交、清空或关闭
草稿记忆时，内存与磁盘状态必须一致，不能把一个 Session 的草稿带入另一个 Session。

文字编辑的磁盘草稿采用 300 ms 防抖；附件或引用添加完成、输入提交前立即保存，不等待防抖计时。Host 关闭等待 pending 保存完成；内存始终持有最新修订。
主页草稿保存上传资源空间身份和工作区，恢复时沿用已有副本及引用绑定；恢复后的元素与新添加元素使用同一编辑和提交流程。
欢迎页与会话页共用结构化输入、草稿持久化、编辑撤销及提交恢复流程；区别仅在于资源归属是预留空间还是已有 Session。
提交前把完整输入及其身份转入 TUI 待确认记录，接受后清除。重启查询框架接受凭据，恢复未接受输入，已接受输入保留在所属会话中，不自动重复提交。
主页资源空间不创建正式 Session。TUI 在启动恢复和关闭时释放不再被草稿或待确认输入需要的准备资源，编辑期间保留撤销所需副本；引用删除不修改源文件。
TUI 批量拖入保存会话副本，`@file` 目录多选添加原路径引用，`@skill` 多选添加技能引用；二者复用与输入框衔接的 CommandPopup，输入框负责过滤，目录不显示多选标记。
引用命令仅在输入框首位键入 `@` 时触发。文件菜单顶部常驻当前目录路径，技能菜单顶部常驻 `Skills` 标题；右侧固定以低亮度 `[x]` 显示已选数量，滚动及无匹配时保持可见，数量不占用列表条目。
聊天页和欢迎页在同一终端事件入口识别拖入或文件粘贴的路径，不要求输入框预先聚焦；开始接收时聚焦输入框，导入后填入附件元素。
终端粘贴按用户输入恢复应用焦点，再分发给失焦前的控件；终端确认弹窗后的粘贴不依赖焦点恢复通知先到达。
弹层内的粘贴仍交给该弹层的输入控件，不转入聊天草稿。
TUI 右键粘贴统一读取系统文本；Windows 无文本时读取原生文件列表并转为路径粘贴，继续使用上述上传入口。
上传和引用准备期间通过输入框的编辑与动作入口暂停修改和提交，保持焦点及正常外观；准备状态不禁用输入控件。
会话事件与流式内容刷新只同步输入可用状态，不重新选择焦点。点击聊天区域后保留阅读焦点，终端失焦后保持失焦；
打开会话、开始附件输入或切换交互模式时才明确转移焦点。附件准备完成不覆盖期间发生的焦点切换。
消息输入框的单次文本粘贴超过 4,000 个 Unicode 码点时，以唯一命名的 `pasted-text_<UUID>.txt` 上传附件插入原位置，
两页共用普通上传与草稿流程。文件路径识别优先，短文本直接插入；不累计正文长度或多次粘贴，连续键入不触发转换。
上传元素显示文件名及扩展名，文件引用显示 `@文件名及扩展名`，技能元素显示 `@名称`，均沿用主题 accent 色与整体编辑、删除和撤销行为。草稿保存正文、文件和技能引用的顺序与位置；排队列表及
`/unqueue` 菜单分别显示附件和引用数量。完整交互见[附件规格](attachments.md)。MCP 启动呈现连接状态与工具数量，
独立的运行期连接面板属于未来界面能力。

## 失败与恢复

- Application 命令失败时保留用户可修正的输入与选择，不先乐观提交 canonical 状态；
- 正文订阅 lag 从已应用游标分页追赶；不可见页面关闭正文观察，重进时读取一致快照；
- 来源、点查或投影失败只停止所属观察并报告原因，不自动无限重载，也不改变执行者生命周期；
- Markdown 或单个呈现组件失败不得篡改 Run 结果；可降级为有界纯文本诊断；
- 选择控制会话时只对遗留 running Run 请求恢复；queued 尚未取得执行锁，不能据此判为进程中断。
  Supervisor 已接管的任务保持原状态，任务启动恢复仍由既有协调器负责；
- 普通提交、继续运行、审批和 AskUser 的执行由 Supervisor 持有；TUI worker 取消只结束本 Host 的等待。
  关闭共享 Application 上 `close_application=False` 的 TUI 释放 Host 资源，已受理运行继续执行；
  显式 abort 提交持久取消意图，Application 关闭按 shutdown policy 处理全部受管工作；
- 私密凭据、完整工具秘密参数和第三方异常原文不得进入公开状态条或诊断页。

## 撤销输入与草稿

恢复输入包含文本、技能调用、会话上传项和原路径引用。TUI draft schema 4 一并保存文本、文件名与附件位置；只有附件的草稿也有效。
编辑文本、切换会话和启用草稿记忆的重启保留附件归属。接受输入后清除草稿；接受前失败与已有草稿合并恢复，
接受后发生模型或显示失败不重复恢复输入。排队撤回也合并保留新草稿。
Controller 不维护第二份恢复输入缓存，界面只通过 Runtime 执行撤销并重载标准观察投影。

撤销后的新 Run 事件使用当前 epoch；旧 Run 的迟到事件与结果保留原代次，不能恢复旧“准备上下文”状态
或读取已删除消息。

## 数据传输

`/export` 不接受参数，仅导出打开命令时的当前会话及其完整子会话树与附件，设置页固定会话范围；
未打开会话时提示先打开会话，不回退到全量导出。TUI 不提供 `/import` 命令。
其他数据操作从 Actions → Manage data 进入分页菜单；导出先选择数据类型，导入直接进入归档设置页，
无需指定类型。归档识别通过应用层读取并校验 manifest，在后台完成；识别前禁用导入，失败留在菜单内。
识别后显示只读类型及适用的范围、覆盖选项，更换归档清空之前的选择和覆盖设置。
Esc 逐级返回并保留上层选择。
归档文件及导出目录通过目录浏览菜单选择，导出提供默认文件名；
会话及原生技能支持全部或 `MultiChoiceScreen` 勾选，导入会话候选来自归档。
会话标题为主标签，ID 以右侧标签显示，不占用独立描述行，支持按标题或 ID 筛选。
路径浏览菜单允许按需编辑位置和文件名，但不要求填写命令 flags；没有 `/data` 别名或 CLI 参数解析入口。
Controller 调用所属 `LocalApplication` 的数据传输服务，复用当前 Session repository，不重新猜测后端。
执行由 App worker 持有，立即返回菜单交互；沿用主题切换的 `Choice.loading` 和原位刷新范式。
执行期间禁用重复提交，其他设置、导航、筛选与关闭保持可用；每次提交固定当时的请求，不受后续表单编辑影响。
进度、成功结果和错误留在菜单内，不写对话消息；关闭菜单不取消传输，重开显示当前操作状态。
CLI 与 TUI 共用业务请求及成功结果文案，参数交互分别由各 Host 适配。
导入不会切换当前会话、启动任务或连接新 MCP server。技能在下一次目录查询或模型请求中可用，个性化提示词在
下一次模型请求中生效；其他配置及覆盖的会话按结果提示重启 Host 后加载。
