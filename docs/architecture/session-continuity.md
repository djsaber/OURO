# 会话连续性与动态环境

> 文档类型：现行架构
> 事实来源：Runtime、工具批次、Harness、Delegation 与环境变化集成测试。

OURO 的 Agent 根据已有事实和当前能力继续任务。框架、插件、工具、技能与模型共同提供可交互的运行环境；环境可以变化，会话连续性依靠可持久化、可解释的事实，以及具体操作清楚的执行语义。

**环境提供当前能力，会话保存可信事实，执行层兑现具体操作的承诺。** 一致性要求限于存在实际依赖的请求、操作、事务与授权边界。整套历史环境不构成继续会话的统一前提。

## 事实、能力与操作

| 职责 | 内容 | 所有权与变化规则 |
|---|---|---|
| 当前环境 | 工具、技能、模型路由、策略与实现 | 由对应组件管理；在明确的决策或操作边界取得有效绑定 |
| 会话事实 | 用户输入、目标、进展、回答、调用、结果与归属 | 由 Session、Run、Harness 等持久记录保存；环境变化不改写已发生的事实 |
| 具体操作 | 待审批动作、待回答问题、执行中调用、已接受结算与子任务交付 | 由所属应用用例维护身份、授权、状态与幂等；按真实依赖决定能否继续 |

这些职责通过现有领域对象表达。Harness 中的业务状态、Host 持有的控制权和插件实现分别遵守自身边界；插件缺失不能被解释为目标消失或限制解除。进程内资源只承载当前执行所需的绑定，不成为持久事实的替代品。

普通输入、审批、回答、人工继续和子任务结果复用同一 Agent 执行链。Run 的创建或延续服务于执行记录、用量和资源所有权；任务连续性由会话事实及后续行动是否有效决定。

## 决策与环境生效

每轮模型决策取得当前有效环境。一次请求的能力描述、工具执行协调器和响应产生的调用使用同一绑定，下一次决策重新取得当前能力。未装配插件的 Runtime 对 Host 工具采用同样的决策边界。父模型看到的 Agent 目录也与该轮实际派遣使用的目录一致。

模型已选择的调用不能因更新而静默转向另一个同名实现。调用执行前仍检查当前权限、控制限制和禁用状态；决策绑定不构成绕过撤销的许可。

插件候选就绪后原子发布，在途调用由持有绑定的 owner 收尾。等待审批、回答或子任务时释放 Run 的环境租约，排队输入只保存持久事实；观察者为尚未处理的回调独立持有租约并负责排空。需要独占后台资源的组件遵守各自的交接规则。

因此，会话在新环境中继续与插件在进程内替换分别承担自己的契约。资源保留时间由实际在途工作决定，不能仅为保留会话身份而延长整个旧环境的寿命。精确生命周期见[运行时](../specs/runtime.md)与[插件规格](../specs/plugins.md)。

## 旧操作的局部收尾

继续任务包含两种责任：解释已有操作，以及基于现有事实进行下一次决策。应用层先处理待完成调用、交互或提交，再进入允许的模型决策。

已持久化的有效结果可以直接读取或幂等提交。尚待执行的调用校验其精确身份和执行契约；契约无法满足时形成明确的未执行结果。待回答问题保留交互身份与已接受回答，单纯收集回答可直接完成；需要调用 resume handler 的操作还要满足执行契约和当前权限。旧批准不转授新动作，回答也不自动成为新授权。

已经发出副作用而未记录结果的调用保留未知状态与核查依据，恢复机制不自动重放。消息帧可以用真实的“结果未知”反馈闭合，但帧完整并不证明外部操作成功或失败。外部幂等或结果查询由具体工具协议提供，框架只维护可验证的操作身份、提交去重和显式依赖。

无法承接的局部操作收尾后，Agent 可以在现有权限内重新决策。若相关行动仍依赖未知结果或必需控制，则保留该限制；必需控制无法解释时暂停受其约束的执行，历史读取、诊断、取消和显式释放控制仍有管理入口。操作与失败语义见[工具交互](../specs/tools-and-interactions.md)及[运行时规格](../specs/runtime.md)。

## Harness、输入与自动继续

输入接收、排队事实和消费授权各有边界。接收前执行当前输入策略；已接受输入持久保留原文、来源、附件和显式激活的技能正文。消费前再按当前策略检查，受阻时保留输入。队列维持 FIFO、原子输入单元及撤销语义，不以持有旧环境保证输入不丢失。

自动继续区分尚待策略决定与已经持久化的结算方案。前者需要当前有效的对应策略；后者按原生提交身份、history epoch、Harness 版本、activation 与队列优先级结算，不再次要求插件回调作出相同决定。回调失效会暂停相关自动继续，不自动解除 Host 保存的控制权。

控制器私有状态由其 owner 解释。显式强制释放可以撤销 Host 控制，但私有清理未确认时必须如实报告，不能猜测或清空私有数据。精确提交与撤销契约见[插件](../specs/plugins.md)、[运行时](../specs/runtime.md)和[会话撤销](../specs/session-undo.md)。

## 子 Agent 的任务承诺

Delegation 保存已委派的任务、父子身份、workspace、模型选择、预算及权限上限。定义更新不静默改写既有承诺；新派遣在父模型的当前决策绑定中选择定义。

child 后续可用工具由当前能力与委派上限、当前权限求交得到。新增工具、同名 owner 替换或权限放宽不能自动扩大已有授权；具体待完成调用仍核对自己的执行契约。能力缺失作为真实结果反馈，任务必需能力不可用时明确受阻。

child 使用普通 Session / Run，复用相同的工具、权限、预算和恢复流程。Delegation 身份保护派遣幂等、真实父子关联与结果唯一交付；这些内部保证不扩展为任意外部写入恰好执行一次。详见[子智能体规格](../specs/subagents.md)。

## 历史上下文与数据契约

历史记录表达过去的观察与行动，当前能力表达下一步可执行的选择。工具已删除不影响保留原调用和真实结果；已接受的用户输入保持原意。请求构造保证调用与结果关联完整，并使当前能力描述与执行绑定一致。

前缀缓存、token 估算和 Provider 私有续接服务于效率，各自检查适用范围。缓存失效不要求冻结环境；无法无损表达的必要数据必须明确报告，不能以丢失事实或重发已产生可见输出的请求换取继续运行。见[上下文规格](../specs/context-and-compaction.md)。

环境摘要、执行契约与持久格式承担不同职责：摘要记录来源，执行契约约束具体操作，格式决定数据能否读取和解释。OURO 只接受声明支持的当前数据格式；组件更新不自动获得跨数据版本兼容。无法解释的 owner 状态保留原数据并报告受影响范围，不隐式迁移或清空。见[会话持久化规格](../specs/session-persistence.md)。

## 实现与维护约束

连续性依靠单一 Agent 循环、明确的应用用例和现有原子提交机制。新增抽象必须对应独立职责和真实变化方向，资源必须具有清楚的 owner 与释放边界；不维护重复的输入、控制或恢复状态。

实现优先减少不必要的环境重建、重复读取和长期资源保留。运行路径读取有界事实，历史查询按需加载；缓存需明确键、失效、容量与所有者。性能结论以实际测量为依据。

设计验收同时检查环境变化后的任务连续性、操作授权和未知结果、控制失效、资源释放及真实持久数据上的恢复。测试证明行为边界，职责与维护成本仍需独立审查。工程要求见[编码准则](../development/coding-guidelines.en.md)。
