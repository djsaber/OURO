# 会话连续性与动态环境

> 文档类型：现行架构
> 事实来源：Runtime、工具批次、Harness、Delegation 与环境变化集成测试。

OURO 的 Agent 根据已有事实和当前能力继续任务。框架、插件、工具、技能与模型共同提供可交互的运行环境；环境可以变化，会话连续性依靠可持久化、可解释的事实，以及具体操作清楚的执行语义。

**环境提供当前能力，会话保存可信事实，执行层兑现具体操作的承诺。** 一致性要求限于存在实际依赖的请求、操作、事务与授权边界。整套历史环境不构成继续会话的统一前提。

## 事实、能力与操作

| 职责 | 内容 | 所有权与变化规则 |
|---|---|---|
| 当前环境 | 工具、技能、模型路由、策略与实现 | 由对应组件管理；在明确的决策或操作边界取得有效绑定 |
| 会话事实 | 用户输入、目标、进展、回答、调用、结果与归属 | 由 Session、Run、Harness 等持久记录保存；环境变化不改写已发生的事实 |
| 具体操作 | 待审批动作、待回答问题、执行中调用、已接受结算与子任务交付 | 由所属应用用例维护身份、授权、状态与幂等；按真实依赖决定能否继续 |

这些职责通过现有领域对象表达。Harness 中的业务状态、Host 持有的控制权和插件实现分别遵守自身边界；插件缺失不能被解释为目标消失或限制解除。进程内资源只承载当前执行所需的绑定，不成为持久事实的替代品。

普通输入、审批、回答、人工继续和子任务结果复用同一 Agent 执行链。Run 的创建或延续服务于执行记录、用量和资源所有权；任务连续性由会话事实及后续行动是否有效决定。

Run 预留及常规收尾由现有 Session 提交边界同时推进权威 Run、Session 投影和必要的最终消息。
Driver 完成接口接收本轮变更；规范消息头由存储提交维护，保护并发接受的消息。
child Run 预留与 Session 活动指针原子发布。精确故障语义见
[会话提交契约](../specs/session-persistence.md#sessionstore-契约)。

上下文准备拥有选择读取：它在一致读边界内取得摘要和未覆盖尾部，随后释放存储边界再做动态投影。
Driver 只协调当前操作，不累积消息历史；重试依赖 Run/turn 与片段 delivery key 的领域点查。
查询索引随消息提交和撤销维护，支持按 Run、turn 和片段身份直接定位；正文由消息事实拥有。

Files 将有序消息正文保存在顺序日志中，Session、Run、事件、资源元信息、消息位置、工具事实、调用状态与摘要使用会话自身的原生数据库。
消息正文读取利用连续 IO；相关原生记录在一个事务中发布，避免为同一语义边界拆出多次文件同步。
Files 快照由存储适配器统一拥有原生发布事务，消息索引不独立打开连接或提前提交；私有空 schema 与会话发布分开。
SQLite 按消息批次写入，并把同批 Run 计数变化汇总后一次更新，避免把完整快照拆成逐条增量提交工作。
两后端共用 SQL 工具事实、资源和摘要实现，读取结果按查询独立解码；Files 的一个查询范围显式共享同一连接，
嵌套读取和提交准备均复用调用方的原生事务。同会话的嵌套消费者共用外层资源锁，Files 未决提交及目录身份检查
也由外层读取边界负责；事实补齐中的记录解析不重复建立读取边界。作用域结束即释放，不引入常驻查询缓存。
消息自身的内容只解码一次，
持久归属检查与引用解析各自承担不同的不变量；查询独占新解码的无引用正文。
显式范围查询按有界批次联接所需工具事实，只有重复使用的可变内容需要复制；惰性上下文读取仍逐条推进。
Outcome 的展示正文和结构化结果按读取需求分列，共享原生行及提交边界。消息投影只读取自身需要的列，
无需解析 Shell 输出、搜索匹配等结构化结果；显式结果读取与完整归档再组装完整 Outcome。
这属于同一事实内部的物理分区，没有另建结果缓存或复制正文。
持久编码借用已验证的消息自有内容并同步完成序列化，独立 MessageFact 用于内存所有权移交；
编码直接使用事实内容。成员查询键由原生列表达，索引维护无需解析成员 JSON。
数据库不复制消息正文，工具正文也不另建日志。会话通知不永久保存；当前事实的最新修改号及消息位置索引支持有界补齐，不保留变更清单。
仅涉及原生记录的提交直接使用数据库事务；跨消息日志、输入或 Harness 文件的一致发布由现有短期提交决定负责。
媒体字节先持久化，Outcome 与新资源元信息、计数共同进入原生事务，避免逐资源文件与结果之间的额外协调。
请求小头、当前请求定位和 Draft 由同一原生数据库拥有；开始、关闭和替换在一个原生事务内发布。
两后端共用请求小头的定位、解码与写入；Files 的输入大正文作为独立不可变文件保存。
追加通过单条事务语句确认该容器仍属于当前请求并写入片段，不重复解码请求头，也不等待 Files 的观察读取锁。
WAL 读事务固定观察者的请求头和 Draft 前缀；Files 原有 Session 读边界继续固定历史和 Harness。
两后端共用原生 Draft 读写实现。原生连接的复用寿命由既有 Run 执行锁决定。
SQLite 的正式响应复用同事务释放的 Draft 页；Files 将正式正文写入 JSONL，原生数据库通过提交时的
自动页回收释放短期正文空间。该差异源于正文的物理归属，不需要额外清理任务或另一份正文仓库。
存储适配器负责这些物理选择，Application 与 Host 仍通过相同的会话、消息和观察端口读取。

执行快照读取 Session 指向的 Run 和当前代待处理 Run，完整 Run 历史属于显式查询。
Core 定义待处理条件，存储适配器在原生提交内维护可定位的成员；应用恢复只处理所选事实，不靠扫描旧 Run 重建执行头。
历史撤销同时终结未结算 continuation 的资格，保存的审计事实不构成恢复旧授权的依据。
定向读取与局部损坏的边界见[会话持久化契约](../specs/session-persistence.md#sessionstore-契约)。

## 决策与环境生效

每轮模型决策取得当前有效环境。一次请求的能力描述、工具执行协调器和响应产生的调用使用同一绑定，下一次决策重新取得当前能力。未装配插件的 Runtime 对 Host 工具采用同样的决策边界。父模型看到的 Agent 目录也与该轮实际派遣使用的目录一致。

模型已选择的调用不能因更新而静默转向另一个同名实现。调用执行前仍检查当前权限、控制限制和禁用状态；决策绑定不构成绕过撤销的许可。

插件候选就绪后原子发布，在途调用由持有绑定的 owner 收尾。等待审批、回答或子任务时释放 Run 的环境租约，排队输入只保存持久事实；观察者为尚未处理的回调独立持有租约并负责排空。需要独占后台资源的组件遵守各自的交接规则。

因此，会话在新环境中继续与插件在进程内替换分别承担自己的契约。资源保留时间由实际在途工作决定，不能仅为保留会话身份而延长整个旧环境的寿命。精确生命周期见[运行时](../specs/runtime.md)与[插件规格](../specs/plugins.md)。

工具原始调用与实际执行绑定、结果观察分别由 Call、started、Outcome 拥有；Run 只引用当前批次，
独立 Call 状态承载审批、等待和待接受提案。执行、恢复和观察按所需范围显式读取，Run 解码不会展开工具正文。
工具返回观察先于业务控制处理保存。框架控制反馈有独立归属，发布时移入固定消息；这使业务处理失败或中断
不会覆盖真实外部观察，也让恢复可以明确说明哪些状态变化未生效，而无需再次执行插件。
消息用固定引用读取原参数与确定结果，未知反馈保留当时字面内容；复制历史不会恢复执行许可。
委派也保存原 Call 的批次身份，等待调度和交付确认以同一身份定位；Provider 复用 call ID 不会把先前批次的结果
当成当前子任务的交付。确认通过 Call 状态和固定消息完成，不需要遍历整个父 Run。
等待同时固定 child Run，避免同一 Delegation 的 follow-up 改变既有结果归属。子结果进入父调用的提交先于父扩展
回调，后者失败不能抹去真实观察；消息发布仍由已有整帧边界负责，没有增加父子分布式事务或另一套交付回执。
等待绑定在 child 启动前进入原 started attempt 的 Call 状态，父停驻复用该绑定。父执行快照因此无需拥有另一份
独立等待身份，取消收尾也不能丢弃关联。派遣按实际 started 参数和当前父授权检查，准备工作及调度在存储锁外完成。
保存观察不依赖父执行资格，恢复任务只携带身份并读取确定 Outcome；无需在调度对象中再带一份结果正文，
也无需根据后来变化的委派展示状态重建原结果。
普通工具和 application Agent control 的异步执行由同一 ToolExecutionContext 拥有取消收尾；上层只按返回值类型
接收确定观察或等待绑定，结果保存复用原 Call 的迟到观察入口。
follow-up 的输入接受与 child queued Run 属于同一原生提交，Delegation 通过该 Run 的前驱和 Input 引用完成当前关联。
Files 的局部恢复补齐关联，SQLite 使用原生事务；调度按身份引用 Input 正文。
模型接受与执行前检查点各自通过既有原生提交边界持久化；整批结果发布同时提交消息、Call 发布状态、
Harness 变更与 Driver ready，恢复无需补齐逐条消息。具体契约见
[工具事实存储](../specs/session-persistence.md#工具事实存储)。

## 中断操作的局部收尾

原始供应商用量由现有账本拥有，Run 只保留执行计数，不作为第二个用量账本。请求报告使用已绑定的归属，
先完成账本自己的事务，再更新 Session 的请求小头；两边没有跨库事务。预算及终态视图读取账本的有限汇总，
账单修订属于独立展示语义。具体未知用量和嵌入宿主约束见[用量规格](../specs/usage-and-billing.md#run-消耗与宿主边界)。
显式恢复使用当前请求身份读取原始事实，再验证该请求仍是当前请求后补齐引用；原始用量只能证明消耗，
不能证明响应已完整保存。查询解引用而不执行这一恢复用例，详见[请求结算与恢复](../specs/usage-and-billing.md#请求结算与恢复)。

继续任务包含两种责任：解释已有操作，以及基于现有事实进行下一次决策。应用层先处理待完成调用、交互或提交，再进入允许的模型决策。

中断解释先准备 partial、执行状态与恢复事件，再通过同一个原生决定发布。正式响应的存在性使用模型轮次身份，
消息位置由提交边界维护，恢复服务读取相应检查点和位置索引。

已持久化的有效结果可以直接读取或幂等提交。尚待执行的调用校验其精确身份和执行契约；契约无法满足时形成明确的未执行结果。待回答问题保留交互身份与已接受回答，单纯收集回答可直接完成；需要调用 resume handler 的操作还要满足执行契约和当前权限。旧批准不转授新动作，回答也不自动成为新授权。

已经发出副作用而未记录结果的调用保留未知状态与核查依据，恢复机制不自动重放。消息帧可以用真实的“结果未知”反馈闭合，但帧完整并不证明外部操作成功或失败。外部幂等或结果查询由具体工具协议提供，框架只维护可验证的操作身份、提交去重和显式依赖。

无法承接的局部操作收尾后，Agent 可以在现有权限内重新决策。若相关行动仍依赖未知结果或必需控制，则保留该限制；必需控制无法解释时暂停受其约束的执行，历史读取、诊断、取消和显式释放控制仍有管理入口。操作与失败语义见[工具交互](../specs/tools-and-interactions.md)及[运行时规格](../specs/runtime.md)。

## 算法与恢复契约

Run 使用一个已接受的 Driver 绑定决定循环算法。默认 Driver 与插件 Driver 共用模型请求、工具批次、审批、
子任务、预算、用量及持久提交端口；插件不能直接写入原生 Run 状态。排队输入在接受时保存 Driver 身份，
执行时核对具体 release、配置修订和依赖实现，不因当前选版变化而替换已接受的算法。

Driver 在可能等待的工具或子任务操作前提供可序列化 checkpoint。等待事实与原生批次原子提交，释放进程内
实现后仍能恢复；已提交结果交给原实现消费，已消费 checkpoint 不重新触发副作用。契约缺失或禁用时保留
待处理事实并明确受阻，不换用默认循环。协议实现与算法不同：Provider 只绑定本次模型请求所用的实现，
会话和 Driver 不依靠长驻的 Provider 资源维持身份。

## Harness、输入与自动继续

输入接收、排队事实和消费授权各有边界。接收前执行当前输入策略；已接受输入持久保留原文、来源、附件和显式激活的技能正文。消费前再按当前策略检查，受阻时保留输入。队列维持 FIFO、原子输入单元及撤销语义，不以持有旧环境保证输入不丢失。

输入原文由独立 InputRecord 拥有，Session 队列只保留待处理身份；小 InputState 记录消费、取消和撤销状态。
消息位置通过固定引用使用接受时的正文、技能和附件意图，实际文件观察由消息拥有。查询边界显式物化所选内容，
存储与归档保留事实和引用，避免把读取视图变成另一个正文来源。
这些状态变化不改写接受时的内容与归属，重试通过输入身份直接定位。撤销后仍独立有效的输入在消费前重新校验，
不会把新的策略许可写回旧接受事实。精确存储与提交契约见[会话持久化](../specs/session-persistence.md)。

自动继续区分尚待策略决定与已经持久化的结算方案。前者需要当前有效的对应策略；后者按 Run 检查点、history epoch、Harness 版本、activation 与队列优先级结算，不再次要求插件回调作出相同决定。结算后 Run 只保留动作和诊断，清除方案中的正文及暂存状态。回调失效会暂停相关自动继续，不自动解除 Host 保存的控制权。

完整提交结果只属于正在执行的调用，不形成永久数据根。短期文件决定承载恢复需要的有限效果，完成后退出；
输入接受和 Run 结算各自保存实际重试所需的事实。当前提交身份只用于持有 mutation 边界期间的丢失返回确认，
不扩展为全局版本条件或万能操作日志。命令输出留在调用内存，取消时等待其拥有的写入任务取得实际结果。

工具的执行归属与业务提交资格分开：取消先撤销调用视图及 worker 反向 Host 权限，所属回调仍由原 owner 收尾。
确定迟到观察只能通过原 Call/started attempt 保存；该路径不接触 Harness、Run 执行头或新历史。
因此保存外部已发生的事实不需要恢复旧授权，worker 关闭且没有返回时也不会被伪装成工具未执行。

控制器私有状态由其 owner 解释。显式强制释放可以撤销 Host 控制，但私有清理未确认时必须如实报告，不能猜测或清空私有数据。精确提交与撤销契约见[插件](../specs/plugins.md)、[运行时](../specs/runtime.md)和[会话撤销](../specs/session-undo.md)。

## 子 Agent 的任务承诺

Delegation 保存已委派的任务、父子身份、workspace、模型选择、预算及权限上限。定义更新不静默改写既有承诺；新派遣在父模型的当前决策绑定中选择定义。

child Run 以固定身份引用冻结的系统提示、工具目录、约束和预算。绑定时按身份读取并验证来源，
进程内 RunResources 持有执行所需配置，释放时一并退出；恢复不依赖当前同名 Agent 定义。原生 CAS 拒绝生命周期
更新替换冻结权限与配置。手动摘要使用 Session 的冻结关联，不承担 child 执行的身份。

child 后续可用工具由当前能力与委派上限、当前权限求交得到。新增工具、同名 owner 替换或权限放宽不能自动扩大已有授权；具体待完成调用仍核对自己的执行契约。能力缺失作为真实结果反馈，任务必需能力不可用时明确受阻。

child 使用普通 Session / Run，复用相同的工具、权限、预算和恢复流程。Delegation 身份保护派遣幂等、真实父子关联与结果唯一交付；这些内部保证不扩展为任意外部写入恰好执行一次。详见[子智能体规格](../specs/subagents.md)。

## 历史上下文与数据契约

历史记录表达过去的观察与行动，当前能力表达下一步可执行的选择。工具已删除不影响保留原调用和真实结果；已接受的用户输入保持原意。请求构造保证调用与结果关联完整，并使当前能力描述与执行绑定一致。

摘要拥有压缩结果和有限来源引用，不复制完整覆盖身份或维护正文哈希。激活与历史撤销负责维护覆盖有效性，
普通上下文投影消费已接受摘要；历史展示锚点不承担来源有效性的职责。具体边界见
[上下文与压缩](../specs/context-and-compaction.md#compactionrecord)。

下一次上下文选择归 Session，最近实际请求归请求记录。媒体范围用固定消息与规范位置表达；投影可以只消费活动
范围，不依赖旧请求 metadata 或全历史定位。撤销、分支和转存维护选择的引用，实际请求保留当时输入。

前缀缓存、token 估算和 Provider 私有续接服务于效率，各自检查适用范围。缓存失效不要求冻结环境；无法无损表达的必要数据必须明确报告，不能以丢失事实或重发已产生可见输出的请求换取继续运行。见[上下文规格](../specs/context-and-compaction.md)。

环境摘要、执行契约与持久格式承担不同职责：摘要记录来源，执行契约约束具体操作，格式决定数据能否读取和解释。OURO 只接受声明支持的当前数据格式；组件更新不自动获得跨数据版本兼容。无法解释的 owner 状态保留原数据并报告受影响范围，不隐式迁移或清空。见[会话持久化规格](../specs/session-persistence.md)。

## 实现与维护约束

连续性依靠统一的原生执行端口、明确的应用用例和现有原子提交机制。Driver 决定算法，框架拥有事实、权限和恢复。新增抽象必须对应独立职责和真实变化方向，资源必须具有清楚的 owner 与释放边界；不维护重复的输入、控制或恢复状态。

实现优先减少不必要的环境重建、重复读取和长期资源保留。运行路径读取有界事实，历史查询按需加载；缓存需明确键、失效、容量与所有者。性能结论以实际测量为依据。

设计验收同时检查环境变化后的任务连续性、操作授权和未知结果、控制失效、资源释放及真实持久数据上的恢复。测试证明行为边界，职责与维护成本仍需独立审查。工程要求见[编码准则](../development/coding-guidelines.en.md)。

消息事实的正文按访问方式组织：Files 顺序日志支持窗口和完整读取，内容无关的偏移与成员索引支持点查、Run 查询和撤销。
正文只保存一份，索引不承担业务事实来源。提交仍由原有有限决定保证一致性，不增加恢复协调器。
SQLite 将原生连接寿命绑定到已有执行所有权，复用语句缓存和 WAL，而事务仍按原提交边界结束。
普通原生句柄允许最后退出的观察连接完成 WAL 收尾；运行结束释放空闲句柄。
Files 的目录投影读取也属于这一连接寿命：Session 头与最新 Run 共享一个原生快照，目录本身仍是可重建的派生数据。
Session 头保留当前 controls 投影，与选中 Harness 引用共同提交，使状态查询无需展开无关的插件私有状态。
该投影只覆盖当前活动控制状态，完整 Harness 仍拥有可撤销历史，不增加历史正文缓存或独立更新协议。
提交准备同样按效果确定读取集：请求、Run 和事件等变化只使用当前头；发布消息、变更 Harness 或撤销历史时读取相应检查点。
两后端都在读取边界完成类型解码，私有新事实直接交给结果；需要共享源事实的纯投影才复制内容。
调用身份以三个不可变字符串组成槽位值对象，复制事实图可直接共享它；身份不携带通用模型字典或字段状态。
原 Call 仍独占参数正文，同一原生行的小元数据投影支持无需参数的结果绑定和提交准备。投影随不可变 Call 一次写入，
没有独立失效或重建协议；额外空间只随 Call 元数据增长，不随参数体积、查询次数或消息投影次数增长。
