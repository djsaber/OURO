# 工具执行结果与模型呈现

> 文档类型：现行架构
> 执行与恢复契约见[工具规格](../specs/tools-and-interactions.md)。

## 事实、内容与呈现

工具执行回答“发生了什么”，请求投影回答“当前模型如何接收这些事实”。二者具有不同生命周期：执行可能产生
不可重放的副作用，而同一执行结果可以被重启、后续请求、其他协议或另一模型重复读取。

`ToolResult` 保存调用身份、错误状态、有序内容、结构化业务数据、资源关系与已声明的状态意图。
`core.content` 的内容类型同时服务于工具结果和消息；字符串是单个文本块的简写。
`structured` 保留机器可读业务结果，`resource_refs` 表达资源关系；二者不隐式替代模型内容。
日志和 Observer 使用 `text_content` 提取文本，不把媒体编码拼进展示字符串。

模型呈现由 Provider 边界负责。工具和执行器不识别协议、厂商品牌或模型名称；消息存储不保存某次请求专用的
协议补偿消息。Provider 只读取内容，不读取本地路径、执行工具或修改会话。

## 执行链路

```text
模型完成响应 → ToolCallBatch → schema / 权限 / 交互预检
    → ToolExecutor：调用、身份校验、内容限额
    → ToolCallCoordinator：收尾、状态意图、持久检查点
    → RunLifecycle：按调用顺序原子提交 canonical 工具结果
    → 上下文：完整工具帧、资源准备、预算
    → ToolResultProjector：原生结果内容 + 零到多个补充上下文
    → 协议 codec → 下一次模型请求
```

SDK 与 worker 将公开内容类型转换为领域内容；MCP adapter 将已支持的原生内容块转换为同一表示。
执行、恢复回调和远端工具共用结果提交路径，不各自注入消息。

每个结果由一个 canonical `tool_result` 消息承载。整批资源校验、状态效果提交、按调用身份去重、撤销和恢复
在执行事务边界内完成。补充上下文只是该事实的请求投影，不参与用户输入、授权、事件回放或执行去重。

## 呈现端口

`ToolResultProjector` 是纯函数，接收模型可见的工具结果，返回 `ToolResultPresentation`：

- `content`：回答该次调用的内容；
- `context`：零到多个有序内容片段，作为该调用的补充材料。

`project_tool_result_messages` 保留原结果的引用和错误状态，在连续工具结果批次结束后依次输出补充片段。
宿主为每个片段生成带工具名、调用 ID 和 `tool-context` 语义边界的 user 消息；其中的文本边界进行转义。
投影函数不选择消息权限，也不创建系统指令。普通文本的索引结果、附加证据与原生媒体都可以使用这个端口。

连续工具结果属于请求准备已经完成的工具交换。投影按输入顺序运行，补充材料不得插在同批两个工具结果之间。
重试从 canonical 输入重新生成呈现，不在上一次已展开的请求上追加。路由切换时按新端点能力投影，原事实不变。

`providers.tool_content.ToolContentPolicy` 是按内容类型声明放置位置的策略实现：优先使用原生工具结果，
其次使用协议允许的补充上下文，不可承载的内容提供明确文本说明。它不按工具名分派。
新增协议负责声明自己的承载能力和编码；需要不同结果呈现语义的 codec 可提供其他纯投影函数。
执行副作用、交互等待和状态提交继续使用各自的类型化契约，不进入呈现端口。

请求准备统一检查内联媒体与工具资源的输入能力和格式；无法发送的媒体转为说明，不消耗请求媒体限额。
符合条件的工具媒体保持类型化，由 Provider 决定原生承载或补充上下文；直接调用 Provider 时，其结果策略也执行能力和格式检查。
这些请求投影不修改 canonical 内容，资源准备同时补充有界内容与读取路径。
用户附件的输入准备与请求适配遵循[文件输入架构](file-input.md)，不复用工具调用身份或补偿消息。

## 端点能力与协议能力

两种能力同时成立才发送原生内容。`ModelMetadata.input_modalities` 表达端点接受的图片、音频、视频模态；codec 表达协议允许的位置和格式。

| 协议 | 原生媒体工具结果的请求呈现 |
|---|---|
| Responses | `function_call_output.output` 中的有序 `input_text` / `input_image` 数组 |
| Anthropic Messages | `tool_result.content` 中的有序 `text` / `image` 数组 |
| Chat Completions | 文本 `tool` 结果与批次之后的图片、音频或视频 user 上下文 |
| 未声明对应模态能力的端点 | 工具结果中的文本说明，不发送该模态数据 |

纯文本结果保留协议的字符串表示。用户附件的有效性和错误语义由文件输入边界负责；工具结果的能力降级
不意味着协议可以静默忽略非法用户输入。

面向模型的说明只描述可见内容和可执行的下一步，不暴露端点、消息角色或内部预算术语。能力不足时明确说明
当前模型无法查看图片、听取音频或查看视频，重复打开或改变大小无效；发送量超限时建议减少文件或提供更小的版本。两种原因分别表达。

## 性能与边界

结果提交按批次工作，不因内容块增加存储查询或事务。请求投影为线性遍历，额外空间只用于输出与当前批次的
补充片段；不复制、解码或重新读取媒体字节，不引入跨请求缓存。

执行器对同一结果的全部文本块共享字符预算，对媒体 URI 共享独立的编码字符预算。文本超限带截断标记，
媒体超限整块替换为说明，不能截断 Base64。请求级媒体与上下文预算由上下文准备负责；估算使用每块媒体的本地规划配额，
不把 Base64 长度当作文本 token。协议封装文字属于估算误差，实际用量由供应商返回。

请求媒体预算按 Base64 字符数计量，外部 URL 按 URI 字符数计量。符合发送条件的已有媒体先扣减剩余额度，资源媒体在签名识别后、完整内容载入内存和编码前检查剩余额度，
每个保留的媒体块只扣减一次；后续请求优先保留较新的消息。计量不切片或复制已有 Base64 内容。
上传资源的字节窗口读取仍会流式校验整个文件的摘要与大小，内存只保留所需窗口，详见[资源规格](../specs/resources-and-supervision.md)。

公开内容类型描述框架能保留的语义。增加一种模态需要定义其内容类型、执行限额和协议编码；不能通过任意
JSON 或回调绕过消息权限、调用关联、资源授权与提交事务。

## 验证边界

- `tests/core/test_tool_result_projection.py`：纯文本的一对多呈现、来源归属、批次顺序和输入不变性。
- `tests/providers/test_tool_result_content.py`：三种协议、原生内容顺序、图片能力降级和路由重投影。
- `tests/application/test_tool_result_content.py`：执行、文件/SQLite 提交、重启、去重及下一次真实上下文准备。
- `tests/providers/test_media_inputs.py`：音视频原生编码、角色约束、格式限制与完整工具交换后的补充上下文。
- SDK、worker、MCP 与执行器测试覆盖内容传递、非法类型和独立输出限额。
