# 文件输入与模型内容

> 文档类型：现行架构
> 行为契约见[附件输入规格](../specs/attachments.md)，存储契约见[资源规格](../specs/resources-and-supervision.md)。

## 输入材料与任务意图

文件是用户提供的任务材料，文字是用户表达的任务意图。文件的所有权、访问地址与模型已经获得的内容是三个独立问题：

- 所有权决定谁保存原件，以及会话删除、分支和迁移时由谁负责它。
- 访问地址让 Agent 使用现有工具继续读取文件及其关联材料。
- 已输入内容记录该次请求实际获得的预览或媒体，支持重启、审查和上下文管理。

输入准备由 Application 完成。选择文件、保存副本和生成预览都不属于 Agent 工具调用；工具调用由 Agent 根据任务自主决定，结果按真实调用记录。

## 文件来源

| 来源 | 所有权和地址 | 适用语义 |
|---|---|---|
| 拖入终端、文件路径粘贴或长文本粘贴 | 待提交输入或会话持有独立副本，保存于 `OURO_HOME/sessions/<reserved_or_session_id>/resources/files/<filename>` | 准备并提交一份材料，后续使用不依赖源文件 |
| `@file` 选择 | 保存原文件绝对路径；工作区内的文件同时绑定选择时的工作区 | 指定项目中的文件，Agent 可以按正常权限读取其依赖和相邻文件 |

两类文件共用内容准备与请求适配。上传保留原名称，并为会话内的文件分配安全、可读且不冲突的存储名称。
内部资源 ID 用于持久关系，摘要用于校验字节；模型使用原名称、会话文件名和可读取的地址。
原路径引用保留文件所在目录的意义，输入准备只读取选中文件，不自动分析依赖。

TUI 在粘贴入口将超阈值文本写成唯一命名的 UTF-8 临时文件，随后复用普通上传流程。
临时源由本次导入操作持有并释放，草稿只引用已上传副本；阈值、命名和粘贴事件处理均属于 TUI。
框架使用统一资源契约，提交阶段不承担文本附件转换。
系统剪贴板由 TUI 适配层读取；Windows 原生文件列表规范化为路径粘贴，与终端拖入共用文件识别和上传流程。
平台能力不进入框架契约；路径按进程所在环境解释，不推断跨系统挂载关系。

草稿删除只移除输入元素。主页草稿保留准备资源以支持编辑撤销；启动恢复和关闭时，TUI 按仍保留的草稿及待确认输入释放不再需要的准备资源。
已成立会话的资源移除检查消息和队列；会话回收携带所属附件目录。
分支与子会话显式接收上传资源时拥有独立副本。归档携带会话文件、清单、消息及实际请求快照，原路径文件作为外部依赖保留。

## 主链与职责

```text
Host 草稿：用户文字 + 有序文件项
    ↓ Application 接受输入 / 持久队列
文件内容准备：来源校验 → 有界读取 → 文本、原生媒体或引用
    ↓ 同一提交边界
canonical 历史：附件骨架 + 可选用户正文
    ↓ 请求投影
当前会话附件地址 + 目标端点能力与预算适配
    ↓ ContextBuilder / ContextSnapshot
Provider adapter → 原生模型协议
```

| 边界 | 职责 |
|---|---|
| `core.input_content` / `attachment_input` | 文件项、文字位置、输入单位及骨架关系 |
| `core.attachment_projection` | 无 I/O 的媒体签名识别、编码识别与字节边界解码 |
| `application.file_inputs` | 有界内容准备、来源说明、预算和请求适配 |
| `ResourceService` / `ResourceStore` | 会话资源关系、内容完整性、文件复制与发布 |
| Session 存储 | 输入、队列和历史的原子提交，分支与归档发布 |
| Provider adapter | 将统一内容块编码为目标端点协议 |
| TUI | 拖入解析、文本粘贴策略、内联目录菜单、原子附件元素和草稿恢复 |

Host 不解释存储布局或展开模型内容；Provider 不负责导入文件；工具不承担输入预处理。
原路径读取复用现有路径策略，上传目录为当前会话提供只读访问范围。实际访问仍受相应工具权限约束。

## 内容准备

文件输入被消费时按元素顺序共享有界预算。文本按 UTF-8 字节数计算内容开销，图片、音频和视频同时受准备配额与编码字符上限约束。
文本能完整容纳时提供全文；否则取首尾窗口，并标明实际字节范围与省略位置。解码后的 UTF-8 开销超出配额时缩小窗口。
这是一份可核对的片段预览，不包含模型生成的语义摘要。

原生媒体需要有效容器签名、端点和 codec 输入能力、受支持的格式以及足够预算。
满足时按模态生成 ImageContent、AudioContent 或 VideoContent；其余情况用文字说明未提供内容的原因。
三种能力相互独立，Application 接收 `ModelMetadata.input_modalities` 的类型化集合，
不通过厂商、模型名或图片能力推断音视频能力。
不透明文件只提供元信息和路径。内容准备不运行文件、不解压、不做 OCR、音频转写、视频抽帧或格式转换。

输入消费时写入历史的说明描述当时实际观察；能力不足时注明附件加入时所用模型不支持该模态，不将当时的能力
描述成后续模型的限制。未保存媒体的输入不会因能力切换而自动补读原件；需要重新附加文件或通过工具读取。

原路径观察使用同一文件句柄读取所需范围，并检查读取前后的身份、大小和修改时间；发生变化时重试一次。
无法得到稳定内容时仍保留文件引用和失败原因。待消费队列只保存输入选择，文件内容在消费时确定。
上传资源读取流式校验整个文件的摘要与大小，只将所需字节窗口保留在内存；字节窗口上限不代表磁盘读取量上限。

## 历史与请求

附件骨架使用 `role=user`、`scaffold=true`、`semantic_tag=attachments`，正文是随后的独立用户消息。
二者通过输入批次关系构成一个上下文单位，排队、压缩、分支和用户撤销都保持这个关系。
文件名和文件内容保持用户材料权限，骨架身份不赋予 system 或 Skill 权限。

骨架 `content` 是已准备内容的消息内权威表示：TextContent 保存元信息和实际预览，ImageContent、AudioContent、VideoContent 的 data URI 保存实际媒体字节。
工具后续读取由各自的 tool_result 保存。请求复用这些内容；源文件变化不改变已经记录的输入。

上传骨架保存原名称、会话存储名称，以及独立的完整绝对路径表。分支复制时更新路径表，每次请求也根据所属会话清单校准，
因此分支或导入后可以使用目标地址，无需重读文件内容。同名原文件通过不同会话存储名称与各自预览明确关联。
原路径引用的地址在选择时固定。

请求投影可以因目标端点不支持对应输入模态或预算不足而省略媒体，并附上原因。ContextSnapshot 保存统一消息与
文件投影，包含当时的地址、媒体块、端点输入能力和省略说明；查询它时直接读取快照。完整上下文预算和压缩沿用既有机制。

用户附件和工具结果统一检查输入能力与格式；不能发送的媒体附带说明，不消耗请求媒体限额。
符合条件的工具媒体保持类型化，协议放置由[工具结果呈现](tool-results.md)负责。
两条链路共用能力不足的自然语言说明，媒体大小或总量限制使用不同说明。
所有图片、音频和视频共用请求级编码字符限额，同一消息的已有媒体与资源引用依次扣减；资源媒体在签名识别后、完整内容载入内存和编码前检查剩余额度。
Provider 在此基础上完成工具结果呈现和协议编码，请求适配和协议补充消息不写回历史。

## 编辑与页面归属

TUI 草稿由文字和带位置、顺序的文件项及技能引用组成，显示元素只是其编辑投影。Backspace、Delete、选择替换和撤销/重做保持元素原子性。
附件准备与焦点归属独立：准备期间统一阻止编辑和提交，不通过禁用输入控件表达忙碌，避免引入焦点和外观切换。
`@file` 和 `@skill` 菜单复用输入框的 CommandPopup。文件目录读取期间保留最后一份完整菜单：首次打开保留引用命令，
进入其他目录保留当前列表，原选中行的单 cell 标记复用主题加载动画；目录快照就绪后一次替换标题、候选和布局，
不发布未完成的目录或临时空列表。
读取期间可继续编辑过滤词或关闭菜单，旧菜单的条目导航、确认与多选暂停；保留等待期间新输入的过滤词，会话或草稿切换使迟到结果失效。

目录读取在后台线程内使用 `os.scandir`，复用目录项的类型信息，关闭扫描句柄后发布按目录优先、名称稳定排序的快照；
不递归枚举、不跟随符号链接。过滤与选择只使用该快照，不重新读取文件系统。
CommandPopup 持有完整候选项，候选集变化时计算列宽和选择标记布局；每项固定占一行，长名称按终端单元格宽度截断。
列表高度由行数直接给出，Textual 仅为当前可见行生成富文本和终端 strip。上下移动只更新新旧焦点行，并由条目索引
直接计算滚动位置；到达边缘时绘制新进入视口的行，标题独立固定。渲染成本受视口大小约束，不随目录项数量增长。

欢迎页的文件选择只改变草稿。上传直接写入预留身份下的最终资源目录，准备清单不构成 Session。
首次输入通过校验后，与 Session 一起持久发布，已有文件和资源身份原位沿用。该输入通过现有持久队列消费边界进入历史，后续执行沿用正常 Run 流程。
TUI 独占草稿内容、保存设置、恢复和保留策略；框架只负责资源准备、归属校验、输入接受和安全释放，不依赖 TUI 草稿格式。
草稿恢复只加载结构化输入及必要元信息。上传不依赖源文件，引用保持原路径及工作区绑定；两类元素均沿用正常编辑、删除、撤销和提交流程。
提交中的输入由 TUI 保存到接受结果明确为止。框架的原生输入提交回执供重启查询，避免丢失未接受输入或重复恢复已接受输入。
排队项保存完整输入；撤回后恢复文字、来源、顺序和位置，已有草稿通过明确的合并规则保留。
