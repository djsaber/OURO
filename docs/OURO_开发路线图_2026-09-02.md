# OURO 开发路线图

> 文档类型：未来规划
> 当前能力不在本文重复列举，以项目概述和现行规格为准。

本文描述尚未实现的能力、实施顺序和进入实现阶段的条件。当前能力以项目概述和开发架构为准。
具体任务、依赖和退出条件见 [执行计划索引](../dev/plans/README.md)。

## 推进原则

- 每项能力先定义 application 用例、领域记录和失败语义，再实现 Host 或具体协议。
- canonical 数据与可重建投影分离；任何新索引都不能成为核心写事务的单点故障。
- 新外部依赖必须停留在适配层，并具备超时、取消、资源释放和可诊断错误。
- 不以“未来可能需要”为理由引入空接口、通用 manager 或深层依赖注入。
- 每一项交付必须包含正常、错误、恢复和并发边界测试，并同步更新权威文档。

## 前置架构基线

后端中立 SessionRepository、File/SQLite adapter、ResourceService、RuntimeSupervisor、ConfigurationFacade、
类型化 Host 事件、LocalApplication 生命周期、TUI、子智能体、builtin Goal/Plan 以及插件管理和运行闭环构成
后续工作的前置基线。边界、不变量和验证证据由[开发架构](OURO_开发架构_2026-09-02.md)与
[现行规格](../dev/specs/README.md)定义。

Marketplace、签名/publisher trust root、worker OS sandbox、每插件依赖环境和通用 session-scoped KV/CAS 不属于
当前路线图；只有真实插件提出无法由当前边界表达的共同需求时才重新评估。

## 近期：Host 产品面

### TUI 产品化增强

TUI 的目标增量集中在历史规模、资源输入和终端体验：

范围：

- 用 Session 消息 cursor 构建冷历史分页和视口窗口，使首屏工作量受页大小约束；
- 为文本、图片资源提供与 canonical resource reference 一致的附件草稿、检查和移除交互；
- 在 Windows Terminal、常见 POSIX 终端和窄屏环境建立首反馈、持续流、长代码块和长历史响应性基线；
- 保持用户离开底部后的视口锚定，并对持续事件过载采用有界降级和持久化追赶；
- 补齐发布级键盘兼容、颜色降级、复制与链接体验。

完成条件：冷加载成本与页大小相关，附件只通过 ResourceService/Session 引用进入 Run，TUI 继续只负责渲染和
输入映射，不解析 Session 文件或 SQLite，也不复制 application 状态机。

### Desktop Host

目标：为现有 application 能力提供本地桌面界面。

范围：

- session catalog、搜索、分支和回放；
- 流式运行、工具批次、审批、AskUser 和 abort；
- 文件 diff、资源预览和设置；
- 通过 RuntimeSupervisor 订阅后台运行。

完成条件：Desktop 只依赖内聚 application service、DTO 与通知，不复制运行规则或直接解析本地文件/SQLite。

## 后续：高级个人智能体能力

### 长期记忆

- 记忆候选提取、用户确认和来源追踪；
- 可查看、编辑、禁用和删除；
- 检索结果与上下文预算协同；
- 防止把工具输出或外部提示自动提升为可信记忆。

### Durable Task/Workflow

- 复用 Goal 的显式创建、Run continuation、状态、预算和控制权仲裁；
- 自动任务负责日历/间隔触发；依赖任务图有独立需求时，再定义 durable workflow 记录与状态；
- ready task 选择、依赖、重试与跨 Run 调度；
- 与当前 durable Delegation 建立显式关联，不复制 Agent 状态机；
- 用户可见的计划进度、预算与控制入口。

多任务/工作流复用子智能体和单 Goal 生命周期，不把 AgentTree 或 Goal state
冒充通用任务图。

### SQLite 产品化

文件与 SQLite 实现同一 SessionStore contract；SQLite 使用 adapter 内部事务和索引，文件到 SQLite 的
导入 API 会验证并整体回滚。CLI 通过命令参数与环境变量选择后端，不隐式迁移。产品化目标包括：

- 提供 Desktop 后端选择，以及 CLI/Desktop 迁移预检、进度和备份体验；
- 在真实长会话数据上建立查询、写入、WAL 维护和恢复基准；
- 定义版本升级、备份恢复和损坏诊断流程；
- 保留文件后端作为可读实现和显式导出来源。

不得为两种实现再增加通用 ORM、UoW 或第二套领域恢复规则。

## 跨阶段质量门槛

每项能力必须满足：

- 行为、错误、取消、恢复和并发语义有测试；
- 不新增 core 对外层的依赖；
- 快速 `tests/architecture + tests/core` gate 通过，完整跨平台 suite 与 branch coverage 门槛通过；
- 敏感数据不进入日志、事件或公开 DTO；
- 资源有明确关闭路径；
- CLI、TUI、Desktop 和协议适配器不复制 application 规则；
- README、项目概述和开发架构与代码保持一致。
