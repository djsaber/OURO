# 测试策略

测试的价值取决于能否发现具体回归，以及失败时能否解释原因。用例数量和覆盖率用于发现盲区，
不能替代对功能、数据完整性、权限、并发和资源成本的判断。

## 选择验证边界

| 需要保护的行为 | 合适的测试边界 |
|---|---|
| 状态转换、协议编解码、预算、输入校验 | 直接调用对应领域对象或函数 |
| 菜单过滤、选择、编辑、返回 | 在 Textual `App` 中挂载目标组件 |
| 提交、会话切换、草稿、审批、跨 Host 恢复 | 使用真实 Application 与临时存储 |
| 原子提交、崩溃恢复、锁、进程回收 | 使用真实文件、数据库或子进程，并注入明确故障 |
| 算法复杂度、缓存和局部更新 | 统计读取、写入、格式化或重绘次数 |
| 帧耗时、按键延迟、吞吐量 | `dev/benchmarks` 中的独立测量 |
| 图案、配色、光照、余辉、装饰、留白和居中效果 | 人工视觉检查 |

TUI 的固定色值、颜色角色映射、色相、亮度、饱和度、悬停配色和透明度由人工视觉检查验收。
自动测试验证主题数据与 Token 格式的合法性、偏好持久化、文本、交互、布局、缓存和资源生命周期，
不对视觉颜色建立断言或等待条件。

仅为检查静态标签、色值或构造器内部字段而启动完整应用，会增加 I/O、定时器和后台任务，
却没有保护额外的集成边界。测试应在能发现对应错误的最小边界执行。
跨存储后端、协议和进程边界的场景有不同失败方式，应按实际风险保留。
升级测试中的旧格式是兼容功能的有效输入，不能仅因数据格式旧而删除。

TUI 应用集成测试按场景放在 `tests/tui/app/`，共用应用构造与受控 Provider 分别由
`support.py` 和 `providers.py` 提供；通用等待直接引用 `tests/tui/helpers.py`。
组件及跨 Host 测试维持独立边界，不为对齐生产目录而改变 fixture 的发现或生命周期。
移动定义后，monkeypatch 路径要跟随被测代码的依赖查找位置；不能只更新到依赖的定义模块。

## 异步操作

`pilot.pause()` 只适合等待消息处理，不代表应用 worker、线程或持久化操作已经结束。
页面切换使用 `tests/tui/helpers.py` 的 `wait_for_screen`；提交和后台状态使用 `wait_until`
等待具体结果。计时上限是挂起保护，不是响应速度要求；超时应报告页面、焦点和 worker 状态。
已有完成 Future、队列或 Event 时优先等待它们；否则按条件轮询，满足条件立即继续。
轮询间隔只负责让出事件循环，不作为操作必定完成的依据，也不重复提交业务动作。

流式交互测试用可放行的 Provider 保持目标阶段，再等待该阶段的业务投影或可见状态。
输入接收、持久化和模型准备也属于异步提交链路，不能在业务状态等待前额外要求首个模型事件
在一两秒内到达。需要同时确认 Provider 已进入流和界面已就绪时，将两者作为同一个等待条件。
从提交开始就用 `try/finally` 保护放行操作，使启动或断言失败也能正常回收阻塞的 Provider。

真实文件存储上的模型启动包含输入提交、Run 检查点、工具批次和子代理创建，不能把整条链路的
累计耗时作为功能断言。TUI Provider 已提供 Event 时，使用 `wait_for_events` 直接等待阶段握手；
其 60 秒上限仅用于检测挂起，阶段到达立即继续，再等待需要操作的界面状态。并发测试用队列
记录启动顺序、用门闩维持重叠，并在整个执行结束后检查最大并发数，不用固定次数的短睡眠。

注入草稿保存故障时，提交 worker 结束不代表恢复草稿的去抖保存结束。恢复真实存储方法前，
必须等待故障阶段的后台写入完成；替换方法不会替换已交给线程的 callable。用门闩控制恢复写入，
明确区分提交拒绝、草稿恢复、故障结束和成功重试四个阶段。

Provider 的文本片段数不等于持久化事件数：适配器可以合并相邻片段。验证订阅缓冲区溢出或
跨进程追赶时，订阅已提交事件并确认上一片段落盘后再产生下一片段，不能用比合并窗口略长的
睡眠推算事件数量。取消请求、执行所有者释放、终态发布也属于不同阶段；取消信号缓存请求时的
快照，不承诺已经进入 `aborted`，终态由 Runtime 完成收尾后发布。

不要缩短真实服务的超时来保持一个待观察的阶段：连接中的 MCP 等状态用测试门闩控制，并使用
正常服务超时。编辑保存后用 `wait_for_menu_action` 等待校验和数据发布完成；其他有限 worker
使用 `wait_for_worker_group`，其默认 60 秒仅用于检测包含真实 I/O 的操作是否挂起，不作为执行速度要求。
不要把按键返回当作后台操作完成。执行 worker 结束后，会话观察者仍可能在异步读取摘要或冻结历史；
终态投影也会先于这些操作更新。检查最终历史和交互组件前，使用 `wait_for_observed_status`
同时等待目标状态及观察批次的应用确认，不能只等待 worker、终态字段或 `pilot.pause()`。
同步子代理测试先订阅结果送达变化，确认送达
记录及其审计事件均已发布；送达辅助函数不等待父 Run 完成。需要验证最终输出时再单独使用
`RuntimeSupervisor.wait_run` 跨越父 Run 的挂起/恢复边界。用门闩保持父模型生成，可以验证提交与执行结束解耦；
避免在事件循环里不断读取存储，这会与被等待的提交争用 I/O。

订阅辅助函数必须先检查初始快照，再等待变化，防止目标状态在订阅前已达成而永远等不到新事件。
跨 Host 的交互请求使用 Agent 树订阅，持久化条件使用状态订阅唤醒后在线程中读取。
快照交接测试的线程门闩由测试明确释放，不能在后台线程中靠五秒期限自动放行；异常路径也要释放。
所有者交接的竞争测试应确认响应方实际遇到占用中的锁，不能睡眠后仅以 Task 尚未结束证明竞争。

验证流式内容使用会话历史和当前文本组件，不依赖 SVG 截图中是否能找到字符串；等待新回复时
同时匹配对应的用户输入及完整回复标记，避免旧回复里的相同词语提前满足条件。
切换会话的滚动位置按实际新内容范围截断，不能假定折叠历史后的总高度一定比原滚动位置小：
后台运行可能已追加内容。Windows 凭据权限测试直接通过只读系统 API 检查实际 DACL，保留当前用户、
唯一显式允许规则、完整权限和禁止继承的断言，避免反复启动 PowerShell 混入额外的启动耗时。
SDDL 的权限主体可能使用 `LA` 等缩写；通过 Windows API 解析为完整 SID 后比较身份，不按文本形式判断授权。
跨运行时观察测试先等待指定生产者进入目标执行阶段，再启动观察者；应用启动返回不代表后台调度器已经
取得共享 home 的调度锁。调度选主与接管由独立的任务应用测试验证。

审批预检请求可早于可恢复检查点保存。交互提交通过 Supervisor 的持久化状态订阅衔接此边界；
测试不能通过等待后台生产者完成来绕开面板已经允许输入时的真实竞争。
业务投影更新、交互组件绑定和布局刷新也是不同的完成边界。发送审批按键前，必须确认面板绑定的
请求身份与待处理请求一致、可输入且拥有焦点；读取几何信息前等待 `screen.wait_for_refresh()`。
仅看到投影中的请求或沿用的焦点，不能证明面板已经准备好接收下一次决定。

终端缩放后使用 `tests/tui/helpers.py` 的 `resize_terminal` 等待实际布局完成，再点击控件或断言几何位置。
Textual 会先更新终端尺寸，再异步分发 Resize；`Screen.size` 已变不代表 compositor 中的控件坐标已更新。
不能以 `pilot.resize_terminal()` 返回或 CPU 空闲代替布局完成，也不要通过重试越界点击掩盖这个阶段差异。

操作需要继续等待用户输入时，不能等待所有 worker：模型流、订阅和子对话框本来就会持续运行。
并发竞争使用 Event 或可控制的依赖明确交接，失败路径也必须在 `finally` 中放行并回收资源。
验证去抖、超时预算时优先控制局部时钟，避免用短睡眠推断因果。

## 执行与定位成本

快速领域门禁：

```bash
uv run --frozen pytest -q tests/architecture tests/core
```

完整回归使用锁定的四个独立进程，并在任务耗时不均时分配剩余用例：

```bash
uv run --frozen --extra themes pytest -n 4 --dist worksteal --durations=20 --cov=ouro --cov-report=term-missing
```

每个进程使用自己的 pytest 临时目录。真实存储、同步写入和子进程协议仍参与测试；
不通过全局屏蔽 `fsync` 或放松数据库事务来加速回归。资源较少的机器可以使用 `-n 2`。
功能回归期间保持电脑持续运行，避免睡眠、休眠或合盖挂起。整机暂停会使多个无关 worker
同时出现长耗时，恢复后的测试保护期限和通信期限可能已到期；这种日志不能直接作为运行性能
退化的证据，也不应通过统一延长生产超时、重试或跳过断言来适配。睡眠恢复能力应另设明确的
故障注入场景，验证持久状态和恢复行为。断电降频但未挂起仍是有效的功能回归环境。
CI 在三个系统上执行功能和安装检查，lint、格式及类型检查在独立 Windows job 中执行一次。
静态门禁安装 `themes`，mypy 使用显式 `--platform win32 --no-incremental`：完整源码包含 Windows
原生适配器，类型检查需要相应的标准库声明及可选扩展的实际安装；增量缓存不能作为依赖可用性的证据。
主题扩展源码位于 `packages/tui-themes/src/ouro_tui_themes`，与核心一起参与静态检查。
基础环境门禁验证框架依赖边界和无扩展回退；安装门禁通过 `uv build --all-packages` 构建核心与主题发行包，
分别验证基础安装与 `themes` 整体安装。欢迎页定向回归入口见[样式包开发](welcome-styles.md#验证)。

诊断单个模块时保持串行，避免把竞争负载误当成模块自身成本：

```bash
uv run --frozen --extra themes pytest tests/tui/test_prompts.py --durations=0 --junitxml=results.xml
```

对比耗时应使用同一机器、Python、依赖、参数与用例集合；同时报告删除了哪些用例。
完整覆盖率门槛维持 80%，不为删除视觉测试而排除生产源码或降低门槛。

## 人工视觉检查

修改欢迎页、主题或渲染样式后，在实际终端检查图案、配色、余辉、边框、留白与文本层次，
并切换主题、动画开关和终端尺寸。输入框、命令弹窗应可见且可操作，中文输入和光标应正常。
自动测试继续保护偏好保存、输入和草稿保留、菜单交互、暂停与卸载后的资源回收。

删除测试时记录其失效的需求、被接受的人工检查范围，或继续保护有效断言的测试。
不使用自动失败重试、`xfail` 或宽泛跳过来隐藏尚未理解的失败。

子代理导航的动画帧推进、思考计时显示、切换中间帧、透明度、加粗与右对齐由人工检查。
审批后父 Run 继续执行由排队输入审批测试保护，多子代理集成测试验证
只读权限、草稿保留、最终滚动位置、流式内容、兄弟切换和历史缓存复用。
首次提交测试中的输入框中间帧位置序列也归入人工视觉检查；继续保护焦点、可输入性、
不重复提交、后续草稿和实际队列状态。
