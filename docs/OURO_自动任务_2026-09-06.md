# OURO 自动任务

> 本文提供功能说明与使用入口。规范性契约和验收依据见
> [自动任务规格](../dev/specs/OURO_自动任务规格_2026-09-06.md)。

自动任务是在计划时刻向普通会话提交输入的应用功能。OURO 运行期间调度任务；关闭进程后不唤醒计算机，也不依赖系统计划任务。多个 Host 使用同一 OURO home 时，由一个持有文件锁的进程负责调度，其他 Host 可查看和修改任务。

## 配置与使用

在 TUI 中按 `Ctrl+P`，Tasks 分组依次提供 Manage tasks、Update status 和 + task。`Ctrl+T` 直接打开 Tasks 任务清单，并复用现有菜单导航，不叠加窗口或打断尚未保存的配置编辑。等待、运行中的任务正常显示，暂停、结束的任务低亮显示，均可进入详情。详情的 STATUS 分组提供 History，可查看执行历史并进入会话；CONFIGURATION 分组提供 Edit、Pause（暂停后为 Enable）和使用删除语义色的 Delete；ACTIONS 分组提供 Interrupt 和 Refresh。配置如下：

| 配置 | 契约 |
|---|---|
| Title | 可选，最多 160 字符；未填写时从描述提取展示标题 |
| Instruction | 必填，支持多行自然语言；`Enter` 进入内联编辑或保存，`Shift+Enter` 换行，`Esc` 取消本次编辑。编辑时固定三行并随光标滚动，保存后恢复单行并预览首行内容 |
| Workspace | 必填，必须是存在的绝对目录；保存和执行时均校验 |
| Approval | 默认 `afk`，即 `auto + unattended`；选项名称及说明与 `/approval` 命令菜单共用同一来源 |
| Model / Model thinking | 可选系统默认模型或指定端点；系统默认模型在保存和每次执行时解析，未配置真实默认端点时不可选。新建任务在有系统默认端点时预选“默认模型”，否则要求指定可用端点；编辑时保留已保存的选择。思考设置共用会话模型思考菜单，选项由模型能力决定，切换模型后恢复该模型默认思考配置 |
| Schedule | 每小时、每天、每工作日、每周、每月或自定义 |
| Time zone | 从可搜索列表选择 IANA 时区，例如 `Asia/Shanghai`；系统本地时区置顶，新建表单默认选中它，编辑时保留任务原有时区 |
| Start / End | 开始时间必填、结束时间可选；表单中的日期时间采用所选时区，结束日期包含当天 |
| Session creation | 默认每次新建；可选择复用一个会话，会话删除后重新创建 |

各配置选项页在当前选项前显示主题定义的选定标记，初始焦点定位到该项。

多行内联编辑由 `ouro.tui.inline_editor.MultilineEditableChoiceScreen` 提供。其他配置表单可复用该组件，通过 `Choice.edit_lines` 声明字段高度；值为 `1` 时使用原有单行行为，大于 `1` 时启用多行编辑。组件统一处理 Shift+Enter 换行、多行粘贴、光标移动、固定高度滚动、Enter 保存和 Esc 取消；业务表单只负责字段、预览和保存回调。

任务管理页提供编辑、暂停/启用计划、中断本次执行、删除任务、打开最近会话及最近 50 次执行记录。暂停计划不取消已经接受的执行；中断通过会话的统一取消协议完成。有活动执行时不能删除任务。删除任务保留它创建的会话。

欢迎页 `Task` 固定以前缀 `7/10 completed` 显示执行统计：分子为完成次数，分母为完成与失败次数之和。统计基于保留的执行记录，同一任务多次执行分别累计，不把仅已结束的计划算作成功；中断不计入分母。删除任务会同步移除其执行记录和对应统计。

非零活动数量按 `• 2 waiting • 1 running • 1 approval` 追加在后，全部小写，分别使用低亮色、主题色和提醒语义色；变为零时自动隐藏。连接符使用欢迎页其他项目的低亮连接符颜色。待审批单独统计活动执行的审批状态，不包含手动停用的计划、等待用户输入或运行预算暂停。已保存的执行记录缺少审批标志时按否读取，调度对账或启动恢复后从规范 Run 更新该标志。

任务状态与单次执行结果分开：有活动执行时展示其等待、运行或暂停状态；本次执行结束后，仍启用且有下次计划的任务回到等待，没有后续计划时保留终结状态。成功、失败或中断均不阻止有效重复计划进入下一轮等待。停用计划在活动执行结束后归入暂停；审批、用户输入或运行预算暂停也归入暂停。执行历史独立保留每次结果及失败原因，回到等待不影响完成与失败次数。

在会话菜单中按 `Tab` 切换 `SESSION • USER` 与 `SESSION • TASK`。两个域可为空。任务会话是可交互的主会话，加载历史后从持久化事件水位恢复流；可以审批、发送后续输入、引导执行及中断。子智能体仍使用现有导航和权限边界。

## 执行计划语义

- 每小时在指定分钟执行；每天、工作日、每周、每月按所选时区的时间执行。工作日指周一至周五，不含国家或地区节假日表。
- 每周可选多个星期；未指定时沿用开始日期的星期。每月可选 1–31 日；月份不存在该日期时跳过，不移动到月末。
- 自定义可每 N 分钟、小时、天、周、月重复；天、周、月支持星期过滤，月支持日期选择。分钟和小时按开始时刻的实际间隔计算，日历周期按本地时间计算。
- 开始时刻包含在计划内，下一次执行严格晚于上一次领取时间。结束时刻后不启动新的执行；已经启动的执行可继续完成。
- 本地日历时间在夏令时跳变中不存在时跳过，重复时间只选择第一次。分钟/小时的实际间隔不受时钟回拨影响。
- 进程恢复时，将错过的多个计划合并为一次，随后定位到未来的下一次；不会一次启动大量补跑任务。计划已经结束时不补跑。
- 同一任务不重叠运行，等待审批也会阻止该任务的新执行。复用会话中有用户发起的活动 Run 时暂缓领取；其他任务继续调度。
- 已持久化领取但尚未执行的任务，在进程异常终止后记为中断，不自动重放指令。已挂起的审批保留在原 Run 中，用户进入会话后可继续。执行中的进程退出遵循统一 Runtime 关闭及恢复语义。

这些规则提供原子领取和防重复派发，不声称对外部工具副作用提供 exactly-once 保证。人工重试或继续由用户结合会话历史决定。

## 分层与运行链路

`ouro.automation` 定义任务配置、执行记录、纯日历计算、Repository 协议及文件/SQLite 适配器。任务后端由 `LocalApplication` 组合，默认 `files`，可通过 `OURO_TASK_BACKEND=sqlite` 或 `--task-backend sqlite` 选择 SQLite，命令行优先于环境变量。文件记录位于 home 下的 `tasks/`，SQLite 记录位于 `tasks.sqlite3`。两种适配器只负责持久化、查询、原子提交和版本比较，不决定执行策略。

任务会话始终复用当前 Runtime 的 SessionStore，由既有 `--session-backend` / `OURO_SESSION_BACKEND` 选择；任务记录后端不决定会话后端。四种组合均受支持，例如：

```powershell
uv run ouro --task-backend files --session-backend files
uv run ouro --task-backend sqlite --session-backend files
uv run ouro --task-backend files --session-backend sqlite
uv run ouro --task-backend sqlite --session-backend sqlite
```

切换任务后端不隐式搬迁或混读数据，已有 `tasks.sqlite3` 可显式选择 `sqlite` 继续使用。相同 home 的 Host 应使用一致的任务与会话后端配置；改变后端前先结束活动执行并关闭原 Host。两种任务后端共用该 home 的调度所有权锁。

文件后端将任务、各次执行及可重建的小型索引分开保存，以跨进程短锁、持久化事务意图和原子文件替换保证观察一致性。恢复只完成已接受的文件事务发布，不重放任务指令。任务与统计查询不扫描执行历史，历史以链式记录按页读取；索引丢失或损坏时可从任务记录重建，规范记录损坏则报告错误。文件后端不创建任务 SQLite 数据库。

`TaskService` 负责输入校验、配置修订、计划领取、结束边界和执行结果投影。`TaskExecutionCoordinator` 将已领取指令提交到统一运行链路，并从精确的 Run 身份对账。`TaskScheduler` 只管理调度进程所有权、唤醒和关闭。`LocalApplication` 组合这些服务，先停止领取，再关闭 Runtime，最后保存任务结果并释放调度锁。调度存储故障有诊断、可重试，不阻止交互会话启动。

```text
Task configuration → atomic claim (task + execution)
                   → RuntimeService.create_session / existing Session
                   → RuntimeService.prepare_run → reserve_run
                   → RuntimeSupervisor.submit_prepared
                   → RuntimeService.run_prepared → RuntimeService.run
                   → shared InnerLoop / Tool / HITL / Event / Persistence
```

子智能体的预留 Run 同样使用 `reserve_run` 和既有状态转换。Core 不认识自动任务、执行频率、任务状态或菜单；Session `namespace` 只表达会话域。应用使用 `default` 和 `task` 区分会话域，子会话与分支继承所属域。未指定 namespace 的会话与目录条目使用默认域；其他任务配置格式采用严格校验，任务数据库只接受当前版本。

用户会话创建通过显式 `on_session_created` 回调绑定 Host 身份，不能从并发事件推测新会话。恢复会话时，应用层的共用活动投影用规范 Run 校准已重放事件，因此尚未产生运行事件的排队会话也能正确展示和中断。审批、回答和中断使用 Supervisor 的通用入口；没有针对任务的执行特例。TUI 只读取应用服务及投影，输入自然语言不会绕过模型、工具或审批限制。

## 性能与一致性

- 调度依赖最早截止时间和配置/生命周期信号，正常空闲时最多每 30 秒检查外部修改或进程接管；同进程配置立即唤醒。
- 默认仅派发一个后台任务，复用现有 Supervisor worker，不额外创建模型执行池。后台输入不进入前台输入的模型启动顺序门控。
- 使用到期索引、有界滚动领取窗口、执行历史分页和短事务；忙碌的复用会话不会饿死窗口后的任务。
- 任务状态对账只读取活动任务关联的 Run，不扫描会话消息历史。生命周期信号只触发轻量唤醒，不转发后台 token 到当前用户界面；现有有界订阅负责选中会话的流。
- 选中会话的订阅同时覆盖本地推送与其他 Runtime 的持久化增量。运行中每 100ms 跟踪外部写入，空闲时每 500ms 检查，同会话共享跟踪器，最后一个订阅离开后停止读取；本地连续事件直接推送。TUI 使用同一按帧渲染队列，切换回来先补齐历史再继续接收流。
- 任务与会话存储 I/O 在线程边界运行。结束的执行释放 Supervisor 句柄和无订阅的活动缓存；等待审批不占 worker。欢迎页通过两秒一次的轻量汇总查询更新，计数变化时才刷新。
- 定义、执行记录和下一次计划通过 Repository 的原子提交领取；SQLite 使用数据库事务，文件后端使用可恢复文件事务。配置使用修订号阻止并发覆盖。运行参数在会话执行锁下与 Run 预留一起绑定。

专项测试覆盖日历和时区边界、结束日期、原子领取、进程调度所有权、失败隔离、审批恢复、会话复用及删除重建、前台并发，以及 TUI 配置、会话域切换、静默执行和中途恢复流。
