# AskUser 工具调研

> 文档类型：调研
> 调研日期：2026-07-28
> OURO 映射基线：2026-09-02
> 当前工具与 HITL 行为由现行规格和 `ouro/tools/builtin_ask_user.py` 定义。

## 1. 调研结论

本次对照了三套仍在演进的开源实现：

| 实现 | 请求结构 | 自由输入 | 答案映射 | 值得吸收的设计 |
|---|---|---|---|---|
| [Kimi Code CLI `AskUserQuestion`](https://github.com/MoonshotAI/kimi-code/blob/main/packages/agent-core-v2/src/agent/tools/ask-user-question/ask-user-question.ts) | 1-4 个问题；短标题；每题 2-4 个带说明的选项；支持多选和后台提问 | Host 自动增加 `Other` | 以问题文本为 key | 描述明确限制使用时机；相关问题批量提问；多选交互完整；非阻塞问题可成为后台任务 |
| [OpenAI Codex `request_user_input`](https://github.com/openai/codex/blob/main/codex-rs/core/src/tools/handlers/request_user_input_spec.rs) | 1-3 个问题；稳定 `id`；短标题；每题 2-3 个带说明的选项 | Client 自动增加 `Other` | 以稳定 `id` 映射到答案数组 | 稳定身份与统一数组结果；推荐项约定明确；工具描述强调非阻塞问题与必答问题的区别 |
| [Gemini CLI `ask_user`](https://github.com/google-gemini/gemini-cli/blob/main/docs/tools/ask-user.md) | 1-4 个问题；`choice`、`text`、`yesno`；选择题 2-4 个选项；支持多选 | 选择题和确认题自动增加 `Other` | 以数组下标映射 | 多种交互类型与多选；CLI 对问题、选项、回顾和取消有专门呈现 |

三者的共同点不是某个具体 UI 控件，而是同一个协议方向：模型提交的是有边界的“问题集合”，Host 负责呈现和收集，答案以结构化数据回到原工具调用。单个无约束字符串会同时损失模型约束、Host 呈现能力和稳定的答案映射。

## 2. OURO 的底层判断

OURO 的 `ToolInputRequest` 是通用挂起边界：任意 resumable 工具都能用 opaque JSON 挂起 Run，Core 不解释工具私有
请求和答案。AskUser 是该协议的内置生产者，不拥有专用 Run 状态机、事件协议或工具恢复流程；CLI/TUI 只适配其
类型化问题结构。

调研基线中的旧 AskUser 参数存在以下问题：

- 旧参数 `question: any` 没有表达问题身份、显示信息、候选项或选择规则；
- CLI 只能打印原始 JSON 并读取一行，Host 没有真正适配请求语义；
- 字符串、数组下标和问题全文都不是可靠的答案身份，问题文案调整会破坏映射。

## 3. OURO 采用的契约

AskUser 参数固定为 1-3 个相关问题。每题包含：

- `id`：最长 32 字符的 lower-case snake_case 稳定标识；
- `header`：最长 12 字符的 UI 短标题；
- `question`：清晰、具体的问题；
- `options`：2-4 个 `{label, description}`；
- `multi_select`：仅在多个独立选项可以同时成立时启用，默认 `false`。

示例：

```json
{
  "questions": [
    {
      "id": "database",
      "header": "Database",
      "question": "Which database should the service use?",
      "options": [
        {
          "label": "SQLite (Recommended)",
          "description": "Keep local setup simple and dependency-free."
        },
        {
          "label": "PostgreSQL",
          "description": "Support concurrent production workloads."
        }
      ]
    }
  ]
}
```

Host 请求使用 `type: "ask_user"` 判别字段，模型参数不重复提供它。CLI/TUI 自动增加 `Other`，最终统一返回：

```json
{
  "answers": {
    "database": ["SQLite (Recommended)"]
  }
}
```

单选和多选都使用数组，避免消费者分支判断；稳定 `id` 使答案不依赖问题顺序或展示文案。

## 4. CLI 适配边界

CLI 是 Host adapter，只负责：

1. 识别内置 AskUser 的判别式请求；
2. 逐题展示标题、问题、选项说明和自动 `Other`；
3. 解析编号、逗号分隔多选、选项标签或自定义文本；
4. 拒绝空答案，保留 `/abort` 和 EOF 语义；
5. 主 Run 与子智能体使用同一个收集器，按问题 `id` 生成结构化答案。

通用插件工具的 opaque JSON 交互继续走原来的通用文本/JSON fallback，AskUser 的产品交互不会反向污染 Core。

## 5. 刻意不引入的能力

- 不增加第二套交互状态机或 AskUser 专用持久化结构；
- 不兼容旧的 `question` 参数，错误调用由统一 JSON Schema 边界明确拒绝；
- 不增加 `background` 参数。Kimi Code CLI 用独立后台任务、自动通知和任务停止协议承载它；在 OURO 当前阻塞式 ToolCall 上只增加布尔开关会形成不可恢复的半套语义；
- 不增加超时默认选择。OURO 已用显式 `interactive | unattended` 表达用户是否在场，隐式超时会引入另一套不确定策略；
- 不增加秘密输入字段。在 CLI 提供可靠的隐藏输入和持久化脱敏前，声明该能力会制造错误的安全保证；
- 不增加独立 `text`、`yesno` 类型。2-4 个具体选项加 Host 提供的 `Other` 已覆盖当前决策场景，并保持模型 schema 与 CLI 状态机简洁。
