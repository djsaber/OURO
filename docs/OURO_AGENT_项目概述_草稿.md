# OURO Agent 项目概述

## 项目定位

OURO Agent 定位是个人通用智能体，基于 Harness 工程和 Pi Agent Core 设计哲学，遵循最简核心实现+最大可拓展性方案构建，为 AI 搭建一套完善可拓展的运行环境，实现个人自动化。OURO 作为个人通用智能体，优先保证个人用户体验、可靠性与可玩性以及拓展性，不追求企业级的安全隔离、审计、高可用与服务化以及复杂优化，OURO 实现精简但完善的核心框架以及高度可拓展的插件系统，以支持未来高级特性通过插件系统集成。

## 设计哲学/原则

1. 核心极简：仅提供智能体运行所必需的、通用的底层能力。
2. 能力自生长：缺失的能力可由 OURO Agent 自行编程实现。
3. 插件原生：能力扩展通过插件机制完成，开发者与用户均可贡献能力，插件实现系统高度拓展性。
4. 前后端分离：核心与所有能力以无 UI 依赖的形态存在（可被 CLI / SDK / RPC 等任意复用）。
5. 避免过度设计：不为臆想的需求预留复杂抽象。

## 设计取向

- 最简内置 + 插件扩展：核心只提供够用的最简实现，复杂/高级策略通过插件按需增强。
- 可组合优先于可配置：能力通过组合中间件/工具达成，而非堆砌配置开关。
- 事件驱动：内部状态变化以有序事件流对外暴露；事件流是 UI 渲染与回放的唯一真相来源。
- 能力自生长：支持让 Agent 自己写工具/脚本补全能力。
- 追加只写：原始历史永不物理丢失；任何压缩/裁剪仅作用于"发送视图"，不破坏存储原文。
- 可恢复性：任意中断（崩溃、用户中止、HITL 挂起）后，会话都能正确恢复，不出现损坏状态。

## 技术栈

| 层 | 技术 | 说明 |
|---|---|---|
| 语言 | Python 3.12+ | 核心与全部能力层 |
| 基础运行框架 | OURO 自研 Runtime / Provider / Tool / Event 基础设施 | 自主维护智能体运行闭环，作为核心引擎 |
| 持久化 | JSONl / SQLite | 会话状态持久化，内置最简，插件拓展其他数据库支持 |

> OURO 自主构建智能体运行基础设施，核心价值集中于稳定的运行闭环、事件模型、持久化恢复、人机协同、扩展生态与前端实现。

## 核心概念

### 智能体循环（Agent Loop）

OURO 的核心运行机制为一个状态机式循环：

1. 接收输入：用户提示 / 转向消息 / 跟随消息 / 恢复信号。
2. 组装上下文：系统提示（可经插件改写）+ 历史（经转换/压缩）+ 工具定义。
3. 调用模型：流式获取助手响应（文本 / 思考 / 工具调用）。
4. 模型响应后处理：插件可改写响应、注入消息、改变控制流（继续 / 终止 / 重新回到模型）。
5. 执行工具：解析工具调用，经解析/校验/确认后并行或串行执行。
6. 结果回灌：工具结果作为新消息加入历史，进入下一回合。
7. 停止判定：无工具调用 / 工具主动终止 / 智能体挂起（工具批准 / 向用户提问） / 应停止钩子 / 错误 / 被中止 → 结束运行。

### 事件模型（Event Model）

系统采用事件驱动架构。事件流是 UI 渲染、可观测性、记录回放的唯一真相来源。订阅者监听事件流；
订阅者的异常不得中断主循环。一次运行产生一条有序事件流，事件类别覆盖循环全生命周期与人机协同：

- 生命周期：运行开始 / 结束；回合开始 / 结束。
- 消息：消息开始 / 更新（流式增量）/ 结束。
- 工具：工具执行开始 / 更新（部分结果）/ 结束（含成功 / 失败 / 被拦截 / 终止）。
- 人机协同：HITL 请求 / 应答；智能体挂起 / 中止。

### 中间件模型（Middleware Model）

系统通过可组合的类型化中间件链实现核心可扩展性，而无需修改循环本身。中间件在循环各阶段注入行为，每个钩子点有明确的组合语义。
OURO 至少支持以下类别的钩子点及其组合规则：

| 钩子点 | 触发时机 | 组合语义 |
|---|---|---|
| 上下文改写 | 每次模型调用前，作用于消息列表 | **链式**：每个中间件接收上一个的结果 |
| 系统提示改写 | 每次模型调用前，作用于系统提示 | **链式** |
| 消息格式转换 | 序列化发送给模型前 | **末位生效**：仅最后一个实现生效 |
| 工具调用改写 | 每次工具调用，校验前，可改写调用 | **首个非空生效**：首个返回非空者短路 |
| 工具执行前拦截 | 每次工具调用，参数校验后（可拦截/改参/请求确认） | **任一拦截即停止** |
| 工具执行后改写 | 每次工具调用，执行后 | **末位覆盖**：后执行者覆盖先执行者 |
| 模型响应后控制 | 助手消息落地后（可改写响应/注入消息/改变控制流） | **末位决策生效，注入消息累加** |
| 回合停止判定 | 每个回合边界 | **任一为真即停止** |
| 运行结束注入 | 全部回合结束后、运行结束前 | 注入消息累加；**非空注入触发一次额外回合** |

## 功能特性

### 核心功能

1. 智能体循环
- 系统实现完整的智能体循环：输入 → 模型流式响应 → 工具调用解析 → 工具执行 → 结果回灌 → 循环/停止。
- 循环支持流式输出。
- 循环支持并行工具执行与串行工具执行**两种模式，且能按工具声明的执行模式自动切换。
- 循环正确处理停止条件：无工具调用、工具主动终止、智能体挂起、应停止钩子、错误、用户中止。
- 循环维护工具调用与工具结果的邻接不变性，以兼容严格校验的模型。

2. 事件流
- 循环在各关键节点广播标准化事件。
- 事件携带足够信息以供 UI 流式渲染。
- 必须订阅者监听事件流，且订阅者的异常不得中断主循环。
- 事件区分"被钩子拦截"与"其他即时错误"两种失败原因。

3. 转向与跟随
- 支持在运行过程中插入转向消息（Steering），引导智能体改变方向。
- 支持跟随消息（Follow-up），在运行结束后排入下一条输入。
- 转向/跟随支持"逐条"与"全部"两种排空策略。
- 支持按标识撤销尚未排入的转向消息。

4. 中断与恢复
- 必须支持中止（主动中断）：用户可在任意时刻中断当前运行，工具应答不能阻塞中断行为。
- 任意中断（中止/崩溃/HITL 暂停）触发后，必须保证会话历史的一致性（为未应答的工具调用补充合成结果，避免历史损坏）。
- 任意中断触发后，会话必须能被正确恢复(为悬挂的工具调用回填合成工具结果，使会话可继续)。
- 中止/出错的运行不得破坏会话可恢复性。

5. 中间件编排
- 必须支持挂载多个中间件。
- 中间件提供的工具必须自动并入智能体可用工具集。
- 中间件声明的外部 LLM 调用必须被可观测性系统正确归属。
- 显式传入的钩子与中间件链提供的钩子必须以可预测方式协作。

### 扩展系统

插件作为高级能力载体：插件可提供工具与中间件，从而承载核心未内置的高级策略——例如参数级/路径级权限规则（工具执行前拦截中间件）、增强版上下文压缩（上下文改写中间件）、OS 级沙箱化命令执行（自定义 Bash 工具）等。核心保持最简，复杂能力按需以插件增强。

1. 插件系统
- 原生支持插件机制以全面扩展系统能力。
- 插件可贡献：工具、斜杠命令、中间件、技能、UI 扩展点等多维度领域。
- 插件遵循统一的扩展契约，与核心解耦。

2. 命令系统
- 支持 Slash 命令（如 `/help`、`/model`、`/tree`、`/fork`）。
- 命令必须可被插件扩展。

### 模型供应商

1. 多供应商支持
- 必须支持主流模型供应商：OpenAI、Anthropic、Google 等，以及兼容 OpenAI/Anthropic 接口的第三方模型供应商。
- 必须支持自定义模型供应商，便于接入私有部署或代理。
- 必须提供测试用替身供应商（无网络、可预设响应），便于无 API Key 的离线开发与测试。

2. 模型配置
- 每个模型端点必须可独立配置：上下文长度、最大输出 tokens、温度、采样参数等。
- 必须支持思考/推理等级配置，并按供应商能力正确映射。
- 必须支持供应商能力描述：声明模型是否支持工具调用、图像输入、流式输出。

3. 模型管理
- 必须提供模型供应商管理，支持添加/删除/更新模型供应商配置。
- 必须提供模型端点管理，支持添加/删除/更新模型配置。
- 必须支持查看系统配置的模型供应商和模型端点信息。
- 必须支持运行时切换当前会话所用模型。

4. 模型调用
- 支持结构化输出：以给定 schema 约束模型输出，并校验。
- 调用时自动提取输入 Token（缓存命中/未命中） / 输出 Token。
- 自动统计模型历史累计费用（Token）消耗。

### 人机协同

OURO 提供最简的人机协同：在关键节点暂停、向人类请求确认/提问、再恢复执行。

1. 审批与提问
- 审批策略：
  - 自动批准：OURO Agent 可直接调用工具，无需人工干预。
  - 手动逐次批准：每次工具调用前弹出确认框，用户点击"同意"后才执行。
  - 会话内自动批准：用户在一次会话开始时自动批准某类工具，后续该会话内自动放行。
- 提问：OURO Agent 可以自主分析，在关键决策节点调用工具向用户发起提问。
- 提问/审批支持无限期挂起，保存状态随时可继续任务。
- 提问/审批支持超时设置；取消/超时以可被模型理解的工具结果形式返回。
- 支持工具的自动批准权限配置，已配置为自动批准的工具不触发用户审批。

2. 暂停与恢复
- HITL 请求能挂起当前运行状态，释放执行（如分离到后台）。
- 挂起的请求可恢复：人类应答后从挂起点继续。
- 可跨进程持久化挂起状态：即使进程重启也能恢复。
- 支持中止挂起的请求，并优雅关闭会话（合成拒绝结果 + 终止消息）。
- 支持幂等恢复：恢复途中崩溃可再次恢复，不重复执行已应答的部分。

### 上下文管理

1. 系统提示
- 必须支持可配置的系统提示词，作为智能体行为基线。
- 必须支持中间件在运行时动态改写系统提示。

2. 上下文组装与消息转换
- 必须将系统提示、对话历史以及其他状态信息等组装为完整上下文。
- 必须支持消息转换层：在发送前对消息做最终格式调整（发送者归因、合成消息标记）。
- 必须区分真实用户消息与框架注入的合成消息（如压缩摘要、转向、上下文脚手架），避免 UI 把内部脚手架渲染成用户发言。
- 必须支持指定工具/技能（用户/命令指定工具/技能）上下文构建。
- 必须支持启动或关闭长期记忆（用户/命令启用或关闭记忆）上下文构建。
- 必须支持计划模式（用户/命令开启计划模式）下的上下文构建。
- 必须支持子智能体模式（用户/命令开启探索模式）下的上下文构建。

3. 上下文压缩
- OURO 内置基础上下文压缩：调用 LLM 摘要旧回合、保留近期尾部，失败直接触发错误，不内置降级策略。
- 支持自动压缩：达到模型上下文尺寸的 80% 时自动触发上下文压缩。
- 支持手动压缩：用户/命令显式触发，立即执行。
- 插件支持：通过插件高度自定义上下文压缩实现。

### 会话管理

1. 持久化后端
- OURO 内置提供基于 JSONL / Sqlite 两种类型的会话持久化后端，可通过插件拓展更多类型的持久化后端支持。

2. 实时读写
- 每次写入完整会话时可以保存会话状态和会话消息。
- 每条消息产生时实时增量写入，保证崩溃后可恢复。
- 每次状态变更时实时更新状态数据，保证重新恢复后状态一致。
- 支持会话的惰性加载：首次访问时从后端恢复历史与状态。

3. 多会话支持
- 支持多会话并发存在与切换。
- 支持会话的创建、列表、切换、删除、重命名、归档。
- 每个会话内部进行的对话、停止、转向等操作，以及运行状态、错误、恢复等，彼此独立互不影响。
- 同一会话的并发用户输入通过转向/跟随排队处理，不并发冲突。

4. 会话树与分支系统
- 会话为树结构，会话树固有一个根节点，根节点是程序节点，作为整个会话的起始锚点，非会话消息。
- 除根结点外，会话树的每个节点对应一条会话消息，分为系统消息/骨架消息/用户消息/智能体消息/工具消息五类：
    - 系统消息: 配置 Agent 系统上下文信息。
    - 骨架消息：OURO 的系统脚手架消息，配置特定信息（构造输入消息、压缩信息、转向消息等）。
    - 用户消息：用户输入（指令、附件等）。
    - 智能体消息：Agent 行动每一步输出的消息。
    - 工具消息：工具执行的消息。
- 支持在会话树指定节点处派生新会话，复制该节点到根节点的完整路径，构建新的独立会话。
- 支持在会话树指定节点处新建分支节点。
- 支持维护会话树的分支切换状态：新输入总是追加到当前切换的分支路径。
- 新建会话分支时，原分支完整保留，不破坏、不丢失，可切换回去。

### 工具管理

1. 内置工具
- Read：文件系统数据提取（含行号、图片转 Base64、Glob 目录结构解析）。
- Write：创建新文件或覆盖现有文件，自动创建父目录。
- Edit：基于严格字符串替换（非 AST 操作），支持模糊匹配。
- Bash：同步终端命令执行，捕获 stdout/stderr/exit code，内置超时。
- AskUser: 向用户提问，支持确认、多选项、多选、自由输入。
- SetTodoList：管理任务进度列表。
- Agent：创建或恢复子代理实例。

3. 工具配置
- 工具命名：支持设置工具别名。
- 权限配置：支持设置工具权限：自动执行 / 需要确认。
- 持久化：配置可以持久化。

2. 工具拓展
- 插件拓展：支持通过插件拓展 OURO Agent 可用工具。
- MCP：支持通过MCP拓展 OURO Agent 可用工具。
- 来源标记：自动标记获取工具来源信息。

3. 工具执行
- OURO 所有工具走统一的工具执行入口。 
- 用户中止时能在传输超时前响应，而非阻塞至超时。
- 标准结构化格式响应工具执行结果（文本/图像/音频/资源等）。

4. 工具组
- 支持工具组（渐进式披露）：将多个工具打包为工具组，按需加载，隐藏任务无关的工具，改善工具数量较大时 Agent 理解能力下降的问题。
- 工具组管理：支持创建/删除工具组，以及启用/关闭工具组，配置可以持久化。
- 
- 支持两种策略：
  - 分发：工具数组与系统提示在整次运行中字节稳定，调用经分发器路由（零缓存失效，推荐默认）。
  - 注入：加载的工具加入模型可见工具数组（原生调用，每次扩展重读缓存）。
- 加载器对每组每运行只执行一次，结果缓存；后续选择性加载从缓存过滤。
- 工具组在系统提示中以**紧凑目录**形式呈现（组标识、展示名、描述、工具名列表）。
- 按需加载整组或组内指定工具（如内置 `load_tools`）。

### 子智能体

OURO Agent 采用 Agents As Tools 模式：系统通过将子智能体暴露为工具，主智能体以工具调用形式发起子智能体任务执行，返回执行结果后主智能体继续推理。子智能体拥有自己完整的智能体循环，子智能体内部的工具调用不出现在主智能体的工具调用序列中。OURO Agent 系统设计应当充分提供拓展的预留边界，全面支持通过插件实现更高级的 Sub Agent 方案。

1. 创建和调用
- 主智能体以标准工具调用（仅主智能体可见）接口创建子智能体。
- 每个子智能体拥有独立提示词配置、会话历史以及状态空间等。
- 子智能体继承主智能体的可用工具集及中间件配置。
- 子智能体继承著智能体的审批策略。
- 支持覆盖设置子智能体系统提示词、可用工具集、审批策略等。
- 子智能不可递归创建子智能体，Agent工具对子智能体不可见。
- 子智能体不可以向用户提问，AskUser工具对子智能体不可见。

2. 事件集成和结果回灌
- 子智能体产生的事件流必须穿透层级边界，汇入父智能体的事件总线。
- 事件必须携带标识，确保 UI 能完整渲染嵌套执行轨迹。
- 子智能体运行结束后，其结果必须以结构化方式回灌到主智能体，保持工具调用与工具结果的邻接不变性。
- 子智能体崩溃、超时或异常被包装为标准化工具结果返回，触发优雅终止并返回结构化结果。

3. 透传机制
- 子智能体内部工具审批会透传到顶层触发 HITL，前台标记标明触发源。
- 审批发生在运行层面，无论是当前主智能体还是子智能体执行中人机交互，都通过相同的外层运行中断流程处理。

4. 终止和恢复
- 主智能体被中止时，必须级联中止所有活跃子智能体及其后代，不得有孤儿进程。
- 子智能体的阻塞操作（如等待工具结果、等待用户输入、长时 LLM 调用）不能阻塞主智能体中断信号。
- 子智能体的运行状态（历史、挂起工具调用、内部变量）必须能被持久化，支持跨会话恢复。
- 恢复后，子智能体与父智能体的调用关系、事件订阅链路必须被正确重建。

### MCP 集成

1. 服务器生命周期
- 创建与删除：支持 MCP 服务器的创建与删除。
- 连接与断开：支持 MCP 服务器的连接与断开。
- 多传输方式：stdio 与 HTTP（SSE/Streamable HTTP）。
- 支持查看 MCP 服务器的状态。

2. 服务器配置
- 可以为每个 MCP 服务器配置环境变量。
- MCP 配置可持久化。

### Agent Skills 集成

- 自动探测可用技能：包括全局技能与当前目录技能。
- L1：加载可用技能元数据（技能路径 + SKILL.md 头部信息）。
- L2：加载指定技能指令（技能目录树 + SKILL.md 完整内容）。
- L2/L3：OURO Agent 自动调用系统工具查看文档、执行脚本等操作。
- 支持指定技能的启用与关闭，启用状态可持久化。

### 长期记忆

- OURO Agent 不内置实现记忆模块功能，但保留拓展接口，支持插件拓展实现长期记忆。
- OURO Agent 支持跨会话的长期记忆机制（如用户偏好、事实积累），在上下文组装时注入。

### 运行模式

OURO Agent 提供五种运行模式，覆盖从终端到桌面、从脚本到嵌入的全场景。所有模式共享同一核心，仅宿主层不同。

1. Interactive（交互模式）
- 基于文本用户界面（TUI）。
- 支持多会话管理、流式输出、工具调用可视化。

2. Print / JSON（一次性执行模式）
- 无交互的一次性执行。
- Print：返回纯文本结论。
- JSON：返回结构化事件流，便于下游解析。

3. RPC（远程过程调用模式）
- 启动时进入 JSON-RPC 服务循环，经标准输入输出与宿主进程通信。
- 支持请求/响应与 Server-Sent Events（SSE）两种子模式。
- 便于编辑器插件或本地代理中间件接入。

4. SDK（编程嵌入模式）
- 以编程方式初始化会话、发送消息、监听事件。
- 不依赖全局配置，适合服务端批量任务或构建上层应用。

5. Desktop（桌面应用模式）
- 基于 HTML+CSS+JS 的独立桌面应用。
- 在 SDK 能力之上提供：图形化会话管理、文件拖拽、本地模型配置、系统级快捷键。
- 与 CLI 共享同一核心，仅 UI 层不同，确保行为一致。

### 配置管理

- 支持全局配置（用户级，跨项目生效）。
- 支持目录/项目级配置（当前工作目录，覆盖全局）。
- 配置涵盖：模型供应商与端点、MCP 服务器、技能启用、工具权限、系统提示、运行参数等。
- 可持久化配置，重启后恢复。

### 可观测

- 所有运行产生标准化事件流。
- 支持基于分布式追踪的调用追踪，层次为：智能体调用 → 回合 → 模型对话 / 工具执行；嵌套子智能体调用应正确嵌套。
- 追踪能正确归属中间件发起的外部 LLM 调用。
- 默认不记录提示/模型输出内容；需显式开启并提供脱敏回调。
- 支持 token 用量、调用次数、延迟、错误率、首字节延迟等度量。
- 支持记录一次运行的完整事件流，并能离线回放/分析（如 `trace` 命令）。
