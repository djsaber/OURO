# 模型订阅支持

OURO 通过产品连接声明、认证驱动和协议适配器组合接入订阅服务。首批内建产品为
`openai-codex`，使用浏览器登录、受限本地文件保存凭据和 Responses 协议；API Key 产品保持独立。
此集成采用已验证的公开 Codex OAuth 客户端兼容流程，不表示 OpenAI 官方对 OURO 的支持承诺。

当前模板提供已实测的 `gpt-5.5` 文本、工具调用和完整加密 reasoning 续接。未开放设备码、图像、
结构化输出或 reasoning 等级控制。模板的 context_window=128000 是本地规划值，不是已经测得的
服务最大上下文。单一 max_output_tokens=8192 用于本地上下文预算；此服务不接收请求输出上限，
实际输出可能超过预算。CLI/TUI 的服务说明会明确标注这一点。

## 创建与登录

首次正式闭环验收建议使用独立 home。以下 PowerShell 命令不改变已有 OURO 配置；后续所有命令使用
同一个 home。若已经创建 personal 实例，直接执行登录，不要重复 add 或 replace。

```powershell
$subscriptionHome = Join-Path $env:LOCALAPPDATA 'OURO-subscription-check'
uv run --frozen ouro provider add personal --type openai-codex --default --home "$subscriptionHome"
uv run --frozen ouro provider auth login personal --method browser --open-browser --home "$subscriptionHome"
uv run --frozen ouro provider auth status personal --home "$subscriptionHome" --json
uv run --frozen ouro provider check personal --home "$subscriptionHome" --json
```

浏览器回调后等待终端显示 Login succeeded，才表示凭据已保存。成功的 status 应为 ready；status 仅查询
本地状态，不验证账户当前权益。check 会发出模型请求，应返回 ok=true。独立探针不保存凭据，因此其
登录成功不能代替此处正式登录。无需导入 Codex/ChatGPT 客户端缓存，也不要手工编辑凭据文件。

## 使用、重启与续接

```powershell
uv run --frozen ouro run "只回复 OURO_OK" --home "$subscriptionHome" --json
```

保存输出中的 session_id，重新启动命令，用该 ID 续接同一会话：

```powershell
uv run --frozen ouro run "请复述刚才的回复" --session <session_id> --home "$subscriptionHome" --json
```

TUI 使用 `uv run --frozen ouro --home "$subscriptionHome"`。从 Manage providers 进入 personal，再进入
Authentication 可查看状态、登录和注销。未登录仍能启动和进入管理界面；请求时才返回认证错误。
现有工具循环、分支、恢复、压缩和子会话路由共用该认证组合；不另外建立订阅专用执行流程。

材料临近到期时自动刷新；模型请求首次 401 且尚未输出时，在既有重试预算内恢复认证。普通刷新保持
账户 scope，不使历史续接失效。失效凭据要求重新登录；认证失败不会切换到 API Key 或另一计费服务。
订阅请求仍记录实际 token，用量金额未知时不显示为零费用。

## 注销验收

```powershell
uv run --frozen ouro provider auth logout personal --home "$subscriptionHome" --json
uv run --frozen ouro provider check personal --home "$subscriptionHome" --json
```

注销清空本地材料；此后 check 应返回 authentication_required，不发出模型请求。重新执行登录命令
即可恢复使用。注销不会退出浏览器上的 ChatGPT，也不调用远端全账户登出。

## 证据范围

正式 adapter 的真实 Windows/browser/gpt-5.5 登录、刷新、两轮工具和跨刷新加密 reasoning 重放已经通过，
见[真实探针摘要](../dev/probes/README.md#正式-adapter-验证)。正式注册路径的自动集成测试使用合成 HTTP
与真实本地回调、凭据文件和文件/SQLite 会话存储，覆盖登录保存、重建、401 刷新续接、工具执行、
用量归属、注销和禁止凭据发送到其他目标；CLI/TUI 验证产品创建、限制披露及未登录管理/结构化失败。

2026-09-19 在 Windows 上使用独立 home、内建模板与用户完成的浏览器登录，正式 CLI 已通过真实账户验收：

| 验收步骤 | 结果 |
|---|---|
| 持久登录 | succeeded，凭据 revision=1 |
| 新进程 provider check | ok=true，gpt-5.5 |
| 首次 run | completed，回复 OURO_OK；实际用量 6205/7 input/output tokens |
| 新进程按 session_id 续接 | completed，复述 OURO_OK；实际用量 6225/7 input/output tokens |
| 本地注销 | logged_out，revision=2，清空到期时间与身份 |
| 注销后 check/status | authentication_required / logged_out |

上述 Host 验收没有强制真实凭据过期；真实刷新及加密 reasoning 重放由正式 adapter 探针单独验证，
自动 401 恢复由合成 HTTP 集成测试验证。测试同时覆盖 unattended run 与自动任务未登录时的结构化错误，
以及登录、重建后使用现有 continue_run 恢复相同 Run；不会为后台任务打开浏览器。

其他模型、设备码、实际上下文极限、其他账户/区域和 POSIX 文件保护不由本次结果推断为已验证。
