# 升级已有用户数据

> 文档类型：使用指南

`ouro-upgrade` 提供离线核心数据升级，在指定 home 的原位置操作。它随当前 `ouro-agent` 安装，
不会升级 OURO 程序。支持的历史格式、保留范围与故障边界见[数据升级规格](../specs/data-upgrade.md)。

## TUI 自动升级与失败数据清理

TUI 启动遇到数据版本错误或已识别的旧提供方能力配置时，会关闭本次启动的服务，自动对当前 home 和所选 Session / Task 后端执行升级。
界面在终端中央显示识别、准备、源数据复核、发布和收尾阶段。文件后端识别显示已完成的会话或任务数，准备、复核和发布显示修改集合的文件数，
完整目录删除计为一个修改项，并使用当前主题的加载动画提示仍在处理。计数表示当前阶段，不能换算为整体进度；较大的单个会话仍可能需要较长检查时间。
升级成功后重新加载主页；原来的 `--session` 选择不会自动打开。正常启动不执行全目录升级检查，主页可用不代表所有历史会话的上下文和摘要记录都已是当前格式。需要检查整个所选后端时，使用下文的 `--check`。

单项升级失败时，其他独立数据继续升级，成功结果会保存。界面列出失败范围和原因，提供重试、退出；
能够确定删除范围时还提供“删除失败数据并重试”。默认选择退出，删除需要再次确认，确认界面默认选择取消。
取消或退出会保留失败项的原数据以及已经成功升级的数据。

删除粒度如下：

- 文件会话：单个会话及其所属记录；文件任务：单个任务及其执行历史与防重标记。
- SQLite 会话：整个会话数据库及其日志文件；文件会话的共享布局无法识别时，边界为整个 `sessions/` 目录与 `layout.json`，包括该目录内的会话及附件。
- SQLite 任务：整个所选任务库；文件任务的共享布局无法识别时，边界为整个 `tasks/` 目录。
- 提供方配置：`config/providers.json`；用量：整个用量账本。凭据及其他配置不在删除范围。

确认后会重新检查，只有仍然失败且已确认的单元才被删除；已修复的数据保留，新出现的失败需再次确认。
删除项会从正常存储移入维护备份，失败边界外的数据、插件、回收站和既有备份保留。恢复界面不提供全量清空 home 的操作。
缺少会话记录、未知版本、数据库结构损坏及未完成的单元内事务均可在确认后放弃。共享容器失败会明确以容器为删除单位，
不会逐条猜测哪些内容仍可用。锁、权限或磁盘写入失败需要先解决环境问题，不会因此删除业务数据。

写回或清理中断且有恢复标记时，可选择恢复该次操作并重新升级；此前完成的成功升级不回退。
界面沿用当前主题和菜单键盘操作，居中显示，无边框、无遮罩。一次启动只自动尝试升级一次，避免失败后循环重启。

操作前关闭使用同一 home 的其他进程。当前标准 CLI/TUI 会通过共享/独占锁拒绝与维护操作同时运行；
旧版 OURO、直接使用 Store 的脚本及嵌入式调用仍需自行停写。处理中不能通过菜单取消，避免后台写入与重新启动重叠。

## 命令行升级

先更新 OURO 程序并关闭所有使用此 home 的 OURO 进程及外部写入者。保留独立备份，确认有足够空间存放
新产物和数据库临时文件。升级将实际修改集合的原文件移入备份目录，工作区和业务文件必须位于同一文件系统；独立完整备份由用户自行管理。

以下为 PowerShell 示例，请替换实际 home：

```powershell
# 检查受支持的核心格式与所需修改
ouro-upgrade --home 'C:\data\ouro-home' --check

# 在该目录内升级
ouro-upgrade --home 'C:\data\ouro-home'

# 按原来的后端启动同一目录
ouro --home 'C:\data\ouro-home'
```

源码环境使用 `uv run --frozen ouro-upgrade ...`，或在已安装依赖的环境中使用
`python -m ouro_upgrade ...`。`--home` 必填，工具不会选择目标目录或搬运整个 home。

Session / Task 后端都默认 files，可分别由 `OURO_SESSION_BACKEND`、`OURO_TASK_BACKEND` 或命令行覆盖。
若原启动选择了 SQLite，应使用相同选择，例如：

```powershell
ouro-upgrade --home 'C:\data\ouro-home' --session-backend sqlite --task-backend sqlite --check
ouro-upgrade --home 'C:\data\ouro-home' --session-backend sqlite --task-backend sqlite
```

升级包含 `config/providers.json` 中旧端点能力与 reasoning 配置的转换。
保留连接设置、凭据引用、原生请求映射、默认行为和用户自定义内容，并维护实例模板绑定所用的基线。
不会自动添加摘要能力或刷新认证。旧 default_effort 与 default.effort 同时存在且不同时，
需先明确保留哪个默认值，工具不会自行取舍；失败文件保留原样。
本地模板文件由正常模板加载流程管理：结构版本过旧时，先备份原文件，再按当前内置目录创建新版本文件，
旧自定义模板与覆盖内容保留在备份中。模板文件不参与离线数据升级。
不会合并或转换未选后端。回收站、旧维护备份、其他配置、凭据及插件私有数据保留原样；成功不代表这些内容
或全部历史执行可用。未知核心版本会明确拒绝；转换结果会校验，已经是当前格式的记录保留原样。
升级不审计当前容器、附件内容或任务防重标记，也不修复已有数据损坏。
缺失的时间、工具绑定和 Harness 使用已有记录或默认值补齐；跨会话委派保留有效关联。
已消费队列标记、旧派生计数和未生效工具变更提案直接丢弃。
已保存的工具结果直接转换，运行中且结果未知的调用标记为可恢复，历史消息继续可读。
文件 layout 9、41 与 SQLite schema 7、26 均可升级至当前格式。原生容器只调整必要的表结构与输入状态，
消息、工具结果、请求正文与草稿保持原内容，不重算历史。会话通知日志不进入当前格式，原库或文件保存在升级备份中。
原生文件会话部分失败时，home 版本号等待剩余单元完成；重试不重复转换已完成的会话。

## 结果和恢复

命令行采用严格模式，任一转换失败均停止发布；TUI 采用上述隔离模式。
命令输出 JSON：`upgrade_required` 表示检查通过且需要升级，`current` 表示无需改写，`upgraded` 表示
本次受支持的核心数据升级完成。TUI 报告中的 `partial` 表示仍有失败单元，
`failures` 列出原因和是否可删除，`discarded` 列出实际删除的单元。已发布操作的报告位于 `.upgrade/receipts/`，其中列明修改文件和备份位置。
确认使用正常后，可自行清理报告所指的备份目录；有未完成升级时必须保留恢复材料。

如果写回中断，`.upgrade/in-progress.json` 会阻止 Runtime 使用此 home，TUI 会进入恢复界面。
保持其他写入者停止，也可以执行：

```powershell
ouro-upgrade --home 'C:\data\ouro-home' --restore
```

`restored` 表示整个修改集合已恢复为升级前内容。排除失败原因后重新执行升级。不要手工删除升级中标记
绕过保护。中断时部分原文件可能已经移入备份，部分仍在原位置，工具会在恢复前核对整个修改集合；若无法找到与原始摘要一致的数据，
工具停止恢复，需要使用独立备份处理。恢复不支持对已经成功升级且继续使用的数据自动降级。
