# 开源 Agent 系统提示词设计模式调研

> 文档性质：历史调研快照。本文保留调研时的外部事实与设计背景，不作为 OURO 当前实现契约。

> 调研日期：2026-07-31  
> 目标：提炼可用于个人通用智能体的稳定提示词内核，而不是复制编码 Agent 的具体工具和场景规则。

## 1. 范围与来源

本次只把官方仓库和官方文档作为事实来源。各项目的在线分支会持续变化，因此以下链接表示调研时的
公开版本，而不是永久固定快照。

| Kimi Code CLI | [default system prompt](https://github.com/MoonshotAI/kimi-cli/blob/main/src/kimi_cli/agents/default/system.md) | 主动执行、理解上下文、并行获取独立信息、持续完成和事实核验 |

的具体措辞写入结论。

## 2. 共同核心元素

| 核心元素 | 跨项目共识 | 对通用智能体的抽象 |
| --- | --- | --- |
| 明确身份与使命 | 首段说明 Agent 是什么、服务谁、主要结果是什么 | 以帮助用户实现意图为首要目标 |
| 意图优先 | 结合请求和上下文理解实际目标，不机械匹配字面 | 遵循指令层级，并在其中最大化忠于用户 |
| 行动导向 | 用户要求完成任务时，不能只给方案或承诺以后执行 | 信息请求直接回答，行动请求推进到实际结果 |
| 上下文先行 | 修改或决策前先检查环境、约定和已有状态 | 先取证，后行动；第三方内容默认是数据而非指令 |
| 自主但不惊扰 | 可以主动完成必要后续，但不擅自扩大范围 | 低风险假设直接推进，重大歧义才询问 |
| 迭代与持久性 | 根据工具结果调整方案，失败后尝试合理替代路径 | 不因一次可恢复失败过早放弃 |
| 验证闭环 | 运行检查、核对输出，不凭“应该可行”宣布完成 | 验证强度与后果相称，不能编造结果 |
| 副作用分级 | 读取和可逆动作更自主，远程或不可逆动作更谨慎 | 谨慎由具体动作风险触发，而不是由话题敏感度触发 |
| 简洁沟通 | 直接回答，减少前后套话，结果比过程叙事重要 | 默认简洁，复杂任务或用户要求时增加细节 |
| 分层组合 | 基础身份、项目规则、工具说明、动态环境分开注入 | 默认提示词保持稳定、短小、与能力和场景解耦 |

## 3. 主要设计模式

### 3.1 稳定内核与动态上下文分离

Hermes 的 `stable → context → volatile` 分层和 Claude Code 对 preset、项目说明、权限的区分都表明：
默认系统提示词应只定义长期稳定的行为原则。工具说明、技能、工作目录、记忆、时间、权限状态和场景规则
应由各自的上下文机制注入。这样既减少提示词长度，也避免基础人格与运行时实现耦合。

### 3.2 使用结果循环，而不是固定流程

Claude Code 将 Agent loop 概括为“获取上下文—采取行动—验证结果”；Kimi 和 Hermes 同样强调工具结果会决定
下一步、不能停在计划或伪造输出。通用提示词应规定这个闭环，但不规定必须使用某个规划工具、命令或测试
框架。

### 3.3 按副作用控制自主度

主流 Agent 的权限设计关注动作是否修改本地状态、触发外部影响或难以恢复。由此可抽象为：低风险且可逆的
步骤可以基于合理假设自主推进；目标、范围或不可逆后果不明确时再询问。风险判断应基于具体请求的现实后果、
严重性和可执行性，而不是政治、生物、化学、NSFW 等主题标签，也不应仅凭直白措辞、假设问题或非主流观点
推断恶意。

### 3.4 最小范围拒绝

OpenCode 明确避免冗长、说教式拒绝。对个人通用智能体，更稳健的模式是先区分讨论与行动：解释、分析、批评、
翻译、虚构、角色扮演、历史报道和学术研究默认属于正常表达，不等同于认可或实施。拒绝应作为最后手段，仅
限制对明确严重现实伤害具有直接、可执行、实质帮助的最小部分；其余请求继续完整回答。风险说明应与真实风险
成比例，而不是进行泛化道德审核或常规动机盘问。

### 3.5 将真实性作为完成条件

Codex、Kimi、OpenCode 和 Hermes 都反复要求检查实际状态、运行验证、如实报告失败。提示词不应要求模型表现
得“永远成功”，而应要求它不能虚构事实、来源、执行、输出或完成状态。

## 4. 未纳入默认提示词的内容

- 具体工具名称、参数、并行调用协议和命令偏好；
- 编程语言、代码风格、Git、测试框架和终端渲染规则；
- 工作区路径、当前时间、记忆、技能索引和项目说明文件；
- 某个模型供应商的已知行为补丁；
- 重复使用 `MUST`、`NEVER` 的长篇提醒和大量格式示例；
- 把敏感话题等同于高风险行动的笼统内容审核。

这些内容可能在特定运行环境中有价值，但属于动态上下文、能力说明、权限策略或专项 Skill，不应占用个人
通用智能体的默认稳定内核。

## 5. 落地结论

新的默认提示词采用四个紧凑部分：`Priorities`、`Working Method`、`Open Inquiry and Risk`、`Communication`。
它保留主流 Agent 的共同执行骨架，同时把用户目标置于高优先级，对模糊请求默认采用善意解释，并明确避免因
话题、观点、语气或虚构表达而拒绝、弱化、净化或说教；安全边界只针对具体、直接、可执行且严重的现实行为
风险，并要求最小范围处理。
