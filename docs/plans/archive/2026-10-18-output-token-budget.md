## 设计原则与职责

基于第一性原理建模本质核心，确保精简、优雅、完整，不过度设计、过度工程化。同一事实只保存一次，同一业务规则由一个责任方表达；必要错误在对应边界明确触发。

| 概念 | 当前表达与责任 |
|---|---|
| 单次输出上限 | 完整配置与请求中的 `max_output_tokens` 为 `int \| None`；缺失与 `null` 同义，默认 `None`。 |
| 请求输入容量 | `ContextBudget` 保存上下文窗口与输出上限，集中派生预留和输入容量。 |
| 上下文测量 | `ContextMetrics` 保存估算值、预算事实及 estimator 身份；剩余容量、利用率和超限状态为派生属性。 |
| 压缩规划与采用 | 框架选择完整材料、保留受保护帧，以实际摘要重建主上下文并在提交前验收。 |
| 摘要生成 | 每次模型调用使用独立请求及摘要配置，不继承主请求的输出上限。 |
| 累计运行额度 | `RunBudgetPolicy` 约束 Run 的累计软额度，实际用量继续归属原 Session/Run。 |

`None` 表示 OURO 不添加请求输出上限，不查询或推测服务端限制。正整数表示明确上限；不使用零、极大整数或隐藏数值默认表达不限制。

## 配置、请求与界面

完整配置加载时统一缺失与空值。编辑操作只应用已提交字段：未编辑的字段保留，明确提交 `None` 清空。使用字段集合表达编辑意图，不向领域模型加入第三种值或 sentinel。

模型目录和工厂构造唯一的最终请求模型，adapter 直接执行该模型。独立模型调用可使用自己的空值或有限上限，不修改共享 adapter，也不与所选端点的配置值比较大小。

Chat Completions 与 Responses 在上限为空时省略对应载荷字段。Messages 协议要求显式有限值，空值在编码边界明确失败。相应 Messages 模板保留有效请求参数；其他模板默认不配置上限。既有受信服务策略继续控制协议字段是否发送，request options 不能覆盖协议自有参数。

CLI 使用 `--max-output-tokens none` 清空。TUI 的端点和摘要设置统一使用英文标签 `Max output tokens`；字段为可选项，未填写时显示 `Optional`，输入框不显示占位提示。清空后保存为 `None`，重新打开仍保持可选空值。

## 统一预算与摘要边界

每次请求采用同一容量规则：

```text
输出预留 = max_output_tokens 为 None 时取 0，否则取该正整数
输入容量 = context_window - 输出预留
```

输入容量必须大于零，配置与模型边界统一校验；不把无效容量抬到 1。`over_budget` 仅描述估算输入是否超出容量，不预测模型生成长度。

主会话按 `输入容量 × target_ratio - 固定内容估算 - 已有摘要投影估算` 规划尾部，最低为零。目标比例属于软规划；摘要生成额度不作为摘要正文大小的预测值。新摘要生成后按完整主上下文实际投影验收，满足容量、历史前缀与代次要求才原子激活记录。

通用框架与策略的契约是输入材料和规范化摘要正文。框架负责 lineage、完整帧、取消、用量归属和安全提交，不检查内置标签或绑定某种提示词输出模式。插件可使用其他提示词和响应格式，再返回 `CompactionArtifact.summary`；无需额外格式注册机制。

内置策略位于 [summary_compaction.py](../../../ouro/application/summary_compaction.py)。其提示词、正文解析、输入分块和格式相关的有限重试由该策略维护。每次生成以独立上下文调用公共模型执行器，不进入主 agent 循环、不携带普通工具、不创建持久化 Session。所有模型路由均使用同一份摘要配置，默认上限为空。

模型完成判定继续拒绝 `length`、过滤及缺少完成事件的响应；标签闭合不能使不完整响应成功。通用请求审计记录参数、原始正文与思考、完成原因、实际用量和错误，不保存标签开闭状态。失败、取消和实际摘要过大均不激活部分结果。

## 当前公开与持久化契约

| 边界 | 当前契约 |
|---|---|
| Plugin API | `4.0.0`；Python SDK 入口为 `ouro.sdk.plugins.v4`。 |
| CompactionCall / CompactionRequest | 提供身份、Harness 视图、已有摘要与材料，不携带主请求输入预算或摘要生成额度。 |
| ProviderModel | `max_output_tokens` 可空。 |
| Worker 传输 | 传输协议为 `3.0`，领域契约由 Plugin API 版本约束。 |
| ContextSnapshotRecord | schema `5`，metrics 保存嵌套预算事实。 |
| CompactionRecord | schema `2`，请求审计允许空上限且不要求格式标签状态。 |

当前运行路径直接实现上述契约；不支持的显式数据版本由格式边界拒绝。

离线升级支持 ContextSnapshot 3/4 到 5、CompactionRecord 1 到 2，以及模型请求、摘要完成事件和提交回执中的预算指标转换。测量、请求容量和开放数据保持原意；转换与发布复用同一备份、恢复和幂等管线。支持范围及拒绝条件见[数据升级规格](../../specs/data-upgrade.md)。
