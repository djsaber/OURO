## 设计方案

### 数据所有权

| 对象 | 权威内容与寿命 |
|---|---|
| Input | 用户或框架已接受的输入正文；InputState 记录排队、消费、撤销和取消状态。 |
| Message | 有序历史骨架、自有正文及 Input/Call/Outcome 引用；资源内容通过固定身份取得。 |
| Call / Start / Outcome | 原始参数、实际执行参数及确定结果分别归属明确；结果正文与 structured 保留各自语义。 |
| Resource | 媒体字节和元信息；先发布资源，再提交引用。查询在读取寿命内取得完整内容或字节窗口。 |
| ContextSelection / Summary | 下一次活动范围，以及摘要正文、覆盖终点和实际前置条件。 |
| RequestManifest / Header | 最近一次实际准备的 provider-neutral 输入与不可变引用；请求状态和计量身份由小头拥有。 |
| Draft | 当前请求的 text/reasoning 前缀；正式响应或 partial 提交后释放。参数碎片不构成执行意图。 |
| Session / Run | 当前状态、选择、计数和执行检查点；RunResult 返回调用摘要，历史事实通过显式查询读取。 |
| 原始用量账本 | Provider 请求身份、原始用量及 Run 汇总；展示账单修订与真实预算消耗分离。 |

正文通过固定领域引用使用，不建立通用对象图、内容寻址仓库或历史快照链。
Call 小投影、消息位置与计数随必要事实增长；运行内连接缓存由执行所有者持有，退出即释放。
正常执行处理活动范围和本轮变化，完整活动输入、显式导出及真实大结果承担其内容规模对应的成本。

### 提交与执行

1. 输入接受与消费使用原生提交，接受回执标识持久事实；业务计算和外部调用在存储锁外执行。
2. Call 在执行前存在，started 在进入工具前持久化；实际结果按到达顺序保存。
3. 完整工具帧按 source_index 发布，消息、Call 状态、Harness 意图与 Driver ready 同提交；冲突不得部分生效。
4. 模型记录与 Adapter 共用一次准备结果。请求完成更新小头，替换请求释放其独占正文。
5. 摘要按覆盖边界和真实前置条件激活；普通追加不使已有摘要失效，撤销只处理受影响范围。
6. Run 终态、Session 投影和必要消息同提交；内存状态在提交成功后推进。

外部作用可能已发生而无确定结果时保留 unknown_outcome，不自动重放。
迟到确定结果仍可归入原 Call；历史发布、业务意图和授权受当前执行边界约束。
已发布的未知反馈保持其原有语义，本地持久化不承诺任意外部操作恰好执行一次。

### 两种后端与读取

Files 使用顺序消息正文和会话级原生数据库；数据库拥有 Session/Run、事件、定位、工具事实、
摘要、请求头、Draft 与资源元信息。纯原生变更直接提交数据库事务；涉及正文文件时使用有限的短期提交决定。

SQLite 使用原生事务与索引，按消息批次写入，同批计数一次更新。
两后端共用事实读写实现，一次 Session 读取共享连接和事务；读取结果在交付消费者前释放存储边界。

冷恢复按当前执行头、pending 调用、当前请求/Draft 和活动选择定位。
普通查询不执行恢复写入；Files 存在未决决定时报告局部需恢复状态。
资源窗口按身份和字节范围读取，读取、请求替换、撤销、分支和转存具有明确资源寿命。

### 上下文、观察与计量

- Manifest 固定实际准备的消息骨架、工具描述及字面值；查询不重新执行动态 Provider 或读取已变化的原媒体路径。
- 默认估算复用活动不可变引用的数值成本；动态上下文、自定义整请求 estimator 和模型能力选择保持原契约。
- 业务事件随事实提交并通过 sequence 追赶；实时输出使用当前 Draft。完整 Run 历史由显式查询提供。
- 原始请求幂等记录与 Run 用量汇总在账本内同事务更新，再由 Session 提交计量引用和收尾。
  缺失报告保持未知；无计量端口的宿主不能提供依赖真实 token 用量的预算保证。

### 行为验收矩阵

以下场景有对应行为回归；功能成立与性能达标分别判断。
测试入口分布于 [Core](../../../tests/core)、[Session](../../../tests/sessions)、

| 编号 | 场景 | 验证目标 |
|---|---|---|
| V01 | 输入接受事务前后中断、回执丢失、相同 input_id 重试不同内容 | 未确认输入可重试；已确认恰有一份接受事实；不同内容冲突；撤销后旧 ID 不复活 |
| V02 | 队列消费与取消竞争，多个输入组成原子单元 | 只有一方获得合法结论，消息引用和队列状态一起提交；FIFO 和原子单元不被拆散 |
| V03 | Provider 在无输出、文本、reasoning、工具参数片段、done 等位置中断 | 已写 Draft 可恢复 partial，未完成工具参数不执行；无完整 response 事务不得伪造成功 |
| V04 | Provider done、取消、账本成功而 Session 未提交；期间账单 correction/reset | 原始用量按请求身份一次生效，可恢复结算；预算不受展示变化影响，无记录保持未知；不会由 done 推断完整输出 |
| V05 | 工具 started 提交前、提交后调用前、作用已发生后 Outcome 提交前强制退出 | 前者可确定未进入工具；后两者明确 unknown_outcome，不自动重放，也不谎称失败无副作用 |
| V06 | K 个并行工具逆序完成，其中一个等待审批、一个失败 | 结果保存不随慢工具丢失；模型历史按 source_index；等待、错误和真实结果关联正确 |
| V07 | Outcome 已保存、工具帧发布尚未完成，随后进程退出 | 重启按 IDs 完成允许的发布，不调工具；业务状态意图应用一次，冲突不部分提交 |
| V08 | 同批两个状态提案冲突，或控制提案在返回时已过期 | 保留已发生工具结果；业务结算明确失败/受阻，不通过重跑工具“修复” |
| V09 | Driver ready/consumed checkpoint 各阶段中断 | ready 可按契约消费一次；consumed 不重复进入旧副作用代码；不回退为默认 Driver |
| V10 | 结束事务中断、提交后通知丢失 | 两后端完成原生提交后呈现一致终态；订阅按已有事件 sequence 补读，无副作用重放 |
| V11 | 撤销合法用户输入及附件原子边界，旧 worker 和 child 结果迟到 | 保留前缀及 Harness 正确；拒绝旧历史发布，保存归属明确的实际结果/用量；不新增任意 assistant 消息可撤销的产品能力 |
| V12 | 分支涉及 owner copy/reset/reject | 目标分支只继承允许状态，reset 不经旧 before 锚点复活，reject 不因当前为空绕过 |
| V13 | 改配置、替换插件、编辑原媒体文件后查询最近 Manifest | 返回原实际 provider-neutral 内容或明确已失效；查询不执行动态回调，不访问变化的原路径重建 |
| V14 | 不支持媒体模型、模型切换、已压缩技能、被省略旧媒体重新选入 | 历史事实不变；输入变化有明确选择和可追踪来源；受保护工具协议完整 |
| V15 | 无诊断消费者、重启、断线订阅；请求已结束时使用旧 Draft 游标 | 业务恢复正确，返回终态/事实引用；不声称可重放已结束请求的原 token 切分 |
| V16 | 写完资源后事务失败、引用提交后进程退出、显式删除和导出 | 未引用资源可由维护处理；已确认引用可读；无静默替换、无不完整媒体发布 |
| V17 | 两个 owner 争用会话、同调用重复提交、旧 epoch 的结果提交 | 一个合法结算；重复查询同结果；不同效果不能共享接受 ID |
| V18 | 非当前 schema、缺必需字段、跨 Session 引用、未知 owner 状态 | 框架明确拒绝相应操作，不猜字段、不升级、不复制一份“修复后历史”继续运行 |
| V19 | 插件修改返回视图、后台线程在取消后写入 | 数据不受隐式修改，关闭视图的提交失败；其他会话仍可运行 |
| V20 | 显式超长 Run、多工具、多次摘要/历史重选 | 没有为规避存储成本新增轮次、会话总长度或工具总量限制；真正外部容量有明确错误与策略入口 |
| V21 | 摘要生成期间正常追加、无关标题/owner 修改或撤销 | 正常追加和无关变化不误拒；实际依赖变化拒绝；撤销尾部时未受影响摘要保留 |
| V22 | 最近请求查询与替换/失效/私有内容清理并发 | 返回同一代完整输入或明确失效，无悬空引用，不将旧清理失败伪装成新请求未提交 |
| V23 | 文件无内存索引的冷恢复、大资源中读小窗口、固定活动资源而增加旧资源 | 只读取当前活动范围和实际字节，不建立全历史 ID 表、不加载全资源清单、不全文件 hash |
| V24 | 控制、插件命令及撤销提交成功后调用方异常 | 本次调用保留原返回值并确认所拥有提交，跨重启通过 Input/Run 领域事实确认已接受效果；不保存万能完整回执，失败 SQLite 事务不得被确认成功 |
| V25 | 同一调用先被标记 unknown，随后真实结果返回，且当前 epoch 已变化 | 原 Call 接受一次确定结果；原未知反馈不被改写；无新历史、无旧 Harness 意图、无重跑 |
| V26 | 默认估算、整请求自定义估算、动态 Context Provider 及模型切换 | 请求内容与真实估算契约一致；复用仅限未变部分，不缓存掉动态行为或要求扩展支持增量 |
| V27 | 显式历史读取、导出、分支与资源删除竞争 | 每页数据完整，必要依赖闭包可用；释放边界后不暴露将被清理的裸引用；分支不继承活动许可 |
| V28 | 普通查询遇到文件未决提交，其他会话仍正常 | 查询不执行恢复写入，明确局部恢复状态；显式恢复仅完成存储效果，不调用工具或插件 |

## 交互性能

通过实际 SessionService/Supervisor 入口测量，读取在线程中执行。
新会话测量发生在已有历史的 home 中；提交时间不含 Supervisor 启动，合成 Provider 即时输出中文、reasoning 和代码块。
首段止于本地 sink 收到文本，完整回复止于 Run 返回；实际网络与屏幕呈现不在计时内。

运行中操作由 Event 保持生成阶段，分别验证当前输出、排队输入未执行、撤回后不再待处理及取消终态。
60 秒期限只防挂起。表中为三个 worker 的中位数；首次读取单列，重复读取排除该次，
翻页与新适配器重开均返回 200 条实际消息并验证内容一致。

## 验收边界

核心设计和已测长会话负载达到本轮收尾标准。小查询、新会话接受、运行中快照等单项成本如表保留；
后续优化由实际负载中的明显瓶颈触发。

最终代码没有再次全量验证。升级模块的 66 项失败留待专门适配；
新 home 手动交互、非 Windows、受控冷缓存、真实掉电与网络端到端性能尚未验收。
全部实际用户交互与屏幕体感也尚未全面验收。

已有临时目录、工具缓存及构建产物的删除曾被自动审批以 `blocked by policy` 拒绝，未提供更具体原因；
这些旧残留未确认全部清除。正式基准的临时 home/源码随上下文退出清理，生成缓存和产物不纳入提交。
