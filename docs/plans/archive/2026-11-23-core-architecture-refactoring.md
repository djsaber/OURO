# OURO 核心架构重构：设计、实施与验收

归档日期为 2026-11-23。产品基线为 `82bcde3eba66232a3606ccaf101230cfa5828036`。阶段 1 至 4 已实施，最终审查覆盖插件退役、并发输入、资源读取和持久恢复。Windows 与 WSL2 的功能验证通过。固定负载的相对时延通过 67/80 项，长历史终端的最大循环延迟仍超过 32 ms。

## 架构判断与责任边界

历史消息编辑（`2525b53`）与可写旁问（`d9c68f6`）都涉及界面、队列和持久事实。跨模块修改的主要来源是输入资格与材料准备分散在多处、工具协调代为传递 Agent 能力、两个后端各自解释同一份快照。既有贡献类型已支持 UI Workbench（`b634662`）通过独立插件扩展，当时 `ouro/` 的改动为零。核心保留本地模块化单体，以实际调用者和持久化时点划分职责。[历史编辑](../../../tests/application/test_undo_inputs.py) · [旁问设计](2026-11-23-side-conversations.md) · [UI Workbench](../../../examples/plugins/ui-workbench)

| 职责 | 决定与副作用的归属 |
|---|---|
| 输入适配与受理 | CLI、TUI 将操作转成 `UserInputRequest`。`InputAdmissionService` 决定是否重复、编辑锚点、技能与附件准备、策略评估和队列提交。Supervisor 用同一次受理提交或一致读取返回的回执与会话头安排执行。 |
| Run、模型与 Agent | `RunStartExecution` 持有会话执行权直到 Driver 返回。`RunLifecycle` 提交持久状态转换，等待中的 Run 按交互身份重新取得执行权。模型轮次取得本轮能力和预算，工具协调使用 Agent 控制和等待操作。Agent 服务拥有委派关系、恢复范围和终态结算。 |
| 会话与存储 | `SessionCommit` 表示一次会话更新。快照准备统一处理消息身份、顺序、输入、工具事实和 Harness 检查点。Files 负责暂存与发布，SQLite 负责数据库事务，各自核对已有资源并按流传递内容。 |
| 插件、宿主与装配 | 宿主拥有依赖、选版、目录发布、调用租约、退役与资源归属。SDK、进程内和 worker 适配器解释公开契约。Plan 与 Goal 的规则归各自插件。组合根向应用传入具体实现，CLI、TUI 和存储驱动处于外层。 |

同一模型响应及其工具使用同一份能力绑定。进入审批或提问后释放租约，恢复时按工具身份、参数、权限、变体与执行契约绑定所需实现。输入按稳定标识及本次有意义的字段比较，Plan 审批直接比较用户当时看到的内容，安装包和执行发布沿用已有身份。[代码组织](../../architecture/code-organization.md) · [插件规格](../../specs/plugins.md) · [会话规格](../../specs/session-persistence.md)

## 实施过程

| 阶段 | 实施与验证 |
|---|---|
| 0　建立基线 | 由基线产品在 Files、SQLite 写入待消费输入、Plan 待答、活动 Goal、已完成和结果未知的工具调用。固定本地 Provider，记录可观察结果、事件顺序、模型派发、提交和同步次数。 |
| 1　插件停用与移除（P0） | 基线会在检查活动依赖前释放会话控制权。宿主在管理锁中检查依赖与选版，条件提交成功即受理停用，随后撤销普通调用入口并发布目录。会话协调器按激活身份完成释放及关联取消。移除当前安装复用这条流程，移除事务重新检查所选版本的状态和活动依赖。带活动依赖的拒绝和条件提交冲突均保留原待答、Plan 文件与激活。 |
| 2　插件协议与在途执行（P0） | 基线协议标识沿用 API 6、worker 3，但请求中的技能字段已经变化。本期公开入口为 `ouro.sdk.plugins.v7`，Plugin API 7.0.0、worker 4.0、Manifest schema 3。安装和选版加载在导入或启动前检查声明。两种适配器都能处理含技能激活的模型请求，不兼容声明的 worker 启动次数为零。第三方插件按本期协议接入。内置 release 将既有执行 API 版本固定在发布定义中，持久执行兼容性由 `contract_version` 表达。 |
| 3　用户输入与 Run（P1） | 受理服务拥有输入准备与排队，移除了对 Runtime 私有受理方法的回调。已有空闲会话可在一次启动提交中接受并执行输入，新会话先原子发布会话与首条输入。CLI 保留等待执行的语义，TUI 先获得持久回执。历史编辑按原历史时点验证，旁问按自身队列消费来源材料。 |
| 4　Agent 与会话写入（P1） | Agent 控制与等待、预算读取、恢复和结算分别归其使用方。两种后端共用无 I/O 的快照准备函数，磁盘格式沿用基线。同一重复消息身份在两端得到同一错误，拒绝发布后可用同一会话身份重试。 |
| 最终审查 | 宿主在唤醒退役任务前登记控制权释放责任。真实 worker 测试以进程号确认，换代后每个激活由原进程成功释放一次。没有活动实例时，失败的释放仍阻止清除数据，显式重试与关闭宿主都可完成释放。卸载遇到并发新增版本时，两个安装和共享数据均保留。并发输入重试取得同一持久时点的回执和会话头，附件与上传资源的读取在事件循环之外执行，子会话核对当前 Agent Run 的持久委派身份。 |

插件原控制器确实不可用时，宿主记录强制释放及私有清理状态。普通清理失败保留其归属和错误。运行与存储沿用已有锁、事务和部分写入处理。阶段 5 的进入条件为实际新增原生贡献类型，或实测能将瓶颈归于候选重复校验、代次元数据。本轮没有触发这两项条件。[退役](../../../ouro/plugins/lifecycle/runtime.py) · [受理](../../../ouro/application/inputs/admission.py) · [Agent 恢复](../../../ouro/application/agents/recovery.py) · [快照准备](../../../ouro/sessions/snapshots.py)

回退时，协议、宿主和插件使用匹配版本，由能解释在途操作的版本先完成结算。用户在本地已经合法提交的输入、工具结果和已发生的外部副作用按原事实保留。
