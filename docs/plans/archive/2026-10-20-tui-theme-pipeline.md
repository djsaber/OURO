# 粒子主题共用计算与帧管线改进记录

> 文档类型：工程实施记录
> 范围：几种既有粒子主题共用的数值引擎、动画调度与终端帧生命周期。

各主题的构图、光谱、动画公式及内部交互设计不属于本次范围。
五种保留的粒子主题各自在脚本内定义页面工厂、标题、布局及激活行为，复用计算与终端适配。
本轮未完成的实际终端与长期测量范围合并保留在本文末尾，归档不代表这些范围已通过验收。
共用计算引擎不是系统组件或 TUI 扩展协议；本记录不构成系统架构设计。

## 审查结论

| 边界 | 证据与决定 |
|---|---|
| 完整页面扩展 | `WelcomePage` 已提供任意组件组合、TCSS、布局、渲染与 Textual 事件；保留现有结构，不新建 UI DSL |
| 公共输入所有权 | `WelcomeHost` 持有稳定输入层；自定义页面控制输入矩形，组件内部交互无需访问 Host 私有状态；保留该分工 |
| 数值依赖 | 将光栅器中的余辉、邻域光照与曝光计算收回共用的 `field.py`；网格、接口与数组操作集中封装，数值模块不导入框架、组件或具体主题 |
| 帧调度 | 原实现周期 tick 与逐帧 worker 分离，忙时跳过 tick，可能再等整周期；改为单一串行循环，保持正常截止时间并合并最新请求 |
| 周期性停顿 | Textual 8.2.8 的 `Strip.divide` 对整行缓存 `[self]`，动态帧持续形成自引用；这些主题的 `FrameStrip` 在恒等切分时直接返回，不缓存自身 |
| 数值与分配成本 | 合并公共数组乘加、复用尺寸缓冲；先比较最终 cell 再构造变化行，避免未变化行分配无用 Segment |

共用实现整体位于 `ouro/tui/welcome/styles/dot_matrix/`，归属主题包：
数值集中在 `field.py`，`DotArtwork` 与 `FrameStrip` 收在 `raster.py`，播放循环留在 `widget.py`。
没有新增生产模块、框架领域或依赖矩阵项。适配在 Textual CSS、滤镜和裁剪之后进行，
实际切分仍复用 Textual；没有改依赖的全局方法、调节 GC、输入节流或按主题打补丁。
独立引擎只交换网格、时间和借用 RGB 数组，不访问 Widget、App、主题目录或时钟。
不增加进程池、通用向量 DSL、多级缓存或主题专属调度器。

共用引擎的 `ParticleGrid` 只描述采样宽高和行优先坐标，构造时由主题提供跨度；2×4 Braille 映射留在呈现适配中。
`PhosphorField(grid, prepare)` 通过主题提供的采样器取得非负 RGB 辐射值，
`frame(seconds, elapsed)` 返回长度为 `width * height`、范围为 `[0, 1]` 的三个 `array('d')`。
输出借用至下次调用，调用方不修改，同一实例不并发使用；引擎不修改采样器输入。
主题自身的 `DotArtwork.engine_factory` 可选择其他满足该接口的实现，不改变 TUI 主题扩展协议。
数值错误按原调用链传播，不静默回退或自动重试。

后台帧仍会与主循环竞争 CPU/GIL；线程边界不承诺消除这种竞争。
引擎工厂可替换公共数值后端，但不会自动编译或加速主题自己的 Python 公式。

## 正常启动的粒子空白回归修复

用户反馈正常启动仅显示 Horizon 标题、艺术区域空白。生产 `App.run` 启动探针复现：
页面已经激活、尺寸为 114×11，但播放时间为零、没有光栅结果，帧 worker 已退出。
原回归主要使用 `run_test`，没有覆盖这一启动时序。

Textual 在 Mount 消息处理结束后才设置 `is_mounted`，而在 Mount 中启动的 worker 可能提前执行。
帧循环以 `while self.is_mounted` 进入，会把“尚未挂载完成”误判成生命周期结束。
修复后帧循环依靠 Textual 在组件卸载时取消所属 worker；发布结果仍检查挂载状态与版本，
不新增等待轮询、重试或额外调度器。

新增正常 `App.run` 启动回归，以事件握手确定 worker 先于 Mount 完成运行，
通过实际合成后的终端输出验证粒子首帧与后续动画帧。
本次运行 `test_dot_animation.py`、`test_welcome_styles.py`、`test_welcome_layout.py`，
共 35 项通过；修改文件的 Ruff、格式检查与 mypy 通过，未执行全量测试。

## 2026-10-21：主题内部数值与编码管线优化

本节记录后续性能工作，取代前文关于当前数值后端为 arrayfunc 的描述。生产改动仅位于
`ouro/tui/welcome/styles/`；依赖声明、锁文件、安装说明、定向测试和基准随之更新。
Host、输入组件、主题协议、布局、帧调度、30 Hz 上限和 Textual 框架均未改动。

### 计算与数据布局

- 可选 `[themes]` 后端由 arrayfunc 替换为 `numpy>=2.3.3,<3`，锁定并验证 2.5.3。
  网格为只读、行优先的 float64 数组；采样器和引擎输出仍由各尺寸实例独占、借用至下次调用。
  NumPy 原生最大值、裁剪和线性插值替代多轮绝对值斜坡计算。
- 余辉保留逐通道的时间衰减与最大值规则。四邻域通过二维切片视图计算，不再复制带 padding 的数组和左右邻居。
  曝光仍使用 `expm1` 保留极弱光精度；`x**0.75` 改为 `sqrt(x) * sqrt(sqrt(x))`，避免通用幂函数。
- Bloom、Tide、Prism 用三角恒等式分离空间基函数和标量时间相位，不累积相位近似、不保存逐帧历史波形。
  Clifford 预计算 14 个固定深度的投影分母倒数，并将共同旋转项提到深度循环外，保留原积分样本及顺序。
- 光栅直接用八个跨步视图读取每个 Braille 单元；掩码比较、RGB 合成和 32 位单元编码均批量完成。
  整幅最终单元先比较，只为变化行构造 Python/Rich 对象；不再逐行复制八个点位或为整幅画面建立 RGB 元组。
  原有覆盖阈值、轮廓阈值、背景合成、24 位颜色和最小行损伤范围保持。

这里采用 NumPy 已有的数组视图与原生算子，不引入自编译扩展、JIT、SciPy、GPU 或计算服务。
基本索引可共享底层数据，减少复制；数组由原有单一 worker 独占，适合多项原生运算释放 GIL 的执行方式。
依据：[NumPy 视图说明](https://numpy.org/doc/stable/user/basics.copies.html)、
[NumPy 线程安全说明](https://numpy.org/doc/stable/reference/thread_safety.html)。

体积有明确取舍：本机 NumPy 包及其本地库约 41.93 MiB，arrayfunc 约 1.74 MiB；
NumPy Windows wheel 约 12.1 MiB。它只属于可选主题依赖，不增加基础安装的计算依赖。
Clifford 的 14 个倒数平面在 114×20 终端区域额外占约 1.95 MiB，随该尺寸的引擎释放。
