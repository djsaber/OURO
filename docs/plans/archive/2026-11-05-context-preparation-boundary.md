# 上下文准备与压缩策略：设计与验收

> 文档类型：设计验收记录
> 验收日期：2026-11-05

## 职责与完成条件

同一会话的下一轮模型请求使用准备完成的上下文。模型请求端口依赖 `ContextPreparer`，不要求上下文由摘要生成。
设计契约见[上下文准备边界](../../specs/context-and-compaction.md#准备能力与执行策略)。

- [x] `ContextPreparationService` 负责读取、动态材料、投影、容量校验和请求记录。
- [x] `ContextCompactionService` 负责默认压缩的自动触发、规划、生成和原子激活，单向依赖准备能力。
- [x] `RuntimeService` 将默认准备流程绑定到模型请求端口；手动压缩使用相同的策略执行与提交边界。
- [x] `CompactionStrategy` 提供默认压缩流程中的文本生成能力；其他上下文构建流程使用通用准备能力。
- [x] 新材料使用 `ModelMessage`，已有历史使用 `MessageRecord`，只有显式 canonical 来源参与引用复用。
- [x] 原生请求始终满足容量、执行归属及上下文选择条件；生成失败或取消不激活部分结果。

`build` 返回同次读取的材料和视图，不自行选择生成策略。`build_view` 接受明确选择的消息，
`finalize` 校验并记录最终请求。上下文内容、选择和生成方式由应用流程决定；规范历史、请求快照和执行授权分别归属。
当前实现提供默认摘要流程，handoff 的具体材料与持久化行为属于对应应用策略的设计范围。

## 验收

两个存储后端的非摘要场景验证：超预算构建不触发模型或生成策略；超预算视图不可提交；
普通角色的替代上下文可以保存为实际请求，canonical 历史不变，且不产生压缩记录。

成本回归验证初始视图与已接受视图的复用、并发追加时的重新读取、无可压缩帧时的直接复用，
以及动态材料调用次数、媒体读取次数、历史 Run 零读取和请求视图寿命。默认循环的前缀、工具完整性、
压缩续跑、取消、并发提交、用量归属和 TUI 队列由对应集成回归覆盖。

包含[协议边界](2026-11-05-context-protocol-boundaries.md)的受影响范围共 **507 项定向回归通过（69.38 秒）**。
27 个 Python 文件通过 Ruff 和格式检查，10 个生产文件通过定向 mypy，`git diff --check` 通过。
验证范围为相关模块；真实端点延迟、缓存命中率及推理质量不在离线验收范围内。

## 活动尾部工作负载

PowerShell：

```powershell
.venv\Scripts\python.exe -m dev.benchmarks.compaction_boundaries --repeat 3 --history-sizes 64 4096 --summary-counts 1
```

Windows 11 / Python 3.14.6，固定两个活动尾部消息和一份摘要，三次采样的请求准备耗时中位数：

| 存储 | 64 条已覆盖消息 | 4096 条已覆盖消息 |
|---|---:|---:|
| Files | 42.2 ms | 39.5 ms |
| SQLite | 44.2 ms | 40.8 ms |

测量包含 tracemalloc，排除样本构造，OS 缓存不受控；结果用于验证活动尾部路径的执行成本，
不作为稳定延迟保证，也不代表远端服务性能。
