# TUI 性能改进计划

> 文档类型：完成归档
> 日期：2026-10-29
> 范围：TUI 会话加载、历史排版、流式交接及思考与执行轨迹展开。

本记录包含设计方案、实施验收和性能证据。有效契约见 [TUI 规格](../../specs/tui.md)，
数据流与职责见[渲染架构](../../architecture/tui-rendering.md)，基准用法见[本地测量](../../../dev/benchmarks/README.md)。

## 设计方案

### 数据与状态所有权

| 对象 | 职责与寿命 |
|---|---|
| Application 观察 | 提供近期完整帧窗口、当前状态、活动草稿、后续事件和分页游标 |
| TranscriptEntry | 保存展示输入及 canonical 消息 sequence；未持久化的活动条目没有该坐标 |
| CachedSessionHistory | 转移展示状态、anchor、源消息边界、脚手架策略、源 Run 集合和原分页游标；至多保留三个非当前会话 |
| ConversationHistory | 拥有逻辑条目、工具/轨迹索引、展开选择、已准备行和单一排版 worker |
| ReasoningLayout | 保存可复用的思考正文行、宽度和主题，连接活动输出与历史 |
| PreparedLine | 保存纯文本行的不可变 segments 和 cell_length，提供准确行高和选择文本 |
| 视口 Strip | 在绘制时物化，使用有界行缓存；Markdown 的 Rich 排版结果直接保存为 Strip |

消息 sequence 用于合并稳定前缀；分页游标属于 Application，原样保留。Files 游标是字节位置，不能用消息序号替代。
源 Run 集合包含隐藏的 scaffold 消息，保证向上补页的摘要位置。缓存身份由条目边界、宽度和完整主题值决定。

### 处理管线

| 场景 | 执行路径与工作量 |
|---|---|
| 长历史冷进入 | Controller 取得近期 200 条完整帧及当前状态 → 展示投影 → 安装快照 → history owner 准备可见行 → 一次发布 |
| 主页进入运行中会话 | 捕获观察快照 → 安装稳定历史 → 恢复思考与 Markdown 开放尾部 → 应用后续批次 → 确认已应用位置 |
| 切换与缓存重进 | 读取近期窗口 → 补齐离开期间的新增缺口 → 投影窗口/缺口 → 合并稳定前缀；实际宽度确定后恢复兼容布局 |
| 流式更新与完成 | 追加新增内容及未完成行 → 完成块进入历史；思考正文直接交接兼容行结果 |
| 提交消息 | Composer 经既有受理流程提交 → 接受后清理草稿 → canonical 输入事件及后续 delta、工具、Run 局部更新 |
| 主/子视图 | 观察目标会话 → 同一历史管线 → 共享 agent tree 增量更新相关工具；子视图只读，返回恢复父会话位置 |
| 思考展开 | 准备所选正文准确断行 → 一次发布行几何 → 仅视口行物化 Strip；再次展开与悬停复用正文 |
| 执行轨迹展开 | 取得本 Run 前序 assistant/tool 条目 → 准备缺失行 → 原子提交准确高度；用户未主动滚动时保持摘要位置 |

可见性由逻辑条目决定，首次加载准备可见内容。Run 终态分类只处理该 Run，工具索引随历史结构更新。
宽度/主题改变触发重排，展示策略改变触发保留范围重新投影，历史代次改变使旧前缀失效。
大段文本在线程中准备，视图 worker 等待发布；输入和滚动继续响应，过期结果按版本丢弃。

### 正确性边界

- 草稿受理、canonical 顺序、观察应用后确认、活动尾部边界、子视图权限与交互语义保持一致。
- 版本、epoch、条目、宽度和主题检查保护切换、撤回、分页及异步排版的实际竞争条件。
- Markdown 解析失败显示原文并报告诊断；历史排版失败保留当前表面并向等待方报告错误。
- 窗口、缓存数量和活动 Markdown 解析预算约束资源寿命；完整内容通过分页、展开和冻结展示。
- 展开使用完整内容和准确高度，滚动锚点、复制、点击 metadata、颜色、边框及留白使用统一规则。

## 测量环境与方法

基线为 `61149241f6cd9cd48af1cc2ab2ecaffd353645d3`。环境为 Windows 11 10.0.26300、Python 3.14.6、
Rich 15、Textual 8.2，headless 100×32；同环境串行执行，每场景三个样本，不清 OS 缓存。
数值为毫秒，中位数 [最小值, 最大值]。headless 刷新与真实终端 paint、p95/p99 分开解释。

真实会话 `ses_4ab06e62246a4a35907ddcc8d3dd18c3` 含 1,075 条消息、255,845 个事件，目录 4,920 个文件约 302 MB。
原始会话检查时已空闲。展示夹具来自独立副本导出的 DTO，适配当前模型字段；完整夹具省略 compaction 标记。
原目录内容、大小、mtime 和文件清单复核一致。该实验验证真实正文展示，当前存储与运行场景由临时 Files home 验证。

`tui_history` 在投影完成后计时，区分行准备完成和刷新确认；不包含 Store IO、DTO 解析与投影。
`tui_sessions` 使用完整 OuroTuiApp 和离线 Provider，在进入前保持 Run 运行并产生 48,070 字符思考和开放答案，
分别记录安装返回、Key 入队到 Composer 更新、历史帧、活动草稿帧和后续 delta 帧。冷进入后补两页至 600 条，再经主页重进。
Key 探针记录安装后一次输入完成时刻；草稿帧代表捕获的内容，后续追平单独测量。

## 验证范围

七组真实近期画面逐行文字、逐字符样式及链接/点击 metadata 一致；仅规范化无样式 None 与 Rich none 的等价表示。
对应行数为 163、163、5,674、5,674、760、760、760。类型、格式、静态检查和相关组件/集成回归通过。

原始运行现场的数十秒耗时未完整复现。真实终端、跨平台、长期资源趋势和全量回归属于未验收范围；
严格响应性目标见[性能治理](../performance.md)。现有样本支持局部工作量与延迟结论，不构成所有场景的性能上界。
