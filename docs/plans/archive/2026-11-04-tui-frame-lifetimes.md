# 欢迎页帧生命周期与渲染对象分配

## 根因与设计

矩阵和粒子动画都在事件循环上完成 Textual 合成和 ANSI 输出，键盘处理共享该线程。
逐帧数值结果过早转换成大量 Rich Segment、Color、Style，再经过样式、滤镜、裁剪与切分；
原生 Strip 还为一次性结果预建七个变换缓存。全局 ANSI 缓存延长了动态颜色的生命周期。
这些分配与存活对象增加了 GC 压力，全代回收同时阻塞动画和输入。

另有两个确切的引用环：Strip 将整行切分结果 `[self]` 缓存回自身；TextArea 的 LRU
在每次编辑失效时只丢弃字典和表头，没有解除双向链表。重启能暂时重置对象代次与缓存，
但不能改变稳态分配模式，因此问题不限于某个主题或终端 shell。

修复按数据生命周期划分：

- 主题生产者发布由单 cell 字符段、RGB 整数或共享色板组成的不可变行快照。
  裁剪、切分、样式继承和真彩色编码保留该表示，不按字符段构造 Rich 对象。
  帧不借用数值 worker 的可变数组；仅保留当前发布行和已有的尺寸所属数值缓冲。
- Rich/Textual 兼容转换集中在主题包 `rendering.py`。宽字符、控制段、链接、装饰、复杂滤镜、
  非真彩色输出和导出需要时按原生语义处理。稳定画布 ANSI 属性最多缓存 32 组，动态混色不入全局缓存。
- 核心 `ouro/tui/rendering.py` 只负责主屏合成片段和编辑缓存的生命周期，不依赖主题包。
  完整行借用原生编码缓存；真实切分沿用 Rich cell 语义，片段不再拥有持久变换缓存。
  TextArea 保留原生 LRU 查找和淘汰规则，在失效时解除环形引用。

没有改变 GC 开关、阈值或触发方式，也没有调整动画帧率、颜色精度、粒子公式或矩阵运动参数。
Textual 8 / Rich 15 的内部适配集中在两个边界模块，未修改第三方类的全局行为。

## 验证方法

`dev.benchmarks.welcome_input` 挂载完整 WelcomeHost 与真实 Composer，使用主屏合成器，
在 160×50 真彩色窗口按独立时钟发送 30 键/秒，循环输入 120 字符再删除。
`--seconds 300` 向上取整为 304 秒，每组 9,120 键；GC 正常开启，预热两秒。
每组在新进程中串行运行，不与 pytest 或其他基准并行。

记录事件创建到处理、预定到达到处理、5 ms ticker 延迟、动画完成合成/编码后的帧间隔、
GC 各代次数与时长，按 30 秒分窗。预定时间指标包含 GC 阻塞按键生产线程的时间。
输出写入 sink，覆盖真实 ANSI 编码，但不代表 Windows Terminal、WSL 终端 paint 或 IME 的人工验收。

```powershell
uv run --frozen --extra themes python -m dev.benchmarks.welcome_input --style matrix --seconds 300 --motion active --output matrix.json
uv run --frozen --extra themes python -m dev.benchmarks.welcome_input --style clifford-torus --seconds 300 --motion active --output particles.json
```

分配检查与计时分开。结构回归验证真彩色帧经过样式、滤镜、裁剪、切分和编码时不逐段构造
Segment、Style、Color，合成片段不创建 FIFOCache，失效编辑行和整行切分结果可经引用计数立即释放。
原生渲染对照覆盖全部四款主题、颜色模式、三个窗口尺寸、宽字符与 CSS 装饰，并逐行比较内容与 ANSI。

## 测量记录

Windows 11 10.0.26300、CPython 3.14.6、NumPy 2.5.3；WSL2 Linux 6.18.54.1、
CPython 3.14.8、NumPy 2.5.4。两端均为 Textual 8.2.8、Rich 15.0.0，GC 阈值 `(2000, 10, 10)`。
四组各约 304 秒、9,120 键，总计约 20 分钟、36,480 键，均完整处理且最终输入为空。

| 环境 / 主题 | GC 0 / 1 / 2 次数 | 输入预定延迟 P99 / 最大 ms | 帧间隔 P99 / 最大 ms | 最大 GC ms |
|---|---:|---:|---:|---:|
| Windows / Matrix | 32 / 2 / 1 | 25.946 / 59.188 | 85.298 / 91.376 | 53.131 |
| Windows / Clifford Torus | 94 / 8 / 1 | 17.715 / 58.605 | 64.147 / 93.679 | 50.680 |
| WSL / Matrix | 32 / 2 / 1 | 4.939 / 43.539 | 75.134 / 112.791 | 38.487 |
| WSL / Clifford Torus | 95 / 8 / 0 | 2.619 / 5.844 | 42.732 / 60.332 | 2.710 |

超过 16 ms 的 GC 共三次，都是本次测量中的首次全代回收：Windows Matrix 在 60.369 秒，
Windows Clifford Torus 在 0.672 秒，WSL Matrix 在 58.103 秒；每组后续均未重复。
因此不能声称完全消除卡顿，首次全代回收仍可能同步延迟输入和动画。
没有用更长预热或删除异常样本隐藏这些停顿。帧间隔也仍有调度抖动，不能用平均 FPS 代替尾部指标。

### 修改前对照与分配量

修改前主题源取自 `b359c4eb`，用同一 Windows 解释器和同一测量脚本回放，
恢复原生 Compositor 和 TextArea LRU；每组 120 秒、3,600 键，未与新版或 pytest 并行。
对照与新版时长不同，以下明确保留时长，不把总次数直接当作同时间内的差值。

| 主题 / 实现 | 时长 s | GC >16 ms 次数 | 输入预定延迟 P99 / 最大 ms | 最大帧间隔 ms |
|---|---:|---:|---:|---:|
| Matrix / 原版 | 120 | 45 | 41.735 / 75.277 | 127.745 |
| Matrix / 新版 | 304 | 1 | 25.946 / 59.188 | 91.376 |
| Clifford Torus / 原版 | 120 | 32 | 26.256 / 104.321 | 189.906 |
| Clifford Torus / 新版 | 304 | 1 | 17.715 / 58.605 | 93.679 |

原版粒子长回收还包含多次第 1 代回收，GC 可从数值 worker 触发并持有 GIL，
因此把计算放到线程并不能隔离它对主线程输入的影响。新版窗口内没有重复出现这种周期性长回收。

另在独立新进程中计数，每组约 8 秒、240 键；这些插桩样本的延迟不混入上表。
Matrix 的 FIFOCache 构造从 427,281 降至 9,771（减少 97.7%，两组均 162 帧）；
Clifford Torus 从 198,493 降至 11,040（减少 94.4%，分别 237 / 236 帧）。
剩余主要属于输入和常规文本组件的原生样式处理。主题真彩色路径的逐段 Rich 对象分配由结构测试约束。

通过原版光栅与矩阵实现另做冻结时间对照：三种粒子、矩阵、两种颜色模式、多个尺寸和时间点，
共 2,532 行的字符、样式及 ANSI 字节一致。该对照独立于性能计时。

最终 321 项定向回归通过，覆盖数值/光栅、帧适配、输入编辑、剪贴板、快捷键、历史、
启动/卸载、主题切换、可选依赖及架构边界；改动范围 Ruff 与 14 个源文件的 mypy 检查通过。
未运行全仓测试，未把输出 sink 结果视为真实终端 paint 或 IME 验收。
