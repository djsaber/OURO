# OURO 系统性审查、优化与文档整理记录

## 目标与判断标准

基于当前提交 `8a6ed55` 梳理项目并审查复杂度、计算、异步与 I/O 成本。保留现有功能及 Provider、插件、存储和未来 Host 扩展契约。以当前代码与可重复测试为事实依据，不将此前计划的完成状态视为本轮结论。

每个候选项先明确业务不变量、实际调用链和成本来源，再决定是否修改。优先消除重复工作、无效状态与资源生命周期缺陷；不按文件长度拆分，不为假设需求新增框架，不删除外部输入校验、权限检查或持久化保障。性能收益用工作量或可重复测量说明。

## 项目地图与审查顺序

| 范围 | 运行职责 | 审查重点 |
|---|---|---|
| `local_application`、CLI/TUI | 本地组合、输入与呈现 | 生命周期、同步阻塞、刷新与重复加载 |
| `application` | Session/Run、监督、Agent、任务、事件与资源编排 | 单一状态来源、取消、锁、查询与 I/O 放大 |
| `core` | 状态机、模型轮次、上下文、工具批次、协议 | 算法复杂度、投影、流式缓冲、抽象成本 |
| `sessions`、`resources`、`billing`、`automation` | 文件/SQLite、资源、账本、任务存储 | 索引、扫描、事务、原子写、后端一致性 |
| `providers`、`auth`、`mcp`、`tools` | 外部模型、认证、连接及工具执行 | 资源所有权、并发、超时、失败处理 |
| `plugins`、`skills`、`config`、`transfer` | 扩展、配置与传输 | 重复转换、无效兼容、缓存边界与数据验证 |
| 测试、规格与工程门禁 | 行为证据和维护约束 | 测试缺口、文档一致性、可复现基准 |

依赖方向保持 Host → Application → Core，基础设施实现端口。核心运行链按提交、上下文、Provider 流、工具执行、持久化、事件投影、终结与取消追踪；文件和 SQLite 的公开行为同时验证。

## 审查结论与证据

基线为 334 个生产 Python 文件、228 个测试文件；架构/Core 基线 224 项通过。范围覆盖全仓依赖/模式扫描及下面的关键调用链审查，不将自动扫描等同于每个函数的逐行证明。此前计划见 [轻量化重构优化](2026-09-24-refactoring-review.md)。

### 运行链与保留判断

1. CLI/TUI 通过 `local_application` 装配端口；Supervisor 拥有进程内作业与观察订阅，Runtime/RunLifecycle 拥有 durable 状态转换。
2. `core.inner_loop` 经 Context/Compaction 构造模型输入，通过 RuntimeAdapter 消费 Provider 流，再由 ToolBatchExecutor 执行工具；Application 先持久化事件再发布。预检交互通知可能先于批次检查点，Host 还须响应检查点后的状态事件。
3. SessionCommit/Harness 负责原子变更和撤销，文件/SQLite 保持同一端口契约；Agent/Task 复用会话运行链。Host 只投影状态，不接管事务。

| 审查面 | 决策与理由 |
|---|---|
| Core/Context/Compaction | 保留领域协议、原子工具帧、增量摘要度量、流式有界 FIFO；它们分别保护扩展、续接正确性与背压，并非无效抽象。 |
| Runtime/Supervisor/Event/Agent | 保留 `run_blocking` 的取消收尾、事件序列锁、Run 所有权、持久事件追赶和 generation 租约。Agent tree 的历史用量查询可在真实规模证据下继续优化，本轮不引入第二套状态缓存。 |
| Session/File/SQLite | 保留版本校验、history epoch、提交摘要、偏移索引、fsync/WAL 和恢复日志；Pydantic 对可变请求重新验证属于持久化边界，不能仅因重复序列化而移除。 |
| Provider/Auth/MCP | 保留协议 adapter、认证提交裁决、受限凭据存储、网络重试与连接生命周期；Responses 完整 item 合并与展示 delta 的职责不同，不机械合并。 |
| Plugin/Skill | 保留贡献类型和 Catalog/generation 扩展面；实际修复声明式 Skill 阻塞 loop，以及附件遍历进入忽略目录的问题。 |
| Billing/Automation | 保留 SQL 聚合与游标查询、任务领取和恢复事务、按日历计算下一次执行及 DST 规则；不新增缓存或另一套任务调度框架。 |
| Config/Transfer/Resource | 配置原子写统一到基础设施；归档输入和资源身份在边界校验。内容寻址资源无需对每个候选重新扫描全部记录。 |
| CLI/TUI | 保留异步加载、刷新合并、草稿防抖与历史渲染 worker；修正子智能体控制事件过滤遗漏，保留高频正文流过滤。仅以 App/Runtime 文件大为由拆文件，缺乏可验证收益。 |

### 已实施项

| 项目 | 根因与实现 | 验证 |
|---|---|---|
| 资源回收 | id 与 digest 一一对应却重复扫描目录；直接删除所属 blob，批次末尾统一刷新目录，部分失败也刷新已完成变更。 | 批量扫描次数、保留其他 blob、部分失败、record 文件身份不匹配回归。 |
| 资源导出 | 校验后再次完整读文件；单次分块复制同时校验 digest/size，校验后原子发布。 | blob 只读一次；缺失、长度错误、同长度内容损坏均保留旧目标、清理临时文件。 |
| 原子 I/O | 临时路径在 fsync 之后才登记；同步失败时清理不到文件。配置另有一套缺少同步和共享冲突重试的原子写。 | fsync 故障、短暂 sharing 冲突、序列化失败和配置并发回归；统一共享 writer。 |
| Windows mutation 锁 | 普通路径与 `\\?\` 前缀产生不同进程内锁，嵌套事务与另一线程可互相等待。 | 实际锁跟踪定位；扩展路径嵌套回归先失败后通过；配置整组 216 项通过。 |
| Grep | 摘要模式仍构造最多 20,000 条正文/上下文，单文件读取预分配约 32 MiB；单文件和目录逻辑重复。 | 共用管线、按需构造、行号迭代、64 KiB 分块读取；计数、分页、忽略规则、大小边界及空文件跨行匹配回归。 |
| Skill | 附件全量递归后才过滤忽略目录；插件的 async prepare 内直接做文件读取。 | 遍历前剪枝；整段准备使用已有 worker 边界；真实插件启用测试检查读取线程与 Catalog 内容。 |
| 工具批次 | 顺序/并发分支重复准备、执行和结果解析。 | 共享局部执行函数，调度和交互停止顺序保留；既有工具批次和权限回归。 |
| 账本首次建库 | 多个实例在空库读取后同时切换 WAL，SQL 事务尚未开始，触发 database is locked。 | 只对首次建库使用既有跨进程锁并重读 schema；受控并发用例先失败后通过，30 轮原并发用例与 4 进程/40 条记录 smoke 通过。 |
| 任务/会话 SQLite 初始化 | 同类检查复现任务库 WAL 竞争、会话库重复写入版本记录；SQL 事务不覆盖先前 schema 读取。 | 初始化整体由既有跨进程锁协调，常规业务事务不取该锁；相关 57 项回归通过，两个存储各 20 轮 × 8 实例冷初始化通过。 |
| 子智能体审批呈现 | 审批预检通知可先于批次落盘；首次查询为空后，Host 又过滤后续状态事件，导致根界面漏显审批。 | 保留子会话 `run_status_changed` 控制事件；原集成用例加受控检查点门闩稳定复现，修复前失败、修复后与 Controller 共 57 项通过，不添加轮询或放宽超时。 |
