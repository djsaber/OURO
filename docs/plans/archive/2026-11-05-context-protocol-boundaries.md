> 文档类型：设计验收记录
> 验收日期：2026-11-05

## 职责与完成条件

会话保存工作事实，应用流程选择模型上下文，协议适配器解释原生响应及续接数据。
只追加、模型选择和压缩时机属于上层策略；底层消息、请求构建和协议编码提供相应能力。
现行契约见[上下文与压缩](../../specs/context-and-compaction.md)、
[Provider 配置](../../specs/provider-configuration.md)和 [Responses codec](../../specs/responses-codec.md)。

- [x] 历史消息的原生响应数据与 Run 执行授权独立；撤销和分支保留所选消息的数据及来源。
- [x] 请求投影按来源选择预算候选，codec 判断协议、认证范围和结构；持久化历史保持完整。
- [x] Chat Completions 的思考扩展保留字段、结构、签名与顺序；流式数组按接收顺序追加。
- [x] Anthropic Messages 使用完整、有序的原生 content envelope，工具调用与 canonical 记录一致。
- [x] 摘要输入包含正文、可读思考、工具调用及结果；签名、密文和原生 envelope 归属协议回传。

兼容扩展按实际字段处理，不按供应商、URL 或模型名称分派。`reasoning_details` 属于兼容接口扩展，
不等同于 OpenAI Chat Completions 标准。原生私有状态遵守来源与协议约束，不通过伪造思考或跨协议解释密文获得兼容。

## 验收

定向回归覆盖两种存储、撤销与分支、来源不匹配的大附件预算、结构化思考落盘与回传、流终态、
密文展示隔离、普通续跑前缀和摘要材料。请求准备不为原生回传资格读取历史 Run，
思考文本提取直接使用首次取得的可读结果；成本断言使用读取次数和数据生命周期。
完整执行结果见[管线验收](2026-11-05-context-preparation-boundary.md#验收)。

## 原生响应投影工作负载

Windows 11 10.0.26200、Python 3.14.6，输入为已读取的 200 条消息和 100 个 Run，
每条正文 1 KiB。原生状态组的 100 条 assistant 消息各带 256 字符思考附件。
每组预热后采样 7 次；计时覆盖上下文投影，排除样本构造、初始历史读取、网络和屏幕呈现，OS 缓存未清空。

| 存储 / 历史 | 投影耗时中位数 | 历史 Run 读取次数 |
|---|---:|---:|
| Files / 普通文本 | 15.860 ms | 0 |
| SQLite / 普通文本 | 9.013 ms | 0 |
| Files / 带原生状态 | 16.658 ms | 0 |
| SQLite / 带原生状态 | 16.472 ms | 0 |

普通文本样本存在波动，Files 有一个 116.851 ms 样本，统计结果不构成稳定延迟保证。
模型的输入量取决于实际保留的材料，摘要按容量使用既有分块规则；本地投影成本不等同于远端 token 成本或总耗时。
