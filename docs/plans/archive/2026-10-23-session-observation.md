本计划围绕执行归属、会话观察和 TUI 展示的边界，解决 Agent 状态通知积压，并完善多会话、
会话切换和多终端观察。任务按可独立验证的阶段推进；本文记录完成范围、验证依据和待验收目标。

剩余工作由[会话协作验收计划](../session-observation.md)跟踪。以下保留原实施阶段与实际验证记录，

## 目标与完成范围

| 目标 | 必须得到的保证 | 主要验收阶段 |
|---|---|---|
| 通用框架与 Host 解耦 | Core/Runtime 不感知界面；Application 提供执行与观察语义；TUI 不控制存储事务或复制领域恢复规则 | P1、P3、P4、P5 |
| 一个 TUI 中多个后台会话稳定运行 | 输入与执行归属明确；切换视图不取消运行；完成、失败、取消及草稿按 Session 隔离 | P3、P5、P7 |
| 随时切换且内容完整 | 正式消息、未提交流式内容和后续增量可靠衔接；过期切换不得提交；工作量避免重复历史扫描和排版 | P4、P5、P6、P7 |
| 多个 TUI 观察同一运行会话 | 单一执行归属，共享持久事实，各观察者独立消费；慢观察者不阻塞执行者或其他观察者 | P2、P3、P4、P7 |

会话隔离包括状态、控制、生命周期与故障隔离；共享 CPU、磁盘及数据库仍存在资源竞争。
Supervisor 的并发限制是其管理范围内的执行限制，不将它扩展为跨进程全局配额。
关闭共享 Application 上的单个 Host 只释放该 Host 的资源；整个应用进程退出仍遵循明确的 shutdown policy。
本计划不增加“执行者进程退出后运行仍继续”的承诺。

## 验证边界

功能与成本验证使用临时 home、合成 Provider 和受控 Event/进程握手，不访问个人会话或真实账号。
Files 与 SQLite 分别验证；同进程双 TUI、真实进程 headless 和实际终端是不同证据层次。
Windows 与 Ubuntu/WSL 的定向进程回归已通过；Files 实际终端功能反馈正常，跨平台重复验收和实时指标仍待验证。

## 目标边界与设计决定

### 执行、事实和展示分别归属

| 层 | 本计划中的职责 |
|---|---|
| Core / Runtime | 通用运行管线、领域状态转换、模型与工具执行、规范事件 |
| Application / Supervisor | 输入受理、长期任务归属与调度、会话观察、通用恢复投影、显式执行恢复 |
| 存储适配器 | 原子提交、一致性读取、按游标查询、执行锁及各后端实现 |
| TUI | 当前选择与草稿、布局、Rich/Markdown 排版、滚动、刷新节奏和交互映射 |

普通交互式提交进入 Application 管理的执行路径，返回受理结果；长期执行由 Supervisor 持有。
`Runtime.run` 可以保留为底层可等待接口，Host 关闭不再通过等待链隐式取消已受理任务。
输入受理失败、受理完成和实际执行完成是不同边界；复用已有 input identity、持久输入与排队语义。

通用观察入口只读取并重建显示所需事实。显示恢复不隐含接管、继续执行、提交输入或 abort。
控制会话选择如需触发执行恢复，由 Host 策略显式调用 Application 命令，并尊重现有执行归属。

### 正文事件与状态通知采用不同语义

正文从一致快照开始，按观察者自己的已应用游标补读和消费后续事件。实时队列是有界加速缓存，
不能决定事实是否丢失；追赶跨度不受队列容量限制。已读取、已入队和已应用游标必须区分，恢复使用已应用位置。
应用内容投影后才推进该位置，不能因把事件交给 renderer 或从队列取出就提前确认。

AgentTree 和活动摘要合并变化通知，消费者按需取得最新状态。相关变化在进入订阅队列前筛选，
状态归约继续复用现有逻辑；不为文本片段逐次查询完整树。沿用 canonical projector，暂不新增长期树缓存或第二套状态机。
快照读取期间发生的变化保留为下一次待刷新；一个订阅最多一个快照查询在途，读取在受管理线程边界执行。

同一 Supervisor 内继续按 Session 共享跟随器。正文订阅和状态订阅各自保留消费状态，A 的读取或关闭不消耗 B 的通知。
跟随器在两类订阅全部关闭后停止；观察订阅关闭与执行停止相互独立。不同进程各自读取共享存储是必要成本。
Agent 树跨 Session 的摘要允许最终一致，不引入跨整个子树的全局事务或伪造全局事件序号。
每 Session 的事件游标、树投影标识和视图切换版本分别服务自己的边界。

读取失败保留原 diagnostic 的原因与级别，关闭失败观察并允许明确重试；正常落后通过持久补读恢复。
观察者自身渲染失败不影响其他观察者；同一个持久数据源的故障可以影响所有依赖它的观察者，不能承诺掩盖共同故障。

### 读取与视图安装分离

正式消息、未提交内容与 high-water 必须来自可证明的一致边界。优先扩展已有窄快照查询；
SQLite 使用读事务，文件后端使用必要的短 Session 锁。读取结束后释放边界，再计算和排版。
轻量活动查询不加载完整消息或 Run 历史；无关附加信息不得扩大正文快照的事务范围。

TUI 的一次视图切换拥有目标 Session、有效版本、订阅、内容投影与排版结果。
后台准备的结果只有在目标仍然有效时才提交；过期结果释放自身资源，不补做尚未开始的完整历史排版。
已经开始的不可取消阻塞调用按既有资源规则收尾，其结果失效后丢弃，不假定取消协程可以停止线程。
快照安装不等待历史排版；活动内容转为历史时，展示任务等待替代内容就绪后释放原显示，
输入消息泵、执行与其他观察者不参与该等待。

### 范围约束

- 复用现有 Supervisor，不增加第二调度器、按根会话公平调度层或跨进程全局配额。
- 不引入常驻服务、跨进程消息总线、ORM/UoW、通用响应式框架或持久化 UI 投影数据库。
- 不以扩大队列、增加 sleep、反复全量重载或无限重试代替语义修正。
- 不弱化 canonical 提交、fsync、权限、输入归属或 history_epoch 规则；不让观察者直接重放工具执行。
- 不将普通用户输入改装为不同用途的 scaffold Host 输入；完整保留附件、技能和队列行为。
- 数据格式迁移不是预设任务。仅当具体实现证明必要时，再明确兼容范围和独立验证。
- 长历史窗口和更深缓存由 P6 测量决定，复用既有缓存，不预先增加全会话常驻内存状态。

- [x] 审查观察、activity/status、按 history_epoch 解析消息等纯读取中的 `session_mutation`；逐项保留其一致性保证并替换错误的写事务语义。
- [x] 将 TUI 所需组合读取收回 Application，去掉 Host 对 `runtime.store` 和事务生命周期的依赖。
- [x] 避免为状态读取调用完整历史快照；将投影计算、格式化和 UI 操作移出锁定范围。
- [x] 保留真实修改所需的写事务和执行锁；不以取消一致性边界换取并发。
- [x] 同步修正会话观察规格中用 mutation 描述只读一致性的条款。

验收：两后端均验证快照与 high-water 一致、历史改写竞争和读取失败资源释放；SQLite 验证读取 A 时另一连接可写 B。
文件后端允许必要的同 Session 短锁，不要求提供 SQLite 的 MVCC 能力。读事务不延伸到排版或订阅生命周期。

退出条件：Host 不掌握存储事务；轻量观察无全历史读取；真实写入原子性和既有恢复测试保持有效。

定位：[AgentTree](../../../ouro/application/agents/tree.py)、[AgentService](../../../ouro/application/agents/service.py)、
[Supervisor](../../../ouro/application/supervisor.py)、[事件跟随器](../../../ouro/application/observations/events.py)。

- [x] 在现有共享事件来源上提供轻量状态观察，相关活动及关系变化在进入状态订阅缓冲前识别；不另起一套磁盘轮询。
- [x] 每个订阅独立维护待刷新状态；重复变化合并，不排队保存历史树快照。

- [x] 将正文与状态订阅共同纳入共享跟随器的存活判断；关闭唤醒等待者并释放本订阅资源。

退出条件：状态消费速度不会形成旧快照 FIFO；诊断准确；单一共享事件来源保持不变。

定位：[SessionService](../../../ouro/application/sessions/service.py)、[Supervisor](../../../ouro/application/supervisor.py)、
[观察 DTO](../../../ouro/application/contracts/execution.py)、[当前恢复逻辑](../../../ouro/tui/app.py)。

- [x] 在现有 Application 服务中形成通用观察入口，返回一致快照、history_epoch、高水位及独立后续观察；名称和 DTO 以调用方审计结果确定。
- [x] 正文、活动 Run 和待处理输入共用同一快照边界；只读输入投影不清理持久队列，Host 不二次读取队列来拼接旧快照。
- [x] 将正式消息覆盖、未提交 text/reasoning、工具与交互恢复等通用语义收回 Application，复用已有 reducer；Rich、布局和滚动不进入框架。
- [x] 明确模型流结束与正式消息提交之间的窗口；不能仅凭 `model_message_completed` 就删除未被正式消息覆盖的内容。
- [x] 实现按观察者已应用游标分页追赶，回放页大小与实时缓冲容量分开；较大积压不再只返回 lag 后交给 TUI 全量重载。
- [x] 在统一观察内部处理 snapshot/replay/live 重叠、持续新写入和再次落后，保持有界临时内存；复用已有有序跟随器。
- [x] 保持历史代次校验；代次变化重新建立快照，导入历史允许有序但不连续的 sequence，不凭序号差臆造事件。
- [x] 将显示恢复与显式执行恢复拆开；observe/close 不创建 Run、不取得执行归属、不触发工具重放。
- [x] 保留 typed/redacted Host DTO；源读取失败停止失败观察并暴露原原因，不启动无止境重载。

验收：快照覆盖 100 后加载期间新增 101 至 120，最终按序完整应用且无重复；再覆盖积压大于多个缓存容量的场景。
验证提交消息前后边界、history_epoch 改写、连续多个 Run、取消初始化、慢消费者和源故障。
观察者读取进度不得当作内容已应用进度；慢消费者恢复处理能力后可追赶，执行者和其他观察者继续前进。

退出条件：不导入 TUI 的 Application 测试可以重建同样的会话语义；初始读取和后续交接无需 Host 自行拼接事务及恢复流程。

## 组合验收与测试选择

核心组合：TUI A 同时运行多个 Session，快速切换其中的运行中会话；另一进程的 TUI B 观察同一 Session。
暂时阻塞 B 的消费或渲染，同时继续 A 的输入和其他 Session 执行；恢复 B 后，两端与 canonical 记录一致。
随后依次关闭一个观察者、显式中止一个 Run、结束剩余运行，验证不同生命周期的结果。

| 场景 | 关键断言 | 验证边界 |
|---|---|---|
| 普通输入、并发超出调度容量、运行中追加 | 输入归属与去重正确，执行并发受控，追加输入不创建第二执行者 | Application + 真实 TUI 提交 |
| 共享 Application 的 Host 关闭 | 仅观察资源释放，运行继续；显式 abort 与整体 shutdown 按契约生效 | Host 集成 |
| 单源、多状态观察者、突发及慢消费 | 各自收敛、互不抢通知、不逐文本重读树、最后一个观察关闭才释放源 | Application 订阅 |
| 快照读取、消息提交、实时增量交错 | 正式消息与未提交内容衔接正确，已应用游标不越过缺失内容 | 两后端持久化集成 |
| 积压大于实时缓存、持续写入与断开重进 | 分页补齐、无重复、内存有界，其他观察者与执行者继续前进 | Application + 真实进程 |
| history_epoch 改写及旧结果晚到 | 不混合历史代次，不由旧任务覆盖新状态 | Application / TUI |
| A→B→C 快速切换和旧加载取消 | 仅有效结果可提交，草稿/焦点/滚动归属正确，旧目标不继续启动剩余排版 | TUI 集成 |
| 读取失败、投影失败、初始化取消 | 原因准确、失败范围明确、资源释放，无自动无限重载 | 最小受影响边界 |
| 两终端观察连续多个 Run 和工具交互 | 每次运行只有一个执行归属，文本与终态摘要完整，操作身份准确 | 真实进程 + 实际终端 |
| 长历史与后台不可见会话 | 查询/排版成本符合阶段目标，无隐形正文渲染或资源持续增长 | 计数回归 + 独立基准 |

现有回归优先扩展：[架构边界](../../../tests/architecture/test_boundaries.py)、
[Supervisor](../../../tests/application/test_supervisor.py)、[运行归属](../../../tests/application/test_run_ownership.py)、

### 当前性能证据

命令和探针口径见[基准说明](../../../dev/benchmarks/README.md)。原始 JSONL 在本地忽略目录
`.ouro-dev/session-observation/`。测量使用 120×40 headless 窗口，不包含真实终端 paint 或操作系统键盘传输。

`review-history-window.jsonl` 使用每后端一个 10,000 条消息样本。初始读取 201 条、显示近期 200 条，
窗口在线程中准备后一次发布；缓存重进不重新排版已有条目，流式重进读取 202 条。首个正文帧如下：

| 后端 | 冷进入 ms | 缓存重进 ms | 流式重进 ms |
|---|---|---|---|
| Files | 340 | 52 | 86 |
| SQLite | 248 | 60 | 88 |

这些单次测量验证窗口成本，不代表延迟分布或终端验收结果。
`review-stream-handoff.jsonl` 使用每后端一次、每轮 400 个片段、片段间隔 5ms 的合成流：

| 后端 | loop lag p99 / max ms | 按键 p95 ms | spinner 最大间隔 ms | GC 最大耗时 ms |
|---|---|---|---|---|
| Files | 14.8 / 132.3 | 9.9 | 234.3 | 122.7 |
| SQLite | 13.6 / 190.6 | 7.0 | 291.8 | 179.4 |

该样本中 Store 调用和历史排版均未落在 TUI 线程；严格响应性目标仍未达到。
长停顿与 gen2 GC 重叠，但不能据此将全部成本归因于依赖。生产代码不修改依赖缓存或 GC 策略。
下一步需在同负载下定位剩余对象分配与回收成本，并完成跨平台重复测量。

稳定活动组件的长时探针 `p6-stable-tail-after.jsonl` 覆盖 Files 20 轮、60 次切换；任务数在 221–227 间波动，
detach 后正文订阅与跟随器均为零。`p6-stable-tail-heap.jsonl` 的第 1/4/8 轮，Widget 均为 156 个、
样式缓存均为 118 项，Strip 随持续新增正文增长。堆诊断不作为响应性测量，也不能仅依据 RSS 判断泄漏。

### 交付与终端边界

真实进程测试使用同一 home：执行端同时运行三个 Session 并切换，观察端暂停正文消费但保持键盘响应；
恢复后完整追赶超过实时容量的事件。两后端均验证连续 Run 的正式正文与摘要、关闭观察端后后台继续，
以及分别中止和完成其他 Run。

[人工终端入口](../../../dev/benchmarks/README.md#人工终端验收入口)提供合成流式正文、工具结果及可选 10,000 条历史，
不调用外部模型或系统命令。人工反馈确认 Files 环境的提交、队列、切换、双端观察、种子会话和首次近期显示无异常；
尚无完整重复次数、跨平台终端 paint 与键盘链路的量化记录。自动测试不替代这些验收。

Ruff、格式复查、mypy、compileall、源码包及 wheel 构建通过；隔离基础环境回归与基础版、themes 版 wheel
安装 smoke 通过。唯一一次全量 pytest 为 6,032 项通过、6 项跳过、9 项失败，覆盖率 87.50%；
失败项修复后的定向复验 9 项通过。后续修改只执行受影响范围回归，不重复全量测试。
严格响应性及实际终端退出条件未满足，阶段记录归档不代表整体完成。
