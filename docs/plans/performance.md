# OURO 性能优化规划

> 文档类型：未来规划

本规划只定义尚需验证或由证据触发的工作，不声明下列目标已达到。当前机制与不变量见
[性能热路径规格](../specs/performance.md)，基准使用方法见[本地测量](../../dev/benchmarks/README.md)。

## 实施门槛

在受支持配置和现实数据量下重复复现超预算，定位到具体业务边界后再实施。优先减少重复计算、IO 和呈现工作；
缓存、数据布局和调度变化必须证明必要。保持 canonical 顺序、持久化、取消、恢复、租约、背压与 Host 解耦。
每项具备失败/竞争回归、资源释放检查和端到端测量，满足目标后停止扩大范围。

## 真实终端响应性

Windows Terminal/PowerShell 与 POSIX 终端分别覆盖以下场景，每场景至少重复 20 次：

- 新旧会话打开、普通流式输出、长 reasoning、工具参数流和较大工具结果。
- 工具进入、完成、下一轮与 Run 终态期间持续键入、滚动和调整窗口大小。
- 审批/AskUser、同步与异步子会话、取消、切换、关闭及恢复。
- 注入慢 Store 和大量历史，分别测量 IO、投影、消息泵与实际 paint。

受控目标：1 ms ticker 的 loop lag p99 ≤ 16 ms、最大值 ≤ 32 ms；按键到 Composer 更新 p95 ≤ 50 ms；
标称 120 ms 的动画不连续错过两个周期。记录全部样本和尾部，不以平均值替代卡顿。
事件队列、Markdown 任务、线程、进程与租约不得持续增长，视口锚点及 Run/UI 终态须一致。

## 超长历史窗口

当前 Store/Application 提供正向分页和 live high-water；TUI 冷打开仍逐页加载完整历史。
需要窗口化时，在同一 Application 边界提供 tail/before 窗口、边界摘要与 live cursor，首屏只物化近期内容，
向前加载保持可见锚点。工具 request/result、model turn 和 compaction 边界不可拆散。
搜索和跳转按目标加载，切换会话后的过时结果不得提交。10,000 条消息不应创建等量 Widget 或 Markdown 任务；
完整 export/replay 保留独立批处理语义。未来 Desktop 使用同一窗口契约。

## 条件性计算与存储优化

| 候选 | 触发证据 | 约束 |
|---|---|---|
| Context/Compaction 边界查询 | 保留历史读取与 covered-prefix 验证主导请求准备 | 保持原子帧、lineage 与动态 Context Provider 新鲜度 |
| 不可变摘要或估算复用 | digest、token estimate 或快照序列化持续主导成本 | key 覆盖内容、模型、工具、lineage 和投影参数；正负命中测试完整 |
| 资源投影复用 | 多轮文本/图片的读取、校验和编码主导请求准备 | 不替代可达性、完整性和 capability 校验；有界 immutable 缓存 |
| 文件 catalog 分片或索引 | 现实目录大小下单体 JSON 刷新持续超预算 | 先合并刷新，保持 canonical 恢复与跨进程一致性 |
| 文件锁 deadline | live holder 等待构成可复现的操作阻塞 | 明确 holder/operation 诊断与失败语义，保持原子提交 |
| SQLite Compaction 索引 | 查询计划证明 Session 范围扫描主导耗时 | 真实数据分布验证索引收益与写入成本 |
| MCP 状态刷新调整 | 空闲唤醒或状态同步 IO 有可测成本 | 保持连接健康、诊断和重连可见性 |

缓存须覆盖模型切换、插件代次、资源引用、分支、压缩、失败恢复、并发及淘汰测试；日志不能复制消息、图片或凭据。
不因合成极端样本默认引入额外 DTO、后台服务、工作流或 renderer。

## 交付要求

功能回归、架构依赖、类型、格式、构建与覆盖率达到[贡献指南](../../CONTRIBUTING.md)要求。
测量包含提交、首段、完整运行、内存峰值和取消收尾；标明平台、样本数、数据规模及不可观测项。
尚未达到终端或规模目标时保留明确限制，不将局部结果扩大为整体性能保证。
