> 当前行为见[附件规格](../specs/attachments.md)，职责与设计理由见[文件输入架构](../architecture/file-input.md)。

## 待验证范围

| 范围 | 前提 | 退出条件 |
|---|---|---|
| Windows Terminal 真实拖入与编辑 | 真实终端、含中文和空格的多文件 | 终端失焦与输入框失焦时首次拖入生效；拖到聊天区域可填入草稿；批量路径解析正确；欢迎页保持；原子删除、排队和撤回恢复正确 |
| POSIX 终端交互 | 对应系统及真实终端 | 验证该终端路径编码、快捷键、窄屏和目录菜单连续导航 |
| 视觉端点 | 用户配置的可用端点与测试图片 | 端点实际接收图片；不支持、超预算和切模型的降级信息准确；快照与实际请求一致 |
| 跨平台会话传输 | Windows 与 POSIX 环境 | 上传副本、同名文件与历史图片可用；新请求使用目标会话地址；原路径依赖明确 |
| 符号链接与特殊文件 | 允许创建对应文件的测试环境 | 导入、选择、读取及归档按路径策略拒绝非法输入，无越界发布 |

## 验收方法

按[附件规格验收矩阵](../specs/attachments.md#6-验收)记录环境、输入步骤和可观察结果。
分别记录算法测试、应用集成、Textual headless、真实终端和真实端点；每类证据只覆盖实际执行范围。

每个环境检查成功、失败、取消、会话切换和重启恢复。使用临时 OURO_HOME 与测试文件，核对项目工作目录没有因上传而自动写入。
涉及真实端点的验证检查所发送内容和请求快照，不仅依据模型回答判断图片是否到达。

全部退出条件具备对应环境证据后，结束本计划。发现契约偏差时同步修正其责任层和权威规格。
