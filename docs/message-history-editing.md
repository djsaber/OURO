# 消息帧裁剪与会话继续

`SessionRepository.truncate_messages(session_id, before_message_id=..., expected_last_message_id=...)`
在指定消息之前裁掉该帧及其后缀。返回值包含首条被撤回消息、最后保留消息及撤回数量。
`expected_last_message_id` 是必须提供的并发前置条件：历史头已改变、边界不存在，或切开同一消息帧时，
均在写入之前拒绝。

用户、系统输入和模型输出的起点均可作为边界，待撤回的后缀可以包含不完整输出。裁剪只检查切口是否
拆开已有帧，不要求保留历史本来就是完整的：例如“早先的半条回复 → 用户输入 → 新的半条回复”，撤回
后两条应保留早先的回复。assistant 工具请求及其结果不能在交换内部切开；完整性恢复在执行前负责补齐，
不属于删除后缀的前置条件。`core.message_frames` 定义边界检查、未完成后缀定位和压缩记录的有效性；它不判断用户角色是否
允许撤回、会话是否忙碌、是否有子智能体，或怎样处理插件状态。

裁剪同时修复 Session 的消息头和计数、清除最新上下文快照，并移除覆盖范围或展示节点已被撤回的压缩记录
及其依赖链。仍然有效的旧压缩可以继续使用。Run、事件日志、用量账本和资源附件记录作为执行事实保留；
因此消息撤回不是文件回滚，也不是清除执行审计。新的消息继续使用保留历史之后的消息序号，事件序号不回退。
调用方须在执行所有权锁内操作，并维护 Session 的规范消息计数；读改写通过 `session_mutation` 串行化。

文件后端从 JSONL 尾部按块定位边界，只解码被移除的后缀和紧邻的一条保留消息，直接按字节截断，不复制保留的
消息前缀。它先持久化裁剪意图；中断后，下一个会话读写在锁内完成裁剪及派生状态更新。SQLite 后端通过
会话消息索引定位和范围删除，在同一事务中更新派生状态。两种后端都不读取或重写事件日志。
压缩元数据的校验与更新另计，成本取决于压缩记录数量及其覆盖清单。
可运行 `uv run python -m dev.benchmarks.message_truncation` 对比保留 100 和 10,000 条消息时
裁去两条尾部消息的耗时；该探测仅使用临时目录，计时不包含测试数据写入。

`SessionService.undo` 是应用层入口：它锁定原会话，从尾部查找最近的普通文本用户消息，校验执行、排队输入、
扩展状态及派遣关系，然后调用同一裁剪接口。TUI 在持久化成功后刷新会话并填充编辑框。重新提交是一次正常的
新输入，不重放已经撤回的消息。

`RuntimeService.continue_run` 从当前保留的对话中选择最近的 Agent Run，支持 `failed`、`aborted`、
`paused` 和 `recoverable`。压缩 Run 和消息已全部撤回的 Run 只保留执行审计，不覆盖继续目标；因此可先
手动压缩再继续暂停的运行，也可撤回到早先中断的对话后继续原 Run。
进程退出遗留的 running/queued 状态由现有恢复服务识别。它校验原扩展契约，补交已持久化的工具结果，
为未知结果补齐明确的协议记录，裁掉未完成输出，再重入模型循环。原 Run ID、起始时间、输入、模型轮数和
累计用量保留，模型请求轮次从原 Run 的下一轮递增。遗留的终结策略检查点先按其持久化契约重试结算，成功后继续；仍无法结算时给出具体错误，
不会丢弃检查点。已完成的运行、没有保留输入或正在执行的会话仍拒绝继续。继续命令自身不消费排队输入
来开启额外 Run。正常的工具审批与用户提问继续由既有交互流程处理。

暂停是可以重试的执行边界。继续时会重新检查当前模型、上下文、策略及原预算，而不跳过这些约束或清零
累计用量。上下文或策略问题修复后即可继续；若原因仍存在，TUI 会明确显示仍然暂停的原因。

子智能体通过 AgentService 和 RuntimeSupervisor 恢复原运行，保留派遣关系与能力边界，刷新过时的终结结果。
已经完成或显式关闭的子智能体保持原状态。TUI 对不支持的边界和命令错误显示 warning 通知。
