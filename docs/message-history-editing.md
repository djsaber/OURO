# 消息撤销与会话继续

会话由有序 canonical 消息与当前 Harness 状态组成。每条新消息保存 `before_harness_version`；撤销指定
消息及其后缀时，框架保留此前消息并恢复该锚点，`history_epoch` 增加一次。撤销无需解释插件业务数据，
也不调用插件恢复钩子。计划等外部文件保持原样，真实 usage 和 Run/工具审计继续保留。

## 框架与应用边界

- `SessionStore.commit_session` / `SessionCommit.before_message_id` 支持任意角色消息节点，包括工具结果
  内部节点。同批消息各有正确锚点；物理批量提交不限制逻辑切口。
- `SessionService.undo` 负责来源选择和取得执行所有权，`RuntimeService.undo` 结清撤销后的输入租约与子会话
  关系。活跃执行未完成取消结算时返回忙碌，由用户先中断。应用入口仅允许直接用户输入，包含
  已提交但尚未消费的排队输入；插件或 Harness 产生的 user-role 消息不冒充用户输入。
- 无参数 undo 优先选择最新待消费用户输入，否则选择最新 canonical 用户输入。取消尚未消费输入只改变
  队列，不回退 Harness 或递增代次；已经消费则按准确消息节点撤销。
- 状态、消息、队列效果和提交回执通过同一原生提交机制持久化。恢复只完成已持久化决定，不重调工具。

## TUI 输入恢复

`/undo` 恢复完整用户输入，包括文本、技能调用和资源引用。
TUI 重载标准会话投影并放回 composer，草稿在切换和启用记忆的重启中保持附件。提交成功后清除草稿；
失败保留可编辑输入，编辑和重新提交继续携带技能与附件引用。

撤销后保留的其他待消费用户输入维持身份与顺序，撤销本身不自动消费。旧执行许可、插件续跑和子会话
迟到交付不得进入新历史。运行收敛由既有 Runtime 所有权负责；未知外部副作用只保留审计，不尝试回滚文件。

`/continue` 在同一历史代次恢复合法的中断检查点；撤销后从当前消息创建新 Run。撤销后的新 Run 不复用旧审批、工具恢复
输入或续跑许可，也不为补齐工具帧再次裁剪用户指定前缀。Provider 上下文投影负责过滤未闭合工具交换，
canonical 消息仍严格保留所选前缀。

## 观察与错误

snapshot、活动状态和消息点查携带同一 history_epoch。TUI 先过滤旧代次事件，再查询消息身份；历史变化
时重载标准 snapshot/live 交接。当前代次缺失消息仍是持久化错误，不通过吞掉异常掩盖。增量事件与终态快照
遵守同一代次规则，重开会话不得恢复已撤销 Run 的“准备上下文”状态。

只支持当前数据格式；版本不符时明确拒绝。请使用新的数据目录或清理失效测试数据，框架不转换旧消息或插件状态。
